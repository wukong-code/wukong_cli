# 0.0.21 Isolated Loop Worktrees 用户验收

> 状态：协议已冻结，尚未执行。
> 适用版本：只接受同一次 fixed-SHA full RC 中 implementation gates 与六平台 native gates 均通过的 0.0.21 候选。
> 隐私边界：不收集源码、diff、文件路径、Goal 正文、provider 请求、终端 transcript、API Key、用户目录或 session artifact。

## 目的

确认未参与实现的目标用户能够理解并独立操作 0.0.21 的核心产品边界：

1. Candidate Gate PASS 只说明隔离候选通过，不是最终完成。
2. 只有显式 Promote、应用到目标 workspace 并通过 target Final Gate 后，Loop 才能得到 terminal PASS。
3. Worktree 提供源码隔离与受限文件工具边界，不是完整 OS process/network sandbox。
4. 用户能够独立完成 Promote，或在 source drift 时选择安全的下一步。

发布门槛：

- 5/5 正确区分 Candidate PASS 与 target Final PASS。
- 5/5 明确指出 worktree 不是完整 sandbox。
- 至少 4/5 无引导完成 Promote，或在 source drift blocker 出现后选择保留候选并先处理 drift。

任一前两项不足 5/5，或第三项不足 4/5，本次 0.0.21 用户验收失败。不能通过补讲、重试或更换同一用户的任务改写结果。

## 招募与冻结

- 在展示脚本、产品界面或术语前固定五名目标用户。
- 用户必须没有参与 0.0.21 的实现、设计评审或测试编写。
- 每名用户只运行一次。
- 看过脚本、提示或界面后不能排除或替换。
- 只有接触脚本前发生的无关设备故障可以替换，并记录替换原因；产品、安装、模型、Git、网络或理解失败都计入结果。
- 五人必须使用同一个 exact commit SHA 的候选；记录 SHA、artifact checksum、OS/architecture 和 Git 版本。

## 测试仓库

每名用户使用自己有权修改的本地 Git 仓库，并满足：

- 至少一个已提交的基线文件。
- 至少一个用户自己的 unstaged 修改，必须在 Promote 后保持不丢失。
- 一个可在本机完成的明确小任务。
- 至少一个真实、可重复的 required check。
- 不要求提交、push、远端访问或向 Wukong 上传内容。

用户不愿在真实仓库测试时，可以退出；退出计入未完成，不能在看过脚本后换成演示仓库重试。

## 主持人边界

主持人只能：

- 提供候选安装命令和 exact checksum。
- 提供本协议中的任务指令。
- 处理与 Wukong 无关的输入设备或屏幕共享故障。

主持人不能：

- 解释 Candidate PASS、Final PASS、Promote、source drift 或 sandbox。
- 指出要点击或输入的选项。
- 建议忽略 blocker、重跑、reset、stash、commit 或删除用户修改。
- 查看、复制或记录用户源码、路径、Goal 正文、终端 transcript 或 provider 内容。

## 单次脚本

### 1. 准备

用户确认：

- 当前仓库存在一项自己的 unstaged 修改。
- `git status --short` 能看到该修改。
- experimental Isolated Loop Worktrees 已开启。
- 当前安装的 `wukong --version` 和候选 SHA/checksum 与主持人记录一致。

### 2. 启动 Loop

给用户唯一指令：

> 用 `/loop` 完成你选定的小任务。看到需要决定的界面时，按你对状态的理解继续；不要提交、stash、reset 或 push。

主持人不再提供操作提示。

### 3. Candidate 决策点

当界面显示 Candidate Gate PASS 或 promotion challenge 时，先暂停操作并询问：

1. “现在任务最终完成了吗？”
2. “目标 workspace 已经包含候选修改了吗？”
3. “下一步由谁决定，决定什么？”

合格条件：

- 明确回答尚未最终完成。
- 明确回答目标 workspace 尚未应用候选修改。
- 明确回答由用户决定是否 Promote，Promote 后还要重新运行 target Final Gate。

记录结构化结果后，用户继续操作。

### 4. Promote 或 source drift

正常路径：

- 用户独立选择 Promote。
- Promote 后 required checks 与 target Final Gate 通过。
- 原有 unstaged 修改仍存在。

若自然出现 source drift：

- 用户不得被提示具体选项。
- 合格行为是保留候选、不强制覆盖，先处理或确认 drift，再恢复同一候选。
- reset、stash、删除用户修改、绕过 exact challenge 或把 Candidate PASS 当最终完成均不合格。

不得为了制造 drift 修改用户仓库；自然未出现 drift 时只评估正常 Promote。

### 5. Terminal 解释

结束后询问：

1. “哪一个 PASS 才表示这次 Loop 最终完成？”
2. “如果 Candidate PASS 后目标 workspace 发生变化，会发生什么？”
3. “这个 worktree 是否阻止仓库里的任意进程访问网络或修改其他本机路径？”

合格条件：

- 指出 target Final Gate PASS 和 completion seal/terminal join 才是最终 PASS。
- 指出 source drift 应阻断或要求重新验证，不能静默覆盖。
- 明确回答不是完整 sandbox；任意 shell/进程副作用不由 worktree 边界完全隔离。

## 结构化记录

每名用户只记录下列字段：

| 字段 | 允许值 |
|---|---|
| `participant_id` | 预先分配的随机编号 |
| `candidate_sha` | 40 位 commit SHA |
| `artifact_sha256` | 候选 artifact checksum |
| `platform` | `linux-x64` / `linux-arm64` / `darwin-x64` / `darwin-arm64` / `win32-x64` / `win32-arm64` |
| `git_version` | 版本号，不含路径 |
| `candidate_vs_final` | `pass` / `fail` |
| `workspace_not_applied_at_candidate` | `pass` / `fail` |
| `sandbox_boundary` | `pass` / `fail` |
| `promote_or_drift_action` | `pass` / `fail` |
| `unstaged_change_preserved` | `pass` / `fail` |
| `terminal_outcome` | `pass` / `blocked` / `error` / `cancelled` |
| `reason_code` | Wukong 稳定 reason code；没有则留空 |
| `replacement_before_script` | `none` 或不含个人信息的设备故障类别 |

禁止增加自由文本备注。若发现产品问题，单独创建去密 issue，只记录稳定 reason code、候选 SHA、平台和可公开的最小复现；不得附带用户仓库内容。

## 汇总

验收完成后只发布聚合结果：

```text
candidate_vs_final: N/5
sandbox_boundary: N/5
promote_or_drift_action: N/5
unstaged_change_preserved: N/5
terminal_pass: N/5
candidate_sha: <exact SHA>
platforms: <aggregate counts>
```

原始结构化记录保存在本地受限目录，完成发布决策后删除。它不是 telemetry，不上传到 Wukong 服务，也不进入 Git 仓库。
