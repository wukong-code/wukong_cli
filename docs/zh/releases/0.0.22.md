# Wukong Code 0.0.22

0.0.22 keeps provider setup available during catalog outages and makes CLI
session and permission behavior easier to understand.

## What's changed

- Provider catalog lookup now falls back from the maintained primary catalog to
  models.dev instead of failing when the primary source is unavailable.
- The source adds a final embedded snapshot path covering common providers,
  including GLM and Kimi.
- `--skills-dir` now applies to interactive terminal sessions as well as
  headless runs.
- Help now presents `-r, --resume` as the canonical session-resume option and
  explains guarded Auto, YOLO, Plan, headless prompt, `--yes`, and additional
  workspace access more clearly.
- `judge` is described as a deterministic local merge gate rather than a
  guarantee that a workspace is safe to merge.

## Known release limitation

The official 0.0.22 native archives were built with the local SEA profile and
therefore did **not** embed the intended provider snapshot. They can still fall
back from the maintained catalog to models.dev, but provider discovery fails if
both remote sources are unavailable. The release workflow now builds every
platform with the snapshot-bearing release profile and executes an offline
catalog smoke against the final ZIP; that correction applies to the next
published version rather than rewriting the existing 0.0.22 assets.

## Compatibility

Existing `-S, --session` and `--assume-broken` invocations remain accepted as
hidden compatibility options. No configuration migration is required.

## Try it

List the provider catalog:

```sh
wukong provider catalog list
```

Resume a session or open the interactive session picker:

```sh
wukong --resume
```

Run one guarded headless turn:

```sh
wukong --prompt "review the current changes"
```

Headless YOLO remains explicit:

```sh
wukong --prompt "apply the requested changes" --yolo --yes
```
