# Wukong Code 0.0.22

0.0.22 keeps provider setup available during catalog outages and makes CLI
session and permission behavior easier to understand.

## What's changed

- Provider catalog lookup now falls back across the maintained primary catalog,
  models.dev, and an embedded snapshot instead of failing when one remote source
  is unavailable.
- The embedded snapshot covers common providers, including GLM and Kimi.
- `--skills-dir` now applies to interactive terminal sessions as well as
  headless runs.
- Help now presents `-r, --resume` as the canonical session-resume option and
  explains guarded Auto, YOLO, Plan, headless prompt, `--yes`, and additional
  workspace access more clearly.
- `judge` is described as a deterministic local merge gate rather than a
  guarantee that a workspace is safe to merge.

## Compatibility

Existing `-S, --session` and `--assume-broken` invocations remain accepted as
hidden compatibility options. No configuration migration is required.

## Try it

List the provider catalog:

```sh
wukong provider catalog list
```

Resume a session or open the interactive session picker:

```sh
wukong --resume
```

Run one guarded headless turn:

```sh
wukong --prompt "review the current changes"
```

Headless YOLO remains explicit:

```sh
wukong --prompt "apply the requested changes" --yolo --yes
```
