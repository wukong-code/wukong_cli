# Wukong Code 0.1.1

`0.1.1` 是 Free、local-first、BYOK 的可靠性与信任边界维护版本。它不新增
顶层命令，不改变 Loop/Gate 判定语义，也不包含 Cost Visibility、provider
费用估算、价格数据库、托管执行或付费权益。

## 维护范围

### Loop、Goal 与恢复

- `/loop revise` 可以修订当前活动 Goal，并保留未被用户显式覆盖的 Done when、
  Must not、Verification Criteria、writer/reviewer、迭代间隔、调用上限和 token
  budget。
- `/goal --until` 不再创建旧式停止条件；用户会被引导到规范 `/loop` 流程。
- Headless Loop 会完整传递迭代、间隔、writer/reviewer provider-call 和 token
  上限；恢复旧 session 时，普通 prompt 摘要只报告本次运行新增的 usage。
- 外部 Codex、Claude Code、Cursor、Kimi Code 或 Grok session 位于其他
  workspace 时，只提示切换目录后重新导入，不会把 transcript 导入当前错误项目。
- 短终端中的 Loop Preflight 会压缩显示；启动取消、授权失败或最终预检失败后，
  保留用户已经编辑的 Preflight，而不是丢失设置。

### Provider 与配置

- Provider catalog 和 custom registry 导入先校验完整配置，再通过一次原子替换
  写入，避免半写入、旧 alias 复活或合法默认模型丢失。
- Kimi Code 与 Grok 的 Resume 来源标签与实际来源保持一致。

### Web 体验

- 断线、重连和恢复连接状态会持续可见，不再只显示容易错过的瞬时提示。
- Server Auth 在 Onboarding 之前完成；token 不会留在地址栏 hash 中。
- Session、Workspace、移动端列表和主要弹层支持键盘操作、焦点约束与 Escape。
- Manual、Auto、YOLO 的说明与颜色和真实权限语义一致；所有进入 YOLO 的 Web
  路径都要求浏览器明确确认。
- Workspace 新增失败时不再创建假的本地条目；重命名通过 server 持久化。
- Side Chat 关闭后保留原 child session；发送进行中禁止重复并发提交。
- Goal、Swarm、Transform 等非默认或实验能力不再占据主要入口；底层兼容命令
  仍按各自 feature flag 和命令合同工作。

### 本地 Web stub

`apps/wukong-web` 提供用于离线联调的 `dev:stub`。它模拟 REST、WebSocket、
Bearer token、Workspace rename 和首条流式回复。所有 HTTP envelope 都返回
HTTP 200，业务成功与失败由 `code` 字段区分，和真实 server contract 一致。

从 monorepo 根目录运行：

```sh
# Terminal 1
WUKONG_STUB_WEB_URL=http://127.0.0.1:5175/#token=stub-local \
  pnpm -C apps/wukong-web run dev:stub

# Terminal 2
WUKONG_SERVER_URL=http://127.0.0.1:58627 \
  pnpm -C apps/wukong-web run dev
```

打开 stub 输出的 `Open Web UI` 地址。默认开发端口是 `5175`，默认 stub token
是仅用于本地开发的 `stub-local`。若修改 `WEB_PORT`、`WUKONG_STUB_PORT` 或
`WUKONG_STUB_TOKEN`，同时更新 `WUKONG_STUB_WEB_URL` 和
`WUKONG_SERVER_URL`，使浏览器、Vite proxy 与 stub 指向同一组端口和 token。

## 信任边界修复

- 修复 vis-web 历史 plan id 类型错误，并把 local Web、vis-web、vis-server 纳入根测试门禁。
- 自动更新改为通知加显式 upgrade；配置缺失、损坏或来源完整性不足时不后台安装。
- 插件安装增加 HTTPS/final URL、下载/解压上限、digest、初装 disabled 和原子回滚。
- checks discovery 只读取真实 workspace 声明；根和成员检查均保留可解释 provenance。
- 删除空 `wukong-migration-legacy` workspace，同步 pnpm、Nix 和 release build。
- Web 请求路径不再执行 schema DDL；旧 SaaS 数据只冻结，不 DROP，应用层停止新增旧宠物/同步领域数据。
- Web 开发说明和公开终态文案回到当前 Free local BYOK Loop；官网与 local Web 各有一条可重复浏览器 Golden Journey。

浏览器流程、断言和本地证据位置见
[`docs/test/0.1.1-browser-golden-journeys.md`](../test/0.1.1-browser-golden-journeys.md)。
这组本地验证不替代真实 OAuth approve/revoke、production D1 或 custom domain
验收。

命令聚合、Provider 首次连通测试、run-plan 文件、Dashboard 设备管理和协调器拆分
分别进入 0.1.2/0.2.0，不进入本 patch。

## 本地发布前验证

以下结果证明 release source 的本地质量；公开 release 仍由六平台资产、升级、
恢复与 production surface workflow 单独验收：

- 官网 53 个测试文件 / 260 tests、lint 与 Next production build 通过。
- vis-web、vis-server 和 local Web 共 12 个测试文件 / 96 tests；三个应用
  typecheck 均通过。
- update/config/workspace discovery 聚焦回归 63 tests 通过；plugin/RPC/TUI
  供应链回归通过，agent-core 与 CLI typecheck 通过。
- 真实浏览器验证 Home、Download、Pricing、未登录 Device Login callback，以及
  local Web token 清除、onboarding、Workspace、Session 和首条 stub 回复；所有
  检查页面 console error 为 0，local Web 相关 API 均为 HTTP 200。
- 根仓库全量测试 732 个文件通过、8 跳过；9,841 tests 通过、48 跳过；0 失败。
- 根 typecheck、全仓 build、`sherif`、Nix workspace 同步检查均通过；lint 为
  0 warning / 0 error，agent-core boundary 没有新增违规。

## 发布完整性合同

`v0.1.1` 只有在同一 exact source 生成的六平台 ZIP、SHA-256、provenance、
`0.1.0 → 0.1.1` upgrade、fresh install、状态恢复、公开 installer 和 production
version surfaces 全部通过后，才算完成 stable 发布。GitHub Release、官网和公开
文档必须分别回报同一 source、distribution 与 website SHA。
