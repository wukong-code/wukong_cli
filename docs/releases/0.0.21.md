# Wukong Code 0.0.21

0.0.21 adds an experimental Isolated Loop pipeline. Wukong can freeze the
user-approved dirty workspace, work in a detached candidate, and apply only the
verified candidate delta after an explicit Promote decision.

## What's changed

- `/loop` can freeze an exact Source Snapshot containing the approved staged,
  unstaged, and selected untracked state. Secret, generated, oversized,
  ambiguous, linked, or unsafe paths fail closed instead of being silently
  omitted.
- A detached candidate worktree materializes the exact snapshot without
  changing the source branch, index, or working tree before Promote.
- Supported Node, Python, Rust, and Go projects use an explicit deterministic
  bootstrap plan. Runtime identity, lockfiles, arguments, environment,
  registries, budgets, and generated scopes are frozen and confirmed before
  dependency preparation starts.
- The candidate writer is limited to guarded file tools rooted in that
  candidate. Candidate verification binds the exact Agent delta, deterministic
  checks, bounded review subject, fresh reviewer, and durable attempt lineage.
- Candidate Gate `PASS` is candidate-only. It cannot produce terminal PASS,
  change the target workspace, or commit a completion seal.
- Promote requires the exact proposal digest and a fresh target fingerprint.
  A target-global fenced lease and per-change journal prevent two Wukong
  processes from interleaving Apply operations.
- Create, update, delete, rename, and mode changes use no-clobber transactions.
  Source drift, concurrent editor replacement, receipt tampering, or an
  unreconcilable restart stops safely instead of overwriting the newer target.
- Only the target Final Gate can produce terminal PASS. Wukong re-reads the
  exact private evidence, result, target fingerprint, Apply journal, and
  completion seal before committing the terminal outcome.
- TUI, headless, Agent RPC, Node SDK, and stream-json surfaces distinguish
  Candidate PASS, Promote, target Final Gate, completion seal, and terminal
  PASS with the same semantics.
- Crash recovery covers snapshot sealing, materialization, bootstrap, candidate
  writes, Apply, Final Gate, completion sealing, and terminal join without
  blindly replaying unknown work.

## Experimental boundary

Isolated Loop worktrees are disabled by default in 0.0.21. Enable them with:

```sh
export WUKONG_CODE_EXPERIMENTAL_ISOLATED_LOOP_WORKTREES=1
```

The feature provides Git/workspace collision isolation for Wukong's guarded
file operations. It is not a complete filesystem, network, environment, or
process sandbox. Shell commands and other same-user processes still execute
with the current operating-system permissions.

Wukong Code remains free, local-first, and BYOK. This release does not add
hosted execution, managed model credits, payment, quota, Team policy, cloud
sync, source upload, or a telemetry metrics backend.

## Try it

Preview the exact Source Snapshot without creating a candidate:

```sh
WUKONG_CODE_EXPERIMENTAL_ISOLATED_LOOP_WORKTREES=1 \
  wukong loop "finish the current change" \
  --dry-run \
  --output-format stream-json
```

In the TUI, start `/loop`, review the frozen finish line and Source Snapshot,
then explicitly confirm the bootstrap plan and Promote proposal. Treat
Candidate PASS as a proposal only; completion requires the target Final Gate.
