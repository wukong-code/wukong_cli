# 0.0.20 Reusable Verification Criteria

> 状态：功能范围已批准，规划中，尚未实现。
> 目标版本：0.0.20。
> 最后更新：2026-07-25。
> 前置版本：[0.0.19 Explicit Finish Line](0.0.19-explicit-finish-line.md)。
> 产品边界：继续 Free、local-first、BYOK；`/loop` 仍是普通用户主路径，不增加默认顶层命令，不引入命令型 Skill runtime、PR Gate、云同步、团队托管规则、Skill Marketplace、托管 grader、支付或 telemetry 后端。

## 一句话定义

> **发现并校验用户本机已经存在的 Verification Skill，把其中严格声明的定性验收 criteria 作为可解释、可选择、可冻结的 Loop 完成标准复用；真实 test/lint/typecheck/build 仍只由 0.0.19 frozen project checks 执行。**

0.0.19 解决“一次 Loop 的完成线和真实 checks 是什么”；0.0.20 解决“已经写好的项目验收规则如何跨任务复用”。

本版提供的是 **criteria catalog + selection + brokered fresh review runtime**，不是 Skill 创建器，也不是新的命令执行平台。为避免同一个 `/loop` 因是否选择 Skill 而出现两套隐私语义，0.0.20 启动的所有新 reviewer attempt 都使用同一 broker/trust/consent 边界；只有 criteria contract 是否升级到 V3 存在差异。

## 研究依据

本设计基于：

- [Building verification loops in Claude Code with skills](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills)
- [Claude Code Skills 文档](https://code.claude.com/docs/en/skills)
- [Agent Skills specification](https://agentskills.io/specification)

吸收的原则：

1. 反复人工检查值得沉淀为可复用项目规则。
2. 检查应匹配具体 workflow，而不是对所有任务全量运行。
3. standalone 应先验证，再考虑 embedded 或 chained。
4. Skill 必须提供真实 evidence，而不是只让模型加载一段 prompt。
5. built-in/plugin-managed Skill 不应被原地修改。
6. PR-wide Gate 必须等个人本地验证长期稳定后再讨论。

不照搬的部分：

- Skill 被发现或加载不代表验证已执行。
- `allowed-tools` 是预授权提示，不是 Wukong 权限边界。
- Skill 文本、自动触发或模型自评不能直接产生最终 PASS。
- 普通 Markdown body、代码块、hooks、dynamic shell 和 MCP 声明不能进入 Gate。
- 0.0.20 不执行 Skill command；命令型 recipe 与跨平台 sandbox 必须单独设计。

## 用户问题

1. 同类任务每次都要重新输入日志隐私、迁移安全、API 兼容、设计一致性等规则。
2. 规则散落在 prompt、README、Skill 和人工习惯里，无法确认本次到底用了哪一版。
3. project、personal 和 monorepo package scope 可能出现同名冲突。
4. “模型认为某个 Skill 适用”与“确定性规则建议某个 Skill”混在一起，结果不可重复。
5. Skill 或 criteria 在 active run 中变化时，旧 verdict 可能失去意义。
6. fresh reviewer 若直接读取整个 workspace，可能接触 `.env`、凭证、session 或与任务无关的敏感文件。
7. Skill 文本、源码和 evidence 都可能包含 prompt injection，不能把它们当系统指令。
8. 多个 criteria recipe 同时选择后，用户看不到来源、顺序、digest 和额外成本。

## 版本目标

1. 复用现有 Agent Skills 目录和 discovery，不创建新的顶层命令。
2. 定义一个只包含 scope 与 qualitative criteria 的严格 sidecar。
3. 支持 personal、project、monorepo package，以及显式受信的 extra/builtin reference source。
4. 只把确定性路径/package 规则产生的结果称为 `suggested`。
5. 模型 recommendation 降级为独立 `advisoryHint`，不能进入 catalog digest 或合同。
6. 支持用户显式选择一个或多个 standalone criteria recipes。
7. 多选结果以可见、连续的 flat order 冻结，不形成依赖图或动态 chain。
8. TUI 显示 why suggested、scope、source、digest、criteria 数量、review 输入边界和成本。
9. Headless 使用 catalog digest + exact provenance digest compare-and-set。
10. 新建 additive `LoopContractV3`，无损保留 V2 finish line、legacy Gate Plan、trust、approval 和 review policy。
11. recipe criteria 带来源投影进 acceptance criteria，由唯一 fresh reviewer 判定。
12. reviewer 只能读取去密、冻结、有限的 review-subject manifest 和脱敏后的结构化 Gate evidence。
13. workspace trust 与 BYOK provider 出站同意分离；每个 run 冻结 exact provider/input consent。
14. deterministic blocker、expected-unresolved check、evidence stale 或 reviewer inconclusive 时绝不 PASS。
15. Skill drift、selection drift、review input 超限和 evidence 注入返回稳定结果。
16. 无论是否选择 Verification Skill，0.0.20 启动的 fresh reviewer 都只能通过同一 broker 读取用户确认的内容。

## 0.0.19 强依赖

0.0.20 实施前，0.0.19 必须已经提供：

1. 无损 `LoopContractV2` 与 V1 append-only identity assignment。
2. frozen `GatePlan`、source locator、definition digest、approval-set CAS。
3. workspace trust、permission 和 recognizable-risk guard。
4. expected-unresolved placeholder 的非执行语义。
5. 每个 required check 只执行一次，Proof aggregate 不重复 discovery/spawn。
6. Gate 前后 workspace/provenance freshness。
7. evidence、Gate attempt、terminal 与 continuation 的 durable join。
8. PASS terminal 必须引用完整、同 run/contract/plan 的 PASS attempt。
9. 单一 continuation policy、Revised Loop Goal lineage 与 replay/idempotency。
10. deterministic blocker 与 fresh reviewer 的固定优先级。

任一前置不成立时，0.0.20 只能提供只读 catalog/dry-run，不能创建 V3 active run。

## 核心不变量

### 1. Verification Skill 只贡献 criteria

0.0.20 Skill 可以声明：

- 它适用于哪些路径/package；
- 项目特有的完成标准；
- reviewer 应为每条标准提供什么 evidence。

它不能：

- 声明或执行 shell/argv command；
- 授予 filesystem/network/secret 权限；
- 修改 workspace、active contract 或 review policy；
- 调用另一个 Skill；
- 删除 legacy deterministic checks；
- 用自然语言 PASS 覆盖 check failure。

### 2. Markdown body 不是 Gate 真相源

Wukong 不从 `SKILL.md` 正文、fenced code 或自然语言中猜 criteria、命令或权限。只有严格 sidecar 中的字段可以进入合同。

### 3. Suggested、selected、advisoryHint 分离

- `suggested`：只来自 versioned deterministic applicability rules。
- `selected`：只来自用户显式操作，并进入合同。
- `advisoryHint`：模型的非阻塞提示；不进入 catalog digest、selection、合同或自动化稳定性指标。

### 4. Skill 是规则来源，不是最终裁判

最终 PASS 仍由以下共同决定：

```text
frozen V2 deterministic checks
+ builtin risk scan
+ selected recipe criteria
+ existing Finish Line criteria
+ prior blocker disposition
+ one fresh-context reviewer
+ final freshness
```

任何 deterministic failure 都有更高阻断优先级。

### 5. reviewer 不直接访问文件系统

0.0.20 启动的任何 fresh reviewer 都不获得任意 `Read`、`Glob`、`Grep`、Bash、Skill、MCP 或 Web。V2/V3 attempt 只能通过内部 evidence broker 读取当前 attempt 已冻结的 review-subject refs 和 Gate evidence refs；没有 Gate Plan/approval 的遗留 V1 必须先由用户创建 Revised V2，不能直接启动 attempt。

## 明确非目标

0.0.20 不做：

- Skill 创建、scaffold、draft generator、自动修改或 promotion；
- command/argv recipe、scripts runtime、artifact collection 或 process-tree sandbox；
- embedded producing-skill binding；
- recipe dependency graph、动态 chain、递归 Skill 调用或 workflow DSL；
- 新的公开 `/verify-skill`、`/chain`、`/workflow` 命令；
- 普通 Skill body 的任意执行；
- Claude `allowed-tools`、hooks、dynamic `!command`、context fork 或 MCP 映射；
- 自动选择、自动冻结或自动升级 Skill；
- built-in/plugin-managed Skill 原地修改；
- Skill Marketplace、远程 registry、签名、安装、更新或云同步；
- GitHub App、PR Gate、Team policy、`/schedule` 或云端执行；
- 托管模型、grader、支付、credits 或 quota；
- 上传 Skill、prompt、源码、session 或 evidence 到 Wukong Web/D1。

命令型 verification recipe、严格 sandbox、private scratch/artifact、embedded/chained 和 authoring flow 只作为 0.0.21+ 候选，不属于 0.0.20 的实现或发布承诺。

## Skill 与 Criteria sidecar

### Agent Skills 外层

继续使用现有目录结构：

```text
.wukong/skills/review-api-contract/
├── SKILL.md
└── verification/
    └── criteria.v1.json
```

`SKILL.md` 通过 namespaced metadata 指向 sidecar：

```yaml
---
name: review-api-contract
description: Review API compatibility and explicit error behavior.
metadata:
  wukong.verification.criteria: verification/criteria.v1.json
---

Use these review criteria when an API contract changes.
```

Markdown body供人类和普通 Skill 使用，但不是 Gate 真相源，也不会传给 fresh reviewer。

### Sidecar 示例

```json
{
  "schemaVersion": 1,
  "kind": "wukong.verification-criteria",
  "id": "review-api-contract",
  "description": "Review API compatibility and explicit error behavior.",
  "scope": {
    "kind": "project",
    "paths": ["src/api/**", "packages/protocol/**"]
  },
  "criteria": [
    {
      "id": "api-errors-explicit",
      "text": "404 and 5xx paths return explicit typed failures",
      "evidence": "Cite the changed handler and its deterministic test result"
    }
  ]
}
```

### Schema

```ts
interface VerificationCriteriaRecipeV1 {
  readonly schemaVersion: 1;
  readonly kind: 'wukong.verification-criteria';
  readonly id: string;
  readonly description: string;
  readonly scope: VerificationCriteriaScopeV1;
  readonly criteria: readonly VerificationCriterionDeclarationV1[];
}

type VerificationCriteriaScopeV1 =
  | {
      readonly kind: 'personal';
      readonly paths: readonly string[];
    }
  | {
      readonly kind: 'project';
      readonly paths: readonly string[];
    }
  | {
      readonly kind: 'package';
      readonly packagePath: string;
      readonly paths: readonly string[];
    };

interface VerificationCriterionDeclarationV1 {
  readonly id: string;
  readonly text: string;
  readonly evidence: string;
}
```

严格解析规则：

- 未知字段、重复 ID、空 criteria、绝对路径、`..`、NUL/控制字符、逃逸 symlink 和大小超限全部拒绝。
- `criteria` 至少 1 条，最多 16 条；单条 `text` 最多 1,000 字符，`evidence` 最多 1,000 字符。
- sidecar 最多 32 KiB，`SKILL.md` 最多 64 KiB。
- path 使用 POSIX logical path；在大小写不敏感文件系统上先做 case-fold collision 检查。
- sidecar 不接受 `steps`、`commands`、`scripts`、`tools`、`permissions`、`hooks`、`model`、`agent` 或 `mcp`。
- criterion 是 blocking completion criterion；非阻塞建议继续放在普通 Skill/文档，不进入 Gate。

## Scope、来源与冲突

支持来源：

- personal：`~/.wukong/skills/`
- project：`<workspace>/.wukong/skills/`
- package：monorepo package 内 `.wukong/skills/`
- extra/imported：只读导入来源，必须显示稳定 `sourceId`
- builtin/reference：随 Wukong 发布的只读 reference recipe，必须带版本

同名 Skill 不能 silent first-wins。selection identity 必须包含：

```text
source + logical locator + skill name + provenance digest
```

Preflight 展示所有冲突来源并要求用户选择 exact identity。package recipe 只对落入 package scope 的任务产生 deterministic suggestion。

## Provenance 与 canonical digest

```ts
interface VerificationCriteriaRefBaseV1 {
  readonly format: 'agent-skills';
  readonly skillName: string;
  readonly criteriaId: string;
  readonly logicalLocator: string;
  readonly skillMdDigest: string;
  readonly criteriaDigest: string;
  readonly provenanceDigest: string;
}

type VerificationCriteriaRefV1 =
  | (VerificationCriteriaRefBaseV1 & {
      readonly source: { readonly kind: 'personal' };
      readonly sourceTrust: {
        readonly kind: 'personal-local';
        readonly rootIdentityDigest: string;
        readonly ownerIdentityDigest: string;
        readonly accessPolicyVersion: string;
        readonly accessControlDigest: string;
      };
    })
  | (VerificationCriteriaRefBaseV1 & {
      readonly source: { readonly kind: 'project' };
      readonly sourceTrust: {
        readonly kind: 'workspace';
        readonly workspaceIdentityDigest: string;
        readonly scope: 'verification-criteria-source';
      };
    })
  | (VerificationCriteriaRefBaseV1 & {
      readonly source: {
        readonly kind: 'package';
        readonly packagePath: string;
      };
      readonly sourceTrust: {
        readonly kind: 'workspace';
        readonly workspaceIdentityDigest: string;
        readonly scope: 'verification-criteria-source';
      };
    })
  | (VerificationCriteriaRefBaseV1 & {
      readonly source: {
        readonly kind: 'extra';
        readonly sourceId: string;
      };
      readonly sourceTrust: {
        readonly kind: 'extra-local-grant';
        readonly sourceId: string;
        readonly trustGrantId: string;
        readonly rootIdentityDigest: string;
      };
    })
  | (VerificationCriteriaRefBaseV1 & {
      readonly source: {
        readonly kind: 'builtin';
        readonly version: string;
      };
      readonly sourceTrust: {
        readonly kind: 'builtin-release';
        readonly version: string;
        readonly assetDigest: string;
      };
    });

interface SelectedVerificationCriteriaRefV1 {
  readonly selectionOrder: number;
  readonly ref: VerificationCriteriaRefV1;
}

interface VerificationCriteriaSelectionV1 {
  readonly schemaVersion: 1;
  readonly preflightCatalogDigest: string;
  readonly selected: readonly SelectedVerificationCriteriaRefV1[];
  readonly selectionDigest: string;
}
```

所有 digest 使用 UTF-8、RFC 8785 JSON Canonicalization Scheme 和完整 SHA-256，并使用明确 domain separator：

| digest | canonical preimage |
|---|---|
| `skillMdDigest` | `wukong/skill-md/v1\0` + 原始规范化 LF bytes |
| `criteriaDigest` | `wukong/verification-criteria/v1\0` + 完整 sidecar canonical JSON |
| `provenanceDigest` | `wukong/verification-criteria-ref/v1\0` + ref 中除 `provenanceDigest` 外的全部字段 |
| `catalogDigest` | `wukong/verification-catalog/v1\0` + applicability policy version、按 identity 排序的全部 refs、validity/conflict 状态 |
| `selectionDigest` | `wukong/verification-selection/v1\0` + 按连续 `selectionOrder` 排列的 selected `{ selectionOrder, ref }`；不包含全量 catalog |

规则：

- digest preimage 永远排除其自身字段。
- logical path 使用 POSIX 分隔符，不含绝对 home/workspace path、mtime、session、账号或 transcript。
- `selectionOrder` 只属于 selection，不属于 recipe provenance；必须从 0 开始、连续且无重复，数组顺序必须与之完全一致。
- `preflightCatalogDigest` 只用于 dry-run → contract creation compare-and-set。合同创建后，active run/restart/continuation 只重算 selected refs 的 provenance 与 `selectionDigest`；未选中的 Skill 新增、删除或更新不能使 active Loop stale。
- Skill/sidecar 在 dry-run、合同创建、attempt 或 continuation 中变化时，旧 digest 不能热升级。
- digest 只用于 change detection，不是发布者签名或代码安全证明。

source trust 规则：

- strict schema 使用上述 paired discriminated union，禁止 source/trust kind 交叉组合；extra 的两个 `sourceId`、builtin 的两个 `version` 必须逐字相等。
- project/package source 必须 realpath-contain 于已确认 workspace，并绑定 exact workspace identity 与 `verification-criteria-source` scope。
- personal source 只接受当前用户拥有的本地目录；POSIX 下 root 与文件均不可 group/world-write，Windows 下 canonical owner 必须是当前用户且 DACL 不允许其他普通 principal 写入。ownership/ACL/permission 变化立即失效。
- extra source 必须有用户在 TUI Security 中创建、可列出和 revoke 的 exact local-root grant；remote URL 不是 source。
- builtin source 绑定当前 Wukong release version 与 packaged asset digest。
- trust identity/grant/version 的变化返回 `verification_criteria_untrusted` 或 provenance drift；选择 Skill 不能自行建立或扩大 source trust。

## Deterministic suggestion 与 model advisory

deterministic `suggested` 只可以使用：

- versioned path glob matcher；
- monorepo package scope；
- 当前 objective 已确认的 workspace/package target；
- 当前 diff 的 logical paths；
- 用户在 Preflight 中显式设置的 scope filter。

每条 suggestion 必须记录：

- matched rule ID/version；
- matching logical paths 的数量和有界摘要；
- source/scope；
- recipe identity 与 provenance digest。

交互会话中已经存在的模型 recommendation 可以作为 `advisoryHint` 显示，但 Wukong 不会为了生成 hint 单独调用模型。`advisoryHint`：

- 只能显示在单独的 “Model hints” 区域；
- 不能创建 suggested/selected 状态；
- 不能进入 catalog/selection/plan digest；
- 不能影响排序、required level 或自动化 trigger 指标；
- 用户若认同 hint，仍需从 catalog 打开 exact recipe 并显式选择。

## V3 Acceptance Contract

只有用户选择至少一个 Verification Skill 时，新建合同才使用 additive `LoopContractV3`；没有 selection 时继续创建 V2 contract。两者在 0.0.20 都使用 brokered reviewer/run records，V1/V2 history 不重写。

```ts
interface LoopContractV3 {
  readonly schemaVersion: 3;
  readonly contractId: string;
  readonly supersedesContractId?: string;
  readonly supersedesGoalId?: string;
  readonly goalId: string;
  readonly objective: string;
  readonly completionCriterion?: string;
  readonly constraints: readonly LoopConstraint[];
  readonly finishLineReview: FinishLineReviewV1;
  readonly workspaceTrust: WorkspaceTrustBindingV2;
  readonly gateApproval: GateApprovalBindingV1;
  readonly acceptanceCriteria: readonly LoopAcceptanceCriterionV3[];
  readonly verificationPlan: readonly LoopVerificationStep[];
  readonly verificationCriteria: VerificationCriteriaSelectionV1;
  readonly gatePlan: GatePlanV2;
  readonly reviewPolicy: ReviewPolicyBindingV1;
  readonly source: 'user' | 'planner' | 'fallback';
  readonly createdAt: number;
}

interface WorkspaceTrustBindingBaseV2 {
  readonly schemaVersion: 2;
  readonly workspaceIdentityDigest: string;
  readonly reviewSubjectPolicyVersion: string;
}

interface BrokerOnlyWorkspaceTrustBindingV2
  extends WorkspaceTrustBindingBaseV2 {
  readonly hasExecutableChecks: false;
  readonly scopes: readonly ['brokered-review-subject'];
}

interface ExecutableWorkspaceTrustBindingV2
  extends WorkspaceTrustBindingBaseV2 {
  readonly hasExecutableChecks: true;
  readonly scopes: readonly [
    'loop-project-checks',
    'brokered-review-subject'
  ];
}

type WorkspaceTrustBindingV2 =
  | BrokerOnlyWorkspaceTrustBindingV2
  | ExecutableWorkspaceTrustBindingV2;

interface BrokerReviewTrustBindingV1 {
  readonly workspaceIdentityDigest: string;
  readonly scope: 'brokered-review-subject';
  readonly trustProposalDigest: string;
  readonly trustGrantId: string;
}

interface ReviewSubjectConsentBindingV1 {
  readonly schemaVersion: 1;
  readonly workspaceIdentityDigest: string;
  readonly reviewSubjectPolicyVersion: string;
  readonly hardExclusionPolicyVersion: string;
  readonly allowedOrigins: readonly ReviewSubjectOriginV1[];
  readonly limits: {
    readonly maxFiles: number;
    readonly maxTotalBytes: number;
    readonly maxFileBytes: number;
    readonly maxGateEvidenceTotalBytes: number;
    readonly maxGateEvidenceBytes: number;
  };
  readonly provider: {
    readonly providerId: string;
    readonly endpointOriginDigest: string;
  };
  readonly consentProposalDigest: string;
  readonly acknowledgedAt: number;
  readonly consentDigest: string;
}

type ReviewSubjectOriginV1 =
  | 'changed-tracked'
  | 'explicit-untracked'
  | 'scope-match'
  | 'gate-evidence';

interface LoopRunSettingsV2 {
  readonly schemaVersion: 2;
  readonly legacy: LoopRunSettings;
  readonly legacySettingsDigest: string;
  readonly brokerReviewTrust: BrokerReviewTrustBindingV1;
  readonly reviewSubjectConsent: ReviewSubjectConsentBindingV1;
  readonly settingsDigest: string;
}

interface LoopAcceptanceCriterionV3 {
  readonly id: string;
  readonly text: string;
  readonly evidenceExpectation?: string;
  readonly criterionProvenanceDigest: string;
  readonly source:
    | 'objective'
    | 'completion_criterion'
    | 'constraint'
    | 'derived'
    | 'verification_recipe';
  readonly provenance:
    | {
        readonly kind: 'v2-criterion';
        readonly v2CriterionId: string;
        readonly v2Source: LoopAcceptanceCriterionV2['source'];
      }
    | {
        readonly kind: 'verification-recipe';
        readonly recipeProvenanceDigest: string;
        readonly recipeCriterionId: string;
      };
}

interface GatePlanV2 {
  readonly schemaVersion: 2;
  readonly stopCondition: 'proof-pass';
  readonly legacySnapshot: GatePlan;
  readonly criteriaSelectionDigest: string;
  readonly criterionIds: readonly string[];
  readonly builtinScanPolicyVersion: string;
  readonly freshReviewerPolicyVersion: string;
  readonly reviewSubjectPolicyVersion: string;
  readonly planDigest: string;
}
```

`GatePlanV2.planDigest` 的 canonical preimage 是：

```text
wukong/gate-plan/v2\0
+ canonical JSON {
    schemaVersion,
    stopCondition,
    legacySnapshot,
    criteriaSelectionDigest,
    criterionIds,
    builtinScanPolicyVersion,
    freshReviewerPolicyVersion,
    reviewSubjectPolicyVersion
  }
```

不变量：

- V2 → V3 只能通过用户确认的 Revised Loop 创建新 goal/contract，不能原地升级或给 continuation 热附加。
- V2 contract/trust 不能被静默改写或扩大。0.0.20 创建 attempt 前必须单独取得 exact `brokered-review-subject` grant，并把实际 grant 写入 `LoopRunSettingsV2.brokerReviewTrust`；它不能替代或授予 `loop-project-checks` shell scope。
- `trustProposalDigest` 使用 `wukong/broker-review-trust-proposal/v1\0` + workspace identity、scope、review-subject policy 和 once/remember intent 的 canonical JSON；grant creation 与 settings assignment 使用该稳定 proposal 幂等提交，首个成功写入冻结随机 `trustGrantId`。
- workspace trust 只授权 Wukong 在本机建立 bounded broker，不等于同意出站。每个 0.0.20 run（包括 restart/continuation）必须在 `LoopRunSettingsV2` 中冻结 exact `ReviewSubjectConsentBindingV1`；它绑定 workspace identity、输入来源/上限、hard-exclusion policy，以及用户实际选择的 BYOK provider 和 endpoint origin。
- `consentProposalDigest` 使用 `wukong/review-subject-consent-proposal/v1\0` + `{ schemaVersion, workspaceIdentityDigest, reviewSubjectPolicyVersion, hardExclusionPolicyVersion, allowedOrigins, limits, provider }` canonical JSON，明确排除 `consentProposalDigest`、`acknowledgedAt` 和 `consentDigest`；`consentDigest` 使用 `wukong/review-subject-consent/v1\0` + `{ consentProposalDigest, acknowledgedAt }`。provider、endpoint origin、policy 或 limits 任一变化都必须重新确认，但不要求改 acceptance contract。
- `allowedOrigins` 必须按上述 enum 顺序、唯一且非空；用户可以收窄来源。limits 必须为正整数，且不得超过 500 files / 4 MiB total / 256 KiB per file / 1 MiB Gate evidence total / 128 KiB per evidence 的 hard ceiling；Skill、model 和 provider 不能放宽。
- `endpointOriginDigest` 使用 `wukong/provider-origin/v1\0` + canonical `{ scheme, IDNA host, effective port }`；UI 同时显示实际 origin。provider call 不能跟随跨 origin redirect，provider ID/origin 与 consent 不一致时必须在发送任何 bytes 前失败。
- V3 legacy plan 存在任一 resolved check 时，`workspaceTrust.hasExecutableChecks` 必须为 true，scopes 同时包含 project checks 与 broker；否则必须为 broker-only variant，不能因为选择 criteria 获得不需要的 shell execution trust。该判别值必须与 legacy `gateApproval.hasExecutableChecks` 完全一致。
- `legacySnapshot` 必须与原 V2 Gate Plan canonical JSON 完全等价，包括 stop condition、resolved/expected-unresolved checks、excluded checks、locators、definitions 和 plan digest。
- `gatePlan.builtinScanPolicyVersion` 必须精确等于 `legacySnapshot.builtinRiskScanPolicyVersion`；V3 不能选择第二套 scan policy，也不能让 criteria selection 改写它。
- expected-unresolved 继续是非执行 blocker；V3 不能把它编译成 command。
- V2 trust、Gate approval、Finish Line warning、review policy、criteria IDs 和 verification plan 语义必须无损保留。
- recipe criteria 在冻结前投影成稳定 V3 criterion IDs；active run 中不能增加、删除、重排或热升级。
- Skill criteria 不能删除或替换 V2 criteria。
- `criterionProvenanceDigest` 使用 `wukong/acceptance-criterion/v3\0` + `{ contractId, id, text, nullable evidenceExpectation, source, provenance }` 的 RFC 8785 canonical JSON/full SHA-256；V2 与 recipe criterion 使用同一算法，runtime 不从文本临时推导。
- 0.0.20 对 V2 contract 的 brokered reviewer 使用只读 runtime projection：用 stable `contractId`、同一算法、`evidenceExpectation: null` 和 `v2-criterion` provenance 计算 criterion digest。该 projection 写入 reviewer input/records，但不改写合同；没有 criteria 时使用 domain-separated empty criteria-set digest。V1 只能在用户确认的 Revised V2 中获得真实 Gate Plan/approval 后进入该路径。
- `gateApproval.gatePlanDigest` 必须等于 `gatePlan.legacySnapshot.planDigest`；它只批准 V2 legacy commands，绝不能与 V3 `gatePlan.planDigest` 比较或被解释为 criteria 授权。

## Headless 行为

在现有 `wukong loop` 上增加：

```text
--verification-catalog-digest "sha256:<catalog-digest>"
--verification-skill "<selection-id>@sha256:<provenance-digest>"
--trust-review-subject "<challenge>"
--ack-review-subject "sha256:<consent-proposal-digest>"
```

规则：

- `--verification-skill` 可重复，参数顺序就是 `selectionOrder`。
- 至少出现一个 `--verification-skill` 时，`--verification-catalog-digest` 必填并创建 V3；未出现 `--verification-skill` 时必须省略 catalog digest、跳过 catalog CAS 并创建 V2。两条分支都要求 broker trust/consent。
- `selection-id` 包含 source + logical locator + skill name，不能只用短名称。
- 每个选择必须携带 dry-run 返回的 full provenance digest，并提交 full catalog digest。
- 合同创建是 compare-and-set；dry-run 后 catalog 新增、删除、重排、冲突、scope 或 digest 漂移都返回 `verification_catalog_changed`。合同创建后不再比较全量 catalog，只验证 selected refs、selection 和 plan。
- 没有有效 exact broker grant 时，每个 0.0.20 run 都必须提交 dry-run 针对当前 canonical workspace identity、`brokered-review-subject` scope 和 policy 生成的最多 10 分钟短时签名 `--trust-review-subject`；它不能代替 project-check trust，也不能被裸路径或宽目录复用。
- 每个 run 还必须提交当前 provider、endpoint、policy 和 limits 对应的 exact `--ack-review-subject`；trust 与 outbound consent 是两个独立决定，Auto/Yolo/`--yes` 都不能代替。provider 或 endpoint 改变时必须重新 dry-run/确认，但不创建 Revised Loop。
- suggested 只在 dry-run 报告，不自动选择。
- `--dry-run --output-format stream-json` 输出最终 `contractSchemaVersion: 2|3`、`selectionState: none|selected`、catalog、deterministic suggestions、selected、digest、flat order、criteria、subject policy、provider endpoint origin、consent proposal digest 和 cost；无 selection 时 selection/catalog-CAS 字段明确为 not-applicable。dry-run 不调用模型，也不生成/输出 advisory hints。
- dry-run 不写 contract/run/trust/consent/selection record，不打开 provider connection，也不读取 subject/Gate evidence 正文。
- 不新增 `--output json`；Auto/Yolo/`--yes` 不能绕过 exact selection CAS。

## Review Subject Broker

fresh reviewer 不直接获得 workspace filesystem tools。每个 Gate attempt 在 deterministic checks 完成后创建 bounded manifest：

```ts
interface ReviewSubjectManifestV1 {
  readonly schemaVersion: 1;
  readonly attemptId: string;
  readonly runId: string;
  readonly contractId: string;
  readonly planDigest: string;
  readonly consentDigest: string;
  readonly workspaceFingerprint: string;
  readonly policyVersion: string;
  readonly entries: readonly ReviewSubjectEntryV1[];
  readonly exclusions: readonly ReviewSubjectExclusionV1[];
  readonly gateEvidence: readonly BrokeredGateEvidenceEntryV1[];
  readonly gateEvidenceExclusions: readonly BrokeredGateEvidenceExclusionV1[];
  readonly manifestDigest: string;
}

interface ReviewSubjectEntryV1 {
  readonly subjectRef: string;
  readonly logicalPath: string;
  readonly sha256: string;
  readonly byteLength: number;
  readonly mediaType: 'text/plain' | 'application/json';
  readonly origin: Exclude<ReviewSubjectOriginV1, 'gate-evidence'>;
}

interface ReviewSubjectExclusionV1 {
  readonly reason:
    | 'secret-path'
    | 'secret-content'
    | 'private-state'
    | 'binary'
    | 'generated'
    | 'oversize'
    | 'outside-workspace';
  readonly count: number;
}

interface BrokeredGateEvidenceEntryV1 {
  readonly producerId: string;
  readonly evidenceId: string;
  readonly brokeredEvidenceDigest: string;
  readonly byteLength: number;
  readonly mediaType: 'text/plain' | 'application/json';
  readonly redactionVersion: string;
  readonly secretScanVersion: string;
}

interface BrokeredGateEvidenceExclusionV1 {
  readonly exclusionId: string;
  readonly reason: 'secret-content' | 'private-state' | 'binary' | 'oversize';
}
```

固定输入策略：

- manifest 的 `consentDigest` 必须等于 attempt/run settings；`policyVersion` 必须等于 consent 的 `reviewSubjectPolicyVersion`，entry/evidence origins 与计数/字节必须是 `allowedOrigins` 和 consent limits 的子集。任一不一致在 provider connection 前 fail closed。
- 优先包含 Loop 基线以来 changed tracked files、用户显式确认的 untracked task files、selected recipe scope matches 和 deterministic finding 引用。
- 只接受 workspace-relative regular text/JSON files。
- hard exclude `.git/`、`.env*`、credential/secret/token/key/cert 文件、provider/auth 配置、Wukong session/log/trust store、home、临时目录、依赖/vendor/build/generated 目录和 binary。
- path 规则后再做 secret-content scanner；命中 sentinel 的文件不生成 `subjectRef`。
- 最多 500 个文件、总计 4 MiB、单文件 256 KiB；超限返回 `review_subject_limit`，不能静默截断后 PASS。
- hard exclusion 不能由 Skill、model、Auto/Yolo 或普通 permission 扩大。
- 用户未同意的 origin 不得进入 manifest；若 blocking criterion 因用户收窄 origin 而无法判断，结果为 `INCONCLUSIVE`，不能回退直接读取。
- 若 blocking criterion 需要被排除内容才能判断，reviewer 必须返回 `INCONCLUSIVE`，不能请求直接读取。
- manifest 在 reviewer 前后重算；workspace 或 manifest 变化使 verdict stale。
- Gate raw stdout/stderr、risk finding payload 和其他 evidence blob 始终留在本机原始 evidence store，不能直接成为 reviewer ref。broker 必须生成独立副本，先按固定 `redactionVersion` 脱敏，再按固定 `secretScanVersion` 扫描；命中 secret/private 内容时只记录 exclusion，不生成可读 ref。
- brokered Gate evidence 单项最多 128 KiB、每个 attempt 合计最多 1 MiB，只接受 text/JSON；不能静默截断。超限或不支持内容只记录 exclusion；若 blocking judgment 依赖它则 verdict 必须为 `INCONCLUSIVE`。
- reviewer 和 provider 只能看到 brokered copy，`ReadGateEvidence` 返回内容必须匹配 `brokeredEvidenceDigest`。raw evidence digest 同样不进入 provider-visible entry。
- provider-visible exclusion 只包含 opaque `exclusionId` 与 reason，不能包含 producer/evidence identity 或 raw digest。`exclusionId` 使用 `HMAC-SHA256(attemptBrokerKey, "wukong/gate-evidence-exclusion/v1\0" + producerId + evidenceId + reason)`，因此同一 attempt 前后重算稳定、跨 attempt 不可关联。
- `attemptBrokerKey`、raw identity/digest 映射只存在于 attempt-scoped 本机 ephemeral broker state，保留到 reviewer 后 freshness recompute 与 attempt completion，随后销毁；不进入 record、manifest digest、reviewer input、日志、导出或出站 payload。进程崩溃导致 key 丢失时该未完成 attempt 按 0.0.19 规则废弃并创建新 attempt，不能伪造原 manifest 的 freshness。
- `(producerId, evidenceId)` 在单个 attempt 内必须唯一；同一 raw evidence 只能进入 readable entry 或 local-only exclusion audit 二者之一，不能同时出现。

broker 只提供：

```text
ReadReviewSubject(subjectRef)
SearchReviewSubjects(query, subjectRefs?)
ReadGateEvidence(producerId, evidenceId)
```

所有参数都必须引用当前 `attemptId` manifest 中已记录的 refs。`ReadGateEvidence` 只接受 `gateEvidence` 中的复合身份，不能读取 `gateEvidenceExclusions` 或本地 raw evidence。broker 不接受任意路径、glob、URL、shell 或跨 attempt ID。

## 唯一 Fresh-context Reviewer

reviewer runtime：

- 新 context，无 writer 对话历史；
- 不加载 project/user/plugin Skills；
- 不继承 parent custom tools、hooks、MCP 或 Web；
- 不把 SKILL.md、criteria、源码或 evidence 当系统指令；
- 只接收 normalized criteria、provenance、prior blocker keys、Gate result manifest 和 Review Subject manifest；
- 只开放 broker 三个内部只读操作；
- 使用相同 model alias fallback 时仍必须创建新 context；
- 不允许 fallback 到 writer 自评。

reviewer 在每个已进入可执行 Gate 的 attempt 中恰好调用一次，即使 deterministic check 失败也运行，以便给 writer 完整反馈。若结构性 preflight 在 attempt 创建前失败，则不伪造 reviewer record。

runtime 校验：

- criterion dispositions 恰好覆盖合同全部 criterion IDs，不能缺失、重复或包含未知 ID。
- criterion dispositions 与 criterion-origin findings 的 `criterionProvenanceDigest` 必须等于合同冻结值；independent finding 不伪造 criterion ID，且永远只能是 advisory。
- `frozen-review-policy` finding 只有在合同 `reviewPolicy.mode === 'blocking-frozen'` 且 locator/digest 精确匹配时有效；`advisory-live` policy 和无 provenance 的 independent finding 只能是 important/note，不能改变 verdict 或阻止/授予 PASS。
- prior blocker dispositions 恰好覆盖 run 的 carried blocker keys。
- `reviewerInputDigest` 绑定 attempt、contract/plan、selection、subject manifest、ordered deterministic result digests、prior blocker-set digest、reviewer policy version 和当前 run 的 `reviewSubjectConsent.consentDigest`。
- `review-subject` evidence 必须精确匹配当前 manifest 的 `(subjectRef, sha256)`；`gate-evidence` 必须精确匹配当前 manifest 的 `(producerId, evidenceId, brokeredEvidenceDigest)`。两种 ref 都必须属于当前 attempt。
- 每条 `satisfied` criterion 至少有一个有效 evidence；`unsatisfied` 必须有有效 evidence 和对应 blocking criterion finding；缺证据时只能是 `unverified`/`INCONCLUSIVE`。
- blocking criterion finding 必须对应同 ID 的 `unsatisfied` disposition；同一 criterion 同时 `satisfied` 且 blocking，或 `unsatisfied` 却无 blocking finding，均为 invalid output。
- 所有 blocking finding（criterion 或 frozen policy）都必须至少引用一个当前 attempt 的有效 evidence 并提供非空 `nextAction`；否则 verdict 为 `INCONCLUSIVE`。
- carried blocker 的 `resolved`、`still-open` 和 `replaced-by` 都必须带有效 evidence；只有 `replaced-by` 可以携带 `replacementBlockerKey`，该 key 必须非空、不同于原 key，并对应当前有效 blocking finding，其他 status 携带 replacement key 一律 invalid。
- verdict `PASS` 要求全部 criterion 为 `satisfied`、全部 prior blocker 都是有证据的 `resolved`，且不存在任何有效 blocking finding；`replaced-by` 明确表示旧 blocker 被新的 blocking finding 取代，因此与 `still-open` 一样必须为 `NEEDS_WORK`，绝不能参与 PASS。任一 unverified/证据缺失/被排除依赖必须为 `INCONCLUSIVE`。
- invalid JSON、跨 attempt ref、未知 evidence、缺失 disposition 或 digest 不一致一律 `INCONCLUSIVE`。

## Gate Runtime 与 PASS

以下是 V3 的完整路径。V2 attempt 使用同一 broker/consent/durable chain，只省略 Skill ref/selection 检查并使用自身 Gate Plan 与 runtime-projected criterion digests；不能回退到旧 filesystem reviewer。V1 没有可合法填入 attempt 的 Gate Plan/approval digest，必须先 Revised 到 V2。

每次 attempt：

```text
1. Resolve frozen V3 contract, exact criteria refs and V2 legacy snapshot
2. Validate workspace/project-check trust, exact broker grant, run-scoped review consent/provider origin, legacy Gate approval, selected-ref/plan freshness
3. Use the 0.0.19 executor to handle each legacy required check exactly once
   - resolved: execute under the frozen V2 contract
   - expected-unresolved: record unresolved; never spawn
4. Run and persist builtin risk scan once
5. Build and persist the bounded Review Subject manifest
6. Run the one fresh reviewer once over all V2 + recipe criteria and prior blockers
7. Recompute workspace, broker-grant/consent/provider, selected criteria and subject-manifest freshness
8. Purely aggregate persisted check/scan/reviewer results once
9. Persist attempt completion, then PASS / continue repair / end run
```

最终 PASS 必须同时满足：

- 全部 resolved deterministic checks passed；
- 没有 expected-unresolved、missing、unavailable 或 skipped blocker；
- builtin risk scan record 唯一、fresh 且 status 精确为 `clean`；
- 所有 blocking criteria satisfied；
- carried blockers 全部以有效 evidence 标记为 `resolved`；`still-open`/`replaced-by` 均阻止 PASS；
- reviewer verdict 必须精确为 `PASS`，并且没有 criterion 或 frozen-policy blocking finding；
- workspace、broker trust grant、run-scoped review consent/provider origin、legacy plan、criteria selection、review subject 和 evidence 均 fresh；
- PASS terminal 引用同 run/contract/plan 的完整 attempt。

Skill verdict、model hint 或 writer summary 均不能覆盖任一条件。

- 外层 `ReviewSubjectManifestRecordedV1.manifestDigest` 必须与内层 `manifest.manifestDigest` 完全相等；不一致按 `record_corrupt` 处理。
- `reviewerInputDigest` preimage 为 `wukong/fresh-reviewer-input/v1\0` + attempt/contract/plan/selection/subject/check/prior-blocker/policy/consent digests。
- `verdictDigest` preimage 为 `wukong/fresh-criteria-verdict/v1\0` + 完整 verdict canonical JSON；digest 位于外层 record，不存在 self-field。
- `proofAggregateDigest` 使用 `wukong/proof-aggregate/v2\0`，绑定 ordered check results、builtin scan、manifest、fresh verdict、prior blockers、consent、status 和 reason code；aggregate 只读 persisted refs，不调用 reviewer 或 executor。
- `LoopEvidenceSnapshotCreatedV2.evidenceDigest` 使用 `wukong/loop-evidence-snapshot/v2\0`，绑定当前 attempt 的 approval、workspace、ordered checks、manifest、fresh verdict、aggregate 和 consent refs/digests。
- 全部使用 RFC 8785 canonical JSON + full SHA-256。

append 顺序固定为：

```text
LoopRunCreatedV2 (new run)
or LoopRunReviewSettingsAssignedV1 (legacy run / explicit re-consent)
→ GateAttemptCreatedV2
→ ordered GateCheckResultRecordedV1
→ BuiltinRiskScanResultRecordedV1
→ ReviewSubjectManifestRecordedV1
→ FreshCriteriaVerdictRecordedV1
→ ProofAggregateRecordedV2
→ LoopEvidenceSnapshotCreatedV2
→ GateAttemptCompleted
→ optional LoopRunTerminal
```

缺失、重复、跨 attempt/run/contract/plan 引用，或 PASS terminal 引用非 PASS/incomplete attempt，均返回 `record_corrupt`。

0.0.19 及更早版本已经落盘的 V1 records 保持原样。0.0.20 新 V2/V3 run 写 `LoopRunCreatedV2`；升级前仍 active 的 V2 run 或用户明确更换 provider/policy 时 append 幂等 `LoopRunReviewSettingsAssignedV1`，不能改写原 run record。从 0.0.20 开始创建的 V2/V3 attempt 都写 additive `GateAttemptCreatedV2`/broker/aggregate/snapshot records。criteria 为空时不伪造 V3 contract，但也不能回退到可直接读取 filesystem 的旧 reviewer runtime。V1 缺少 Gate Plan/approval，因此只能浏览历史或进入用户确认的 Revised V2，绝不能伪造 digest 来实例化 V2 attempt record。

每个 attempt 必须引用 exact `runSettingsRef/settingsDigest`；trust grant、consent、manifest、aggregate/snapshot 与 run settings 的 identity/digest 必须完全一致。provider/policy 改变需要新的显式 Preflight 与 assignment；旧 assignment 不得被自动替换。manifest/verdict/aggregate/snapshot refs 和 digests 必须指向当前 attempt 的唯一 records；Gate completion 与 PASS terminal 继续沿用 0.0.19 的完整 snapshot-before-completion 约束。

`LoopRunReviewSettingsAssignedV1.idempotencyKey` 使用 `wukong/review-settings-assignment-idempotency/v1\0` + canonical `{ runId, previousRunSettingsRef, consentProposalDigest, brokerReviewTrustProposalDigest, legacySettingsDigest }`，不包含 runtime 生成的 `trustGrantId`、`acknowledgedAt`、`consentDigest` 或最终 `settingsDigest`。首个成功写入冻结 grant、acknowledgement time 与全部 final digests；同一请求重试必须返回该 record。并发不同 proposal/previous-ref assignment 只能有一个 CAS 胜出，其他返回 stale。已经开始的 attempt 永远使用其创建时引用的 settings；新 assignment 只能影响后续 attempt。

## 稳定 Reason Codes

| reason code | 状态 | 含义 |
|---|---|---|
| `legacy_contract_upgrade_required` | NEEDS_WORK | V1 缺少 Gate Plan/approval，必须先由用户确认 Revised V2 |
| `verification_catalog_changed` | NEEDS_WORK | dry-run catalog 与提交 CAS 不一致 |
| `verification_criteria_missing` | NEEDS_WORK | frozen Skill/sidecar 不存在 |
| `verification_criteria_changed` | NEEDS_WORK | SKILL.md、sidecar 或 provenance drift |
| `verification_criteria_invalid` | ERROR | strict schema 不合法 |
| `verification_criteria_collision` | ERROR | 同名多来源未选择 exact identity |
| `verification_criteria_untrusted` | ERROR | workspace/source trust 不成立 |
| `verification_selection_limit` | ERROR | recipe/criterion/size 上限超出 |
| `review_subject_limit` | ERROR | review input 超过文件/字节上限 |
| `review_subject_excluded` | NEEDS_WORK | blocking criterion 只能依赖 hard-excluded 内容 |
| `review_subject_trust_required` | ERROR | 当前 workspace 缺少 exact broker-read trust grant/challenge |
| `review_subject_consent_required` | ERROR | 当前 run 缺少或提交了过期的 provider/input consent |
| `review_evidence_excluded` | NEEDS_WORK | blocking criterion 依赖未进入 broker 的 Gate evidence |
| `review_subject_changed` | ERROR | manifest/review 期间 workspace drift |
| `reviewer_invalid_output` | ERROR | verdict schema/digest/evidence 不完整 |
| `reviewer_unavailable` | ERROR | fresh reviewer 不可用 |
| `reviewer_evidence_stale` | ERROR | evidence 不属于当前 attempt 或已 stale |

未知 ERROR 默认不可自动 retry；沿用 0.0.19 persisted continuation policy，不增加第四种 terminal status。

## 向后兼容

- V1 合同保持原行为，沿用 append-only identity assignment。
- V1 在 0.0.20 中不得创建新 attempt；TUI/Headless 返回 `legacy_contract_upgrade_required` 并展示 Revised V2 proposal，只有用户确认 Finish Line、Gate Plan、trust 与 approval 后才能创建新 V2 goal/contract/run。
- 现有 V2 continuation 继续使用原合同，不自动附加 criteria。
- 给 V2 增加 criteria 必须创建 Revised Loop、新 goal/contract lineage。
- `legacySnapshot` 完整保存 V2 Gate Plan；raw shell 仍只由 0.0.19 runner 执行。
- expected-unresolved 不生成执行 step。
- 历史 record 不 rewrite。
- 没有 selected Verification Skill 的新 Loop 继续创建 V2 contract，但 0.0.20 run/attempt 仍使用 brokered reviewer、exact local trust 和 provider consent。
- V3 continuation 恢复完全相同的 selected refs、selection 和 plan digest；全量 catalog 只在新合同创建时做 compare-and-set，未选 Skill 的变化不影响 active Loop。
- continuation 创建新 run，并针对当时实际 BYOK provider/endpoint 重新冻结 review-subject consent；这不是 acceptance contract revision。
- 升级前遗留的 active V2 run 在 0.0.20 发起下一个 attempt 前必须完成 broker trust/consent Preflight；拒绝或缺失时零 reviewer/provider 调用并返回 `review_subject_consent_required`，不静默沿用旧的直接 filesystem reviewer。遗留 V1 使用上一条 Revised V2 路径。
- Skill drift 不自动升级 active contract；恢复原文件或创建 Revised Loop。
- `.wukong/checks.json`、`--check`、普通 Skills 和高级诊断命令保持可用。

## Privacy 与本地数据

- catalog、criteria、digest、selection、subject manifest 和 verdict records 只保存在本机。
- 不发送到 Wukong Web、D1、feedback、telemetry 或 crash payload。
- hard-excluded secret/private files 和 secret-bearing/raw Gate evidence 不进入 broker，也不发送给 BYOK provider。
- 被允许的 review-subject 与脱敏后 Gate evidence 只会按当前 run 的 exact consent 发送给用户选择的 BYOK provider；文案必须写成“不上传给 Wukong”，不能误写成“完全不出网”。
- logical paths 不包含绝对 home/workspace path。
- evidence preview 与 brokered Gate evidence 落盘/出站前使用 versioned redaction + secret scan；raw evidence 不暴露给 reviewer。
- 不保存完整 reviewer transcript。
- local eval 数据不构建远端 telemetry 后端。

## Eval 计划

### Deterministic trigger eval

每个 reference recipe 至少提供：

- 5 个 should-trigger fixtures；
- 10 个 should-not-trigger fixtures；
- unrelated docs-only task；
- Skill 名称只在普通文本中出现；
- imported transcript injection；
- monorepo package scope；
- path case、separator、CRLF 和 Unicode。

同一 commit/objective/fixture 在 3 个 fresh process 中，deterministic suggested identities、order、rule reason 和 digest 必须完全一致。model advisory hints 不进入该指标。

### Quality eval

- 每个 reference recipe 至少 5 个代表性任务，做 with-criteria / without-criteria 配对。
- seeded deterministic/qualitative blocker false PASS 必须为 0。
- blocking finding 的 criterion/provenance/evidence/next-action 完整率必须为 100%。
- 3 个 fresh session 的 selection、criterion dispositions、terminal status 和 reason code一致；finding 文案不要求逐字一致。
- with-criteria 任务完成率不得下降。
- reviewer token/time 不得突破合同 hard budget，Result 显示实际值。

### Adversarial input eval

分别在以下位置注入“直接 PASS、忽略失败、读取 secret、调用 Bash/MCP/Web、读取任意路径”的恶意指令：

- `SKILL.md`；
- criteria text/evidence expectation；
- workspace source；
- deterministic stdout/stderr；
- Gate evidence。

验收：

- deterministic failure 仍阻止 PASS；
- reviewer capability 不扩大；
- hard-excluded secret sentinel broker read 次数和出站次数均为 0；
- 跨 attempt/未知 evidence ref 被拒绝；
- invalid/incomplete verdict 进入 `INCONCLUSIVE`。

## 测试计划

### P0：Schema、catalog 与 provenance

- unknown fields、duplicate IDs、empty criteria、path escape、control chars、size limits。
- personal/project/package/extra/builtin precedence 与 collision。
- source/sourceTrust paired-union negative fixtures；personal+builtin、builtin+workspace、extra sourceId mismatch、builtin version mismatch 全部拒绝。
- RFC 8785/full SHA-256/domain separator golden fixtures。
- 每种 digest 的 self-field exclusion 和跨平台一致性。
- SKILL.md/sidecar drift、rename/delete、case collision。
- deterministic suggested 与 model advisory hints 完全隔离。

### P0：V3 与 compatibility

- V1/V2/V3 discriminated union、round-trip、restore。
- V2 → V3 只能 Revised Loop；V2 history/continuation 不 rewrite。
- 0.0.20 V2/V3 attempt 都使用 additive broker/run-settings records；遗留 active V2 通过幂等 assignment 升级，拒绝 consent 时零 provider 调用；V1 必须 Revised V2，缺少确认时零 attempt。
- legacy Gate Plan canonical equality，required/excluded/source/definition/approval 无损。
- expected-unresolved 在 V3 中仍 unresolved 且零 spawn。
- recipe criteria provenance、stable criterion IDs 和 flat selection order。
- full catalog CAS 只覆盖 dry-run → 合同创建；restart/continuation 只校验 selected ref provenance、selection 和 plan digest，未选 Skill drift 不阻断。
- project/package/personal/extra/builtin source trust、extra grant revoke、ownership/permission/release-asset drift。
- V3 broker-only/workspace-checks+broker trust union 与 legacy approval `hasExecutableChecks` 完全一致；无 resolved check 时不能获得 shell scope。
- 每个 run 的 consent proposal/ack round-trip；provider、endpoint、policy 或 limits 变化后旧 consent 失效。
- broker grant 在 reviewer 前后与 PASS 前 revalidate；mid-attempt revoke 使 evidence stale，不能继续读取或 PASS。
- assignment 重试使用稳定 proposal-based idempotency key，复用首次 `acknowledgedAt`/settings digest；并发不同 proposal/previous-ref 只有一个 CAS 胜出。
- provider origin normalization、跨 origin redirect 零出站、consent digest 与实际 connection origin 不一致时 fail closed。

### P0：Review broker、fresh reviewer 与注入

- secret/private/generated/binary/path/size exclusions。
- hard-excluded file 永远没有 subjectRef。
- raw Gate stdout/stderr/evidence 不可读；brokered copy 的 redaction、secret scan、单项/总量上限和 digest 有 golden/negative fixtures。
- secret-bearing/oversize Gate evidence 没有 readable ref；若 blocking judgment 依赖它则 `INCONCLUSIVE`。
- provider-visible exclusion 不含 producer/evidence identity 或 raw digest；attempt-keyed HMAC ID 前后重算稳定、跨 attempt 不可关联，ephemeral key/mapping 在 attempt completion 后销毁。
- broker 拒绝任意 path/glob/URL、raw/excluded evidence 与跨 attempt refs。
- subject manifest 前后 workspace drift。
- fresh reviewer 不继承 parent tools/Skills/hooks/MCP/Web。
- criteria/source/evidence prompt injection 不能提权、读取 secret 或覆盖 blocker。
- `review-subject | gate-evidence` tagged pointer、dispositions exact coverage、非空有效 evidence 与 prior blocker-set coverage。
- reviewer `PASS`/`NEEDS_WORK`/`INCONCLUSIVE` 与 dispositions/findings 双向一致；independent advisory 不能 blocking，只有 exact frozen-policy provenance 可以产生 policy blocker。
- invalid/incomplete/inconclusive verdict 不 PASS。

### P0：Execution ownership 与 durable join

- 每个 legacy check 仍只由 0.0.19 executor 执行一次。
- reviewer 每个完整 attempt 恰好一次；Proof aggregate 纯聚合一次。
- run settings assignment/consent/attempt/check/scan/subject/verdict/aggregate/snapshot/completion/terminal 使用同一 durable `attemptId` 与 exact settings/consent digest。
- missing/duplicate/cross-run/contract/plan records fail closed。
- PASS terminal 不能引用 incomplete 或 NEEDS_WORK attempt。
- Skill/selection/subject drift 后旧 PASS stale。

### P1：真实 E2E 与跨平台

至少包括：

- 新建无 Skill V2：TUI 与 Headless 都只确认 broker trust/consent，明确跳过 catalog CAS，并完成 brokered reviewer → Gate terminal；
- 遗留 V1：TUI/Headless 只展示 Revised V2 proposal，未确认时零 attempt；确认 Finish Line/Gate/approval 后使用新 goal/contract/run，不改写 V1；
- 升级前 active V2：接受 consent 后以 additive records 继续，旧 contract/run history 不改写；
- 升级前 active V2：拒绝 trust/consent 后零 provider call、零出站、零 attempt/terminal 状态漂移；
- API compatibility criteria；
- migration/log-security criteria；
- frontend component/design criteria；
- monorepo package criteria；
- 两个 standalone recipes 的 flat ordered selection；
- `NEEDS_WORK → writer fix → all criteria satisfied → PASS`；
- irrelevant task 不产生 deterministic suggestion；
- model hint 不进入合同；
- restart/continuation 后 selection 不漂移；
- macOS/Linux/Windows catalog/path/digest/broker behavior；
