# 0.2.0 Pro Reliable Autonomy（旧草案，待重新规划）

> **状态：SUPERSEDED / 不可作为当前实现、收费或发布日期依据。**
> 2026-07-30 取消 isolated worktree / Safe Promote 后，本文及其 Bounded
> Parallel Loop、Local Loop Supervisor 组件依赖的 Promote、lease、
> fencing 和 Final Gate 架构均已失效。以下正文只保留历史研究上下文。
> 0.2.0 当前没有已批准技术方案、收费 SKU、价格或 Checkout；只有 0.1.0
> 发布并出现真实重复多任务监督需求后，才允许重新研究和单独批准。

## 一句话定义

> **Pro 不出售用户自己的 API Key 或本地 Loop 次数；它出售可控的可靠自治：2–5 个隔离任务的有界并行、用户显式 Detach 后的本机 exception-first 监督，以及可选的 Verified PR Gate 工作流。**

0.2.0 的核心不是“更多 Agent”，而是减少人持续盯过程的时间，同时保持：

- 明确意图和冻结合同；
- 隔离执行与确定集成；
- 硬预算与执行 fencing；
- approval、问题、冲突和加预算仍由人决定；
- 最终结果仍由真实 workspace Gate 验证；
- 机器关闭后不执行，源码和 evidence 不上传 Wukong。

## 1. 为什么不放进 0.1.0

0.1.0 先证明单个 Trusted Local Loop 可以被稳定安装、完成、恢复和推荐。并行、Detach、Supervisor、GitHub 写入和 Billing 会同时增加：

- 多 worktree 的资源与冲突管理；
- parent/child/integration lineage；
- 跨进程 execution authority 与 owner-death；
- aggregate BYOK budget；
- 支付、entitlement、取消、退款和支持义务。

把它们与 0.1.0 同日发布，会让稳定性和付费价值都无法清楚验证。因此 0.2.0 只能在 0.1.0 真实使用成立后，以邀请制 Pro Pilot 验证。

## 2. 产品分层

### 2.1 Free Forever

Free 保留 0.1.0 的完整本地价值：

- 单个前台 Loop。
- BYOK writer/reviewer，不要求登录。
- Resume、Finish Line、Verification Criteria、Gate。
- 单 Loop exact snapshot、独立 worktree、safe Promote 和 target Final Gate。
- 本地恢复、取消、continuation 和高级诊断。
- 不按 Loop、轮次或 BYOK token 设置 Wukong quota。

安全 primitive 不能被付费墙降级。Free 与 Pro 使用相同的 snapshot、lease、Gate、redaction、permission 和 fail-closed 基线。

### 2.2 Pro Pilot

候选 Pro Pilot 只包含一组连贯价值：

1. **Bounded Parallel Loop**
   - 一个父 Loop 拆成 2–5 个扁平 required tasks。
   - 每个写任务使用独立 worktree。
   - 默认并发 2，hard fan-out 5。
   - planner、child、retry、reviewer、integration 和 Final Gate 共用硬预算。
   - 冲突、缺失 required child 或预算不足不能误报 PASS。

2. **Explicit Detach + Local Loop Supervisor**
   - 只有用户确认 exact detach digest 后才在本机后台继续。
   - 统一查看多个 Loop，只提升 approval、问题、冲突、预算、provider 和终态等 exception。
   - Attach、Pause、Resume、Cancel 使用 CAS 与幂等状态。
   - 机器关机、owner 失效或状态不明时停止新工作并 fail closed。

3. **Verified PR Gate（候选附属能力）**
   - 在本地生成、redact、预览 Gate summary。
   - 可将结论幂等更新到用户已有 GitHub PR。
   - 绑定 exact commit SHA，stale/partial write 返回 ERROR。
   - PR Gate 不是单独的主要购买理由；只有真实用户证明它能提高可靠自治的交付闭环时才进入 Pilot。

### 2.3 Team Later

Team 不进入 0.2.0 自助购买。只有出现多个真实团队共同需要以下能力时，才另立版本：

- shared Verification Skills / policy；
- org/repo/path 级 required rules；
- shared budgets、audit、retention；
- GitHub App、SSO/SCIM、private runner；
- 团队 approval 与责任边界。

“个人 Pro 有并行”不等于已有 Team 产品。

## 3. SKU 与价格实验

0.2.0 候选商业实验只允许：

- 一个 Pro SKU；
- 邀请制、月付；
- 候选价格 `$12/月`；
- 无年付、终身版、seat billing、多档 Pro 或复杂超额费；
- Pricing 在公开 Checkout 前仍只展示当前 Free 产品，不把候选价格写成可购买。

`$12/月` 是实验假设，不是公开承诺。收费验证的是“减少监督、可靠完成多个任务”的价值，不是 BYOK token、模型额度或人为限制后的解锁。

## 4. Pilot 进入门槛

开始任何真实收费 Pilot 前必须同时满足：

### 产品证据

- 0.1.0 已正式发布并完成至少 30 天稳定观察。
- 至少 15 位外部用户完成过真实目标 workspace Final Gate `PASS`。
- 至少 7 位在 14 天内对第二个不同 Goal 再次取得 Final Gate `PASS`。
- 至少 5 位目标用户明确出现“同时推进多个任务或频繁回来处理 exception”的重复需求。
- 单 Loop 的 false PASS、workspace damage 和不可恢复 Promote 已知 P0/P1 为 0。

### 工程证据

- parallel parent/child/integration/final Gate 全链路通过 fault-injection。
- global/per-Loop capacity、token/time、provider concurrency 与 cancel/restart fencing 通过。
- Detach、owner-death、sleep/wake、crash/restart 和 lost process reconciliation 跨平台通过。
- account/entitlement service 不可用时仍能完整运行 Free 单前台 Loop；Pro capability unknown 必须 fail closed。
- Billing Test Mode、cancel、refund、grace、portal、webhook duplicate/out-of-order 和 entitlement recovery E2E 通过。

### 隐私与支持

- 源码、prompt、diff、transcript、绝对路径、secret 和 raw Gate evidence 不进入 Wukong Web。
- 用户明确理解 Detach 是本机后台，不是云端；机器关闭后不会继续。
- Terms、Privacy、退款、取消、支持范围和数据处理说明已同步。
- 已准备可回滚的 allowlist、kill switch 和人工支持流程。

## 5. Pilot 与公开收费门槛

### 邀请制 Pilot

- 邀请 10 位目标用户。
- 至少 5 位实际使用 Pro 能力完成真实任务。
- 至少 3 位非关联用户完成真实付款。
- 至少 2 位进入第二账期并续费。
- 每个付款用户的购买原因能明确归因到并行/监督/可靠交付，而不是“支持项目”或误以为包含模型 credits。

### 公开 Checkout

公开 Checkout 不是 0.2.0 代码完成后的默认动作。还必须满足：

- 至少 10 个付费 Pilot 用户完成真实 Pro Loop。
- 至少 5 位在 30 天内重复使用 parallel 或 Supervisor。
- 至少 3 位完成续费。
- 0 个未解决 Billing/entitlement P0/P1。
- 0 个未解决 privacy、false PASS、workspace damage 或失控后台执行事件。
- 支持成本和退款原因可接受，并有书面继续/调整/停止决策。

未满足时保留 invite-only；代码存在不能替代付款、复用和续费证据。

## 6. Entitlement 原则

- capability-based，不用 `tier === pro` 猜权限。
- Free local Loop 永远不查询或消耗 paid allowance。
- Pro 服务故障只阻止 Pro admission，不阻止 Free 单前台 Loop。
- capability 必须在开始 parallel/Detach/PR write 前确认；执行中失联使用短期、受限、可审计 lease，不能永久 fail-open。
- entitlement unknown、expired 或 revoked 后禁止新的 child、Detach、Resume-execution 和 GitHub write；已在途任务只能推进到下一个 durable safe checkpoint，然后转为 `needs_attention`。
- 降级后用户仍可只读查看、Cancel、导出本地摘要、reconcile 和保留 candidate/result；不能因失去 Pro capability 删除本地状态或锁住恢复入口。
- 正在执行的 Promote 原子临界区不能被 Billing 变化粗暴中断；它必须完成当前 fenced transaction 或按 journal 回滚/reconcile，随后停止新工作。Billing 状态永远不能改变 Gate outcome 或制造 PASS。
- 退款、争议、取消和 grace 的状态转换由服务端真实 billing projection 决定。
- 隐藏 UI 不是权限控制；CLI、Web/API 都由同一 server-side resolver 执行。
- Wukong 不对 BYOK token 加价，也不把用户 provider key 代理为收费 inference。

## 7. Billing 最小闭环

如果 Pilot 被批准，必须一次完成：

- server-side Price allowlist；
- 每用户最多一个 active/grace subscription；
- Checkout、Customer Portal、周期末取消与恢复；
- signature verification、event id 去重、乱序安全和 Stripe object 回读；
- subscription/invoice/refund/dispute/grace/recovery；
- success page 轮询真实 entitlement；
- append-only billing event ledger + current projection；
- CLI/Web 显示 capability、billing 状态和管理入口；
- allowlist、public checkout flag 与 emergency kill switch。

`checkout.session.completed` 本身不能直接授予长期 entitlement。

## 8. 0.2.0 明确不做

- 128 workers、递归 Agent Tree 或动态无界 workflow graph。
- 云端 agent、Hosted Terminal、Hosted Report、Remote Control 或跨设备执行。
- 自动审批、自动回答用户问题、自动增加预算或自动扩大 permission。
- 机器关闭后继续运行、开机自启或不可见 daemon。
- managed model credits、托管 reviewer、BYOK markup 或 usage overage。
- Team/Enterprise、SSO/SCIM、组织 audit、private runner。
- telemetry 产品指标后端；Pilot 使用明确同意的 cohort、billing evidence、访谈和本地可导出摘要。
- 将 worktree、process group 或 owner-death guard 宣传成完整 sandbox。
- 为每个内部组件新增默认顶层命令；产品面继续由 `/loop` 驱动。

## 9. 发布顺序

```text
0.1.0 stable
  → 30-day observation
  → 0.2.0 internal alpha
  → 10-user invite-only Pilot
  → payment + reuse + renewal review
  → keep invite-only / revise / stop
  → only then consider public Checkout
```

0.2.0 可以发布为 Free stable + invite-only Pro capability，但不能在没有真实 Pilot evidence 时把公开 Checkout 当作 release checklist 的默认终点。

## 10. 0.2.0 完成定义

0.2.0 只有在以下条件全部成立时才算完成：

1. 0.1.0 Free contract 无回退，服务故障不阻止单前台 BYOK Loop。
2. Bounded Parallel 与 Local Supervisor 两个组件达到各自完成定义。
3. parent/child/integration/Promote/Final Gate 不会因 partial success 产生 false PASS。
4. Detach、owner-death、capacity、cancel、crash/restart 和跨平台恢复通过。
5. Pro capability 与 Billing 全生命周期 fail closed，取消/退款/争议可恢复。
6. 隐私文案、产品 UI、CLI、Web/API 和 entitlement 一致。
7. 邀请制 Pilot 至少取得 5 个真实 Pro users、3 个付款用户和 2 个续费用户。
8. 是否公开 Checkout 有独立证据评审；未通过时继续 invite-only，而不是伪造“已公开收费”。

在实施批准前，本文件、组件规格和价格都只能写作 Candidate。
