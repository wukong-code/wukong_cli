## 一句话定义

> **0.1.2 不增加 Wukong 能做的事，只让第一次使用能自己走通，并把 60 个入口收敛成
> 一条默认路径：安装 → Provider → Preflight → Loop → Gate。**

0.1.0 冻结了 Loop 的用户合同，0.1.1 修好了可靠性。剩下的问题不是能力不足，而是
**能力找不到、第一次跑不通、跑不通时不知道卡在哪**。0.1.2 只解决这一类问题。

## 2. 用户价值假设与证据缺口

**本版本尚未附上可复核的一手使用证据。** 规划时“无 open issue”等观察只属于历史
快照，本次未重新核对远端 issue 或私有 cohort。optional CLI telemetry 的接收端已在
`wukong_web/workers/telemetry` 实现只存安装 ID、使用日期、版本、平台与架构，以及
90 天清理；它不存事件内容，也不能证明任务完成或重复使用。源码契约见
[CLI telemetry contract](../operations/cli-telemetry.md)，生产部署与清理执行本次未复验。
`reports/latest/*.jsonl` 是本地测试结果，不是用户行为。因此下面是**假设**，不是结论。

按"工程投入 + 公开定位 + 获客路径"三个代理信号排序：

| 假设的高价值能力 | 支撑信号 | 0.1.2 处置 |
|---|---|---|
| `/loop`（写→检查→审查→修复，带可解释终态） | 0.0.12 起每个版本的主线；`agent/goal` 4382 行是全仓最大模块；ROADMAP 一句话定义即 Loop | 列入 core，且是唯一被 installer 指向的终点 |
| `/resume`（Codex/Claude Code/Cursor/Kimi/Grok 五来源导入） | 唯一的跨产品获客入口；0.0.14 起持续扩源；0.1.1 还在修跨 workspace 误导入 | 列入 core，保持五来源 |
| `/provider`（BYOK 配置） | Loop 的硬前置；0.1.1 刚为它做过原子写入修复 | 列入 core，并补连通测试 |
| Gate 结果可解释（PASS/NEEDS_WORK/ERROR/PAUSED/STOPPED_BY_USER） | 0.1.1 专门修了公开文案；是与"自动 PASS 动画"的差异点 | 三个真实案例必须展示非 PASS 终态 |
| `/swarm`、`/today`、`roles`、`vis` | `agent/swarm` 核心仅 60 行，但 TUI 侧 `agent-swarm-progress.ts` 有 1727 行；`today`、`roles` CLI 各约 100 行 | 投入与位置不匹配 → 降级为 advanced，不删除 |

**证据缺口**：没有任何数据说明用户实际最常用哪个命令。0.1.2 不引入新 telemetry
event 来补这个缺口（与 0.1.0 的承诺一致），改为用**三个授权脱敏真实案例**产生
可复核的一手记录。在这三个案例完成前，任何"用户最喜欢 X"的表述都不得写进公开
文案。

## 3. P0 交付项

实施顺序优先首次成功路径及其真实用户验证，再完成其余已批准的命令面、headless
与 Web 收敛及维护项；发布仍须满足本页全部门槛。客户发现和现有能力陪跑可并行，
不等待 0.1.2 新 binary 或 0.2.0 完整瘦身；这不授权实施 0.1.3 候选或开展收款。

### 3.1 首次成功路径

- **一致的下一步。** `install.sh`、npm postinstall 和 `wukong doctor` 输出同一条
  `cd project → wukong → /provider → /loop`，由同一份常量生成，并有断言三处一致的
  回归测试。PATH 未包含安装目录时，先给出 PATH 修复，再给下一步。
- **Provider 连通测试。** 新增显式 `wukong provider test [providerId]` 与 TUI
  `/provider` 内的等价动作：发起一次最小请求，区分并分别提示
  `auth-failed` / `not-found` / `network` / `timeout` / `ok`。约束：只在用户显式触发
  时发起；不打印 key、endpoint query 或响应体；不因失败而改写配置；无网络时给出
  明确的 offline 结论而不是伪装成功。
- **可恢复 Preflight。** 把 0.1.1 的"进程内保留编辑"升级为落盘草稿：Preflight 的
  用户编辑（Goal、Done when、Must not、check 选择、运行上限）以 workspace 为键持久化，
  进程重启、修复 provider 配置后重进 `/loop` 时提示"继续上次 Preflight / 重新开始"。
  草稿不含 secret，不含 evidence，不自动执行；被 `/loop` 成功启动或用户显式丢弃后
  即删除。
- **单一确认的 headless run-plan。** `wukong loop --dry-run` 增加
  `--plan-out <file>`，写出不含 secret 的可审核 run-plan；`wukong loop --plan <file>`
  读回同一份 plan 并只需**一个** `--approve-plan <digest>` 即可启动，digest 覆盖
  当前 8 个 digest/challenge 的全集。约束：8 个既有 flag 全部保留可用一个 minor；
  plan 文件与 workspace、contract schema version、broker 有效期绑定，任何不一致
  fail closed；新增负向测试断言 plan 文件不含 provider key、endpoint credential、
  transcript、raw evidence 与绝对 home 路径。

### 3.2 命令面收敛（只改默认可见性，不删能力）

- **TUI core 收敛为 8 个**：`/loop`、`/resume`、`/provider`、`/settings`、`/new`、
  `/help`、`/feedback`、`/exit`。把 `/permission`、`/model`、`/transform`、`/login`、
  `/logout` 从默认 tier 降为 `advanced`。所有命令继续可直接输入、可通过
  `/help --all` 发现、自动补全在输入前缀后仍然命中。
- **CLI 引入与 TUI 对齐的三级 tier**：`core` = `wukong`、`-p`、`provider`、`loop`、
  `doctor`、`upgrade`、`check`、`web`（2026-10-02 决定：local Web UI 作为默认入口之一）；`advanced` = `export`、`review`、`roles`、`today`、
  `guard`、`judge`、`login`、`logout`；`hidden` 维持现状。`wukong --help` 只列 core
  并在结尾指向 `wukong help --all`；`wukong help --all` 列全部，含当前隐藏项。
  commander 无三级 tier，需要在 `cli/commands.ts` 增加一层 help 渲染，不是逐条加
  `hidden: true`——后者会让 advanced 命令彻底不可发现。
- **新增聚合入口 `wukong check`**：一条命令跑 Loop 使用的同一套项目检查与风险规则，
  只给出确定性检查通过、失败或执行错误，并明确 `reviewer: not_run`；不能输出完整
  Gate PASS 或声称任务已验收。完整 Gate 仍须冻结合同、检查及 fresh-context reviewer
  共同判定，不改变其语义。`verify`、`scan`、`proof`、`judge`、`guard` 在本版本
  **只降级为兼容别名**，行为不变、不打印删除警告以外的新语义，至少保留到 0.2.0 之后
  的一个 minor。`wukong check` 不做模型调用，保持确定性。
- **命令契约回归**：沿用 0.0.17 建立的命令契约测试，断言 (a) core 集合精确等于上述
  列表，(b) 每个 advanced/hidden 命令仍可执行，(c) 每个兼容别名的退出码与输出与
  0.1.1 一致。

## 4. 三个授权脱敏真实案例（发布门槛的一部分）

替代"动画 PASS"的验收证据。每个案例必须由真实用户在真实仓库完成，且经授权脱敏后
可公开复核：

1. 覆盖 `install → provider test → /loop Preflight → Loop → Gate` 全链路；
2. 至少一个案例经由 `/resume` 从外部 agent session 导入开始；
3. 至少一个案例以 **NEEDS_WORK 或 STOPPED_BY_USER** 结束，并展示证据与下一步；
4. 每个案例记录首次成功耗时、卡点位置和用户原话结论；
5. 案例不含源码、路径、repo 名或 provider 凭据。

案例是**发布门槛**，不是发布后学习：三个案例未就绪，0.1.2 不得替换官网 PASS 展示，
也不得对外宣称"首次成功"改善。

## 5. 兼容与弃用策略

- 不删除任何命令、别名或配置项。`verify`/`scan`/`proof`/`judge`/`guard`、
  `/permission`/`/model`/`/transform`/`/login`/`/logout` 全部保持可执行。
- 降级只影响 `--help`、`/help` 与自动补全的默认列表；显式输入与脚本调用不受影响。
- headless 的 8 个 digest/challenge flag 与新的 `--plan/--approve-plan` 并存一个
  minor，且两条路径产生同一 contract digest。
- 0.1.1 写出的 records、snapshot、Loop session 必须能被 0.1.2 直接恢复；新增
  Preflight 草稿是可选文件，缺失时行为等同 0.1.1。
- 生产旧表只冻结不 DROP。

## 6. 发布门槛（minor 级别）

必跑，不可豁免：

- 全量自动化 + typecheck + lint + build + sherif + publint + Are The Types Wrong；
- 命令契约回归：core 集合精确匹配、advanced/hidden 仍可执行、兼容别名行为不变；
- `wukong check` 语义回归：确定性检查通过但 reviewer 未运行时，明确标记未运行，
  不输出完整 Gate PASS；没有检查、部分执行、执行失败和过期证据均不得冒充完整验收；
- run-plan 负向测试：plan 文件不含 secret、凭据、transcript、raw evidence、home 绝对路径；
- Provider 连通测试矩阵：`ok` / `auth-failed` / `not-found` / `network` / `timeout` / offline；
- Preflight 草稿矩阵：取消、进程重启、修复配置后重进、显式丢弃、损坏草稿 fail closed；
- 恢复兼容回归：0.1.1 records/session 全部可恢复；
- 六平台构建 + checksum + provenance + fresh install + 0.1.1 → 0.1.2 upgrade smoke；
- 中英文发布面同步：CHANGELOG、官网版本面、README、user-guide、docs 侧边栏；
- 三个授权脱敏真实案例；
- Web 生产 high 归零或有 owner/期限/缓解措施；Actions 不再触发 Node.js 20 弃用告警。

可豁免（记账到 TODO，由下一个 minor 关闭）：cohort 对齐与集中宣传门槛。

## 7. 明确不做

- 不做 GoalMode / TUI / `useWukongWebClient` 拆分，不动 225 条 boundary baseline——
  属于 0.2.0，需要先批准迁移设计。
- 不把 Visualizer 或 `dist-web` 移出 CLI bundle。12 MB + 17 MB 的分发体积是真实问题，
  但拆分会改变 `wukong vis` 与 local Web 的获取方式，属于 0.2.0 的扩展边界工作。
- 不删除 `@wukong/migration-legacy`。
- 不新增 telemetry event；不在网站数据库中建设 metrics backend。例外：2026-10-02 决定：为已发布的 optional CLI telemetry 补上接收端，但只统计安装数（独立 D1 `wukong-telemetry`，只存随机安装 ID、使用日期、版本和平台；不存任何事件内容；忽略账号令牌、不存 IP；最后使用 90 天后删除），不作 cohort 证据，由 `wukong_web/workers/telemetry` 承载，不改变 CLI 发送的字段。
- 本版本不做 PR Check、共享 policy、团队权限/预算、Billing、hosted model、云端 Agent、
  `/schedule`、managed credits、公开 Checkout。后续最小 PR Gate 归 0.1.3 试点候选；
  共享治理与完整 Billing 归 0.3.0 产品化评审，其他能力继续后移。
- 不新增默认 `/agents`、`/parallel`、`/worktree`、`/supervisor`。
- 不引入 process sandbox、dynamic workflow graph、Remote Control、Hosted Terminal。

## 8. 完成定义

0.1.2 完成，当且仅当：

1. 一个从未装过 Wukong 的用户，只按 installer 输出的三步，能在不看文档的情况下
