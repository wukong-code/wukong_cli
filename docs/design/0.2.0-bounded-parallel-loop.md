# 0.2.0 组件：Bounded Parallel Loop（历史草案）

> Internal engineering record — kept in Chinese. English product docs: the user guide and release notes.

> **状态：SUPERSEDED / 不可实施。**
> 本文依赖的 0.0.21 snapshot、worktree lease、Candidate Gate、Promote 和
> target Final Gate 已于 2026-07-30 取消。以下正文只保留研究过程，不能
> 作为 0.2.0 功能、Free/Pro 权益、测试或收费依据。若未来真实用户证明需要
> 有界并行，必须从当前已发布能力重新设计并单独批准。

## 一句话定义

> **让一个父 Loop 把冻结合同拆成 2–5 个扁平叶子任务，在独立 worktree 和统一硬预算内并行执行；结果按冻结顺序集成后，只有集成候选与真实目标 workspace 的最终 Gate 可以产生 PASS。**

0.0.21 与 0.1.0 先证明“一个 Loop 能隔离执行、安全回写并稳定发布”，0.2.0 的 Parallel Phase 才证明“多个写 Agent 能在明确上限内并行，而且不会因碰撞、漏算成本或部分失败误报完成”。

本版不追求 Agent 数量。默认并发为 2，硬 fan-out 为 5；当前内部 `AgentSwarm` 的 128 上限不是产品能力。

## 研究依据

本设计参考：

- [Steps of AI Adoption Artifact](https://claude.ai/code/artifact/bfdfaef9-bc62-4dfe-ba9e-c58a26c9accf)
- [Claude Code subagents](https://code.claude.com/docs/en/sub-agents)
- [Claude Code worktrees](https://code.claude.com/docs/en/worktrees)
- [Dynamic workflows in Claude Code](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)
- [Running an AI-native engineering org](https://claude.com/blog/running-an-ai-native-engineering-org)

吸收的原则：

1. 并行 Agent 必须使用隔离 worktree。
2. 人应确认任务拆分、预算和最终集成结果，而不是逐条监督输出。
3. 自动 tests、lint、typecheck、security review 和最终 diff review 必须先于扩张并发。
4. 并发越大，review、成本、冲突和异常处理越容易成为新瓶颈。
5. 最终完成判断属于父 Loop 的集成 Gate，不属于任何 child。

不照搬的部分：

- 不采用 `~10/~100/~1,000+` 作为容量或成熟度目标。
- 不允许模型动态生成无界 workflow graph。
- 不允许 child 递归启动写 Agent。
- 不提供云端 Agent、手机控制、Slack 常驻 Agent 或 Team 控制面。
- 不把 token 使用量或 Agent 数量当成成功指标。

## 当前实现基线与风险

现有 AgentSwarm 可以批量启动 subagent，但不是安全并行 Loop：

- 每个 child 继承父 Agent `cwd`，没有独立 worktree。
- 单次 schema 最多接受 128 个 child。
- 默认启动节奏没有用户可见的并发硬上限；环境变量未设置时不会形成产品级 cap。
- child token usage 没有完整计入父 Goal budget。
- parent wall-clock 到期通常要等当前 tool/turn 返回后才能发现，不能证明立即终止整棵任务。
- 部分或全部 child 失败时，Swarm tool 仍可能作为普通完成结果返回；TUI 可能显示 overall `Completed`。
- `/tasks` 能看当前 session 的后台任务，但没有 parent/child/integration/Gate 的统一 lineage。

因此，0.2.0 不能直接给现有 AgentSwarm 增加一个 UI 开关。它需要新的 Parallel Loop contract、scheduler、budget ledger 和 integration Gate。

## 用户问题

1. 多个写 Agent 在同一 cwd 中会覆盖文件，无法证明谁产生了最终 diff。
2. 任务拆分如果存在隐含依赖或路径重叠，并行反而增加返工。
3. child 的局部成功可能掩盖另一个 required child 失败。
4. 子 Agent、reviewer、retry 和集成步骤的 token/time 没有统一硬预算。
5. rate limit 或 provider usage 缺失时，系统可能继续乐观启动任务。
6. 冲突若交给模型静默解决，父合同可能被弱化。
7. 并行结果没有确定集成顺序，重跑可能得到不同 workspace。
8. 取消父任务后，后台 child 或子进程可能继续运行。
9. 用户看到多个 “Completed”，但不知道最终集成 Gate 是否真的通过。

## 版本目标

1. 让父 Loop 冻结一份 `ParallelPlanV1`，只包含 2–5 个扁平叶子任务。
2. 每个 mutating child 必须使用 0.0.21 的独立 snapshot、worktree lease 和 delta primitives，但 child 只产生局部 readiness，不复用根 Loop 的 candidate PASS。
3. 启动前展示任务拆分、path scope、集成顺序、并发和总 BYOK 预算。
4. 无法证明可并行、存在确定依赖或明显 scope 重叠时，回退到 serial Loop。
5. 默认并发 2，允许用户在 1–5 内选择，任何入口都不能绕过 hard fan-out 5。
6. parent、planner、child、retry、reviewer、integration 和 final Gate 共享一个硬预算 ledger。
7. 为 integration 与 final Gate 预留预算，不能被前面的 child 消耗完。
8. 所有 child delta 按冻结顺序进入独立 integration worktree。
9. changed-path 或 hunk 冲突必须停止集成，不能静默覆盖或自动解决。
10. 任一 required child 未达到 `ready`，或处于 `blocked/failed/aborted/not_started/lost`，都阻止 integration 和 parent PASS。
11. 只有 integrated candidate Gate + Promote + target final Gate 能产生 terminal PASS。
12. parent cancel 能级联停止 queued/running child 和已知 process tree。
13. crash/restart 不重复启动 child、调用 provider 或 Promote；若 integration 在一个多文件 delta 中途失去 owner，废弃该 owned attempt 并从 immutable base 创建新 attempt 确定重建，不在未知 partial tree 上盲目续写。
14. TUI 与 Headless 使用相同 parent/child/budget/integration reason codes。

## 强依赖

本组件实施前必须满足：

1. 0.0.21 source snapshot、worktree lease、delta、Promote 和 final Gate 通过四类发布门槛。
2. 0.0.20 brokered reviewer、criteria provenance 和 exact provider consent 模型可扩展到已确认的 parallel plan；旧 serial consent 不能自动复用到多个 worktree。
3. 0.0.19 parent Acceptance Contract、Gate Plan、terminal 和 continuation 仍是唯一完成真相源。
4. 当前 subagent batch/rate-limit/cancellation 只能作为底层组件复用，不能直接视为 Parallel Loop 合同。
5. 任一 worktree、budget 或 final Gate 前置不成立时，只能生成只读拆分 proposal 或退回 serial Loop。

## 核心不变量

### 1. 父合同只冻结一次

Parallel mode 不创建第二套完成语义：

- parent `AcceptanceContract`、Finish Line、Must not、Gate Plan 和 selected criteria 保持不可变。
- child task 只是 parent contract 的有界投影。
- child 可以增加更严格的局部约束，不能删除或弱化 parent constraint/check。
- 外部 transcript、planner 建议或 child output 不能获得 contract revision 权限。
- 改 objective、required check 或 blocking criterion 必须创建 Revised Loop。

### 2. Parallel Plan 必须扁平、有界、可确认

```ts
interface ParallelPlanV1 {
  readonly schemaVersion: 1;
  readonly planId: string;
  readonly parentGoalId: string;
  readonly parentContractId: string;
  readonly parentContractDigest: string;
  readonly baseSnapshotDigest: string;
  readonly baseMaterializedSourceDigest: string;
  readonly tasks: readonly ParallelLeafTaskV1[];
  readonly integrationOrder: readonly string[];
  readonly concurrencyLimit: number;
  readonly aggregateBudgetDigest: string;
  readonly planDigest: string;
}

interface ParallelLeafTaskV1 {
  readonly taskId: string;
  readonly objective: string;
  readonly pathScope: readonly PathScopeV1[];
  readonly constraints: readonly string[];
  readonly expectedOutput: string;
  readonly required: true;
}

interface PathScopeV1 {
  readonly scopeId: string;
  readonly repositoryRootIdentity: string;
  readonly kind: 'exact' | 'prefix';
  readonly canonicalRelativePath: string;
  readonly casePolicy: 'sensitive' | 'insensitive';
  readonly symlinkPolicy: 'deny';
  readonly scopeDigest: string;
}
```

P0 规则：

- `tasks.length` 只能是 2–5。
- 所有 mutating leaf 都是 required；P0 不用 optional child 隐藏失败。
- task graph 必须扁平，child 不能启动另一个 mutating child。
- `integrationOrder` 覆盖每个 task 恰好一次。
- P0 不接受 glob。exact/prefix scope 必须基于 frozen repository root 解析 `.`/`..`、Unicode normalization、platform case policy 和 filesystem identity；symlink、case collision 或无法 canonicalize 时返回 serial recommendation。
- create/update/delete 的目标路径必须在 scope 内；rename 的 source 和 destination 都必须在同一 child scope 内。
- canonical scope 有任何重叠、任务存在确定先后依赖或 base snapshot 不一致时返回 serial recommendation。
- planner 只能提出只读 proposal；若 planner 本身需要 provider request，必须使用当前明确的 planner consent，并在请求前从 proposal budget 预留，确认后把实际/保留用量并入 aggregate ledger。
- 用户确认 exact plan digest 前，不能创建 child/integration worktree，也不能发送任何 child 或 integration provider request。

### 3. 每个写 Child 都必须独占 Worktree

```ts
type ChildReadinessOutcomeV1 = 'READY' | 'BLOCKED' | 'FAILED';

interface ChildReadinessV1 {
  readonly schemaVersion: 1;
  readonly readinessId: string;
  readonly parentRunId: string;
  readonly planId: string;
  readonly planDigest: string;
  readonly taskId: string;
  readonly taskDigest: string;
  readonly pathScopeDigest: string;
  readonly leaseId: string;
  readonly sourceSnapshotDigest: string;
  readonly materializedSourceDigest: string;
  readonly candidateId: string | null;
  readonly candidateWorkspaceDigest: string | null;
  readonly candidateDeltaDigest: string | null;
  readonly orderedChangeManifestDigest: string | null;
  readonly actualChangedPaths: readonly string[];
  readonly agentDeltaDigest: string | null;
  readonly localEvidenceRefs: readonly string[];
  readonly localEvidenceDigest: string;
  readonly usageLedgerDigest: string;
  readonly outcome: ChildReadinessOutcomeV1;
  readonly reasonCode: string | null;
  readonly resultDigest: string;
}
```

- 只读 research/reviewer 可以共享冻结的 brokered refs；任何写 child 必须使用独立 0.0.21 lease。
- child 只能写自己的 candidate root，不能写 parent、integration 或其他 child worktree。
- child 不能 merge、rebase、push、修改用户 branch 或应用其他 child delta。
- child 只生成 `ChildReadinessV1`，outcome 为 `READY | BLOCKED | FAILED`；禁止使用 `PASS/NEEDS_WORK/ERROR` 等根 Gate 术语。
- `READY` 只证明该 leaf task 的 expected output、path scope、局部 constraints、适用的 scoped checks、risk scan 和 workspace freshness 成立。
- `BLOCKED` 表示局部合同、scope、权限/consent 或确定检查仍有可定位 blocker；`FAILED` 只表示 runtime、provider、worktree 或 evidence 基础设施无法产出可信 readiness。
- child 实际 changed paths 必须是 canonical `pathScope` 的子集；任何 out-of-scope create/edit/delete/rename/mode change 都返回 `BLOCKED/parallel_child_scope_violation`，不能进入 READY。
- `READY` 必须同时固定完整 0.0.21 `CandidateDeltaV1` 的 candidate ID、candidate workspace、ordered change manifest、Agent delta 和 candidate delta digest；任一缺失或不一致都 fail closed。
- child 不运行或伪造 parent full Gate；parent frozen checks、全部 selected criteria 和唯一 fresh reviewer 只在 integration worktree 完整执行。
- `ChildReadinessV1` 必须引用 task、lease、snapshot、changed paths、局部 evidence 和 usage；缺失或 stale 时不是 READY。
- worktree 创建失败或 identity 漂移时，该 required child 失败，不能转为共享 cwd 重试。

0.0.20 reviewer consent 也不能静默扩大：

- Parallel Preflight 必须展示 child 数量、每个 brokered review subject、总输入上限和 exact BYOK provider origin。
- serial run 的 reviewer consent 不能自动授权多个 child worktree。
- child readiness 如果需要 model review，必须使用 plan-confirmed、bounded child consent；P0 可以只使用 deterministic scoped checks 和 risk scan，把唯一 model reviewer留给 integrated Gate。
- 任一 child consent refusal 都保持该 child `not_started`，零 provider connection。

### 4. 并发必须有产品级硬上限

新建 `ParallelLoopScheduler`，不直接暴露 AgentSwarm 的默认行为：

```ts
interface ParallelRunExecutionLeaseV1 {
  readonly schemaVersion: 1;
  readonly parentRunId: string;
  readonly ownerProcessIdentity: string;
  readonly fencingToken: string;
  readonly registryRevision: number;
  readonly lastHeartbeatAt: string;
  readonly state: 'active' | 'cancelling' | 'reconciliation_required' | 'released';
  readonly leaseDigest: string;
}
```

- 每个 parent run 在当前用户私有 run registry 中只有一个 execution lease；acquire/adopt 使用 cross-process lock + CAS，并单调提升 fencing token。
- child spawn、provider request、budget append、integration journal 和 Promote handoff 都必须携带当前 fencing token；旧 owner 不能在新 token 后继续。
- 默认 `concurrencyLimit = 2`。
- 用户允许范围为 1–5。
- hard fan-out 为 5，配置、环境变量、TUI、Headless 和模型 tool call 都不能扩大。
- scheduler 先检查 worktree lease、权限、provider consent 和预算 reservation，再启动 child。
- queued child 在获得 capacity 前不能建立 provider connection 或执行工具。
- rate limit 只能降低有效并发，不能提高 hard cap。
- 并行过程中需要新权限时，child 进入 `waiting_permission`，暂停新 spawn，并在当前前台 Loop 显示一个明确 attention item。

### 5. 整个 Loop Tree 共享一个硬预算

```ts

}

  readonly budgetId: string;

  readonly eventId: string;

  readonly eventDigest: string;

```

预算覆盖：

- 拆分 proposal/planner；
- parent writer/coordinator；
- 每个 child 的全部 turns、tools 和 retry；
- read-only reviewer/security specialist；
- integration；
- child readiness、integrated candidate Gate、fresh reviewer、Promote 和 target final Gate；
- provider fallback、rate-limit retry 和 usage reconciliation。

不变量：

- parent、child、reviewer、integration 和 final Gate 每开始一个新的 agent turn/Loop iteration 前，都必须在同一 ledger 中以 CAS 预留 `iterations: 1`；没有成功 reservation 就不能开始该 turn。retry、fallback 和 crash 后重新开始的 turn 都计入，已开始的 iteration 不因中止或 adoption 退回。
- 每个 provider request 在发送前预留“保守 input estimate + request max output tokens + safety margin”；所有 in-flight reservation 都立即计入已占用预算。
- reservation 必须在同一 budget ledger 上以 CAS check-and-reserve、append、flush/fsync 完成后才能 spawn/connect；actor/request/idempotency 相同的重试只能返回原 reservation。
- 只有 provider 返回可验证 actual usage 时才能释放未使用 reservation；usage 缺失、异常终止或响应不可解析时保留全部 reservation，不能按 0 处理。
- provider request ceiling/safety margin 和 tokenizer policy 版本化并进入 budget digest；provider 超出声明上限时停止新请求并返回 accounting error。
- spawn 前同时原子预留 child 最小执行预算；预留失败则 child 保持 `not_started`。
- ledger event 绑定 execution fencing token、monotonic revision 和 previous-event digest；crash/adopt 时未知 active reservation 先转 `retained_unknown`，完成 request/process reconciliation 前不可释放。
- child 无权提高、重置或借用 final Gate reserve。
- 预算耗尽后不再启动 queued child，并请求取消当前 run 所有 attached descendants；到 safe checkpoint 前保持 cancelling，不能宣称立即停止。
- 本地“硬预算”指没有未预留的请求可以发出；实际 provider billing 与 tokenizer 误差只在已冻结 safety margin/request ceiling 内，无法证明精确账单相等。
- parent terminal 显示本地总 usage 和未完成任务，不上传 telemetry。
- user-facing limit 是本机 BYOK 安全上限，不是账号 quota 或付费 entitlement。

### 6. 部分失败不能显示 Completed

每个 child 使用：

```text
queued
running
waiting_permission
checking_readiness
ready
blocked
failed
aborted
not_started
lost
```

聚合规则：

- readiness 与 lifecycle 唯一映射为 `READY → ready`、`BLOCKED → blocked`、`FAILED → failed`；其他 lifecycle state 不得伪造 readiness outcome。
- 只有全部 required child `ready` 才能进入 integration。
- 任一 `blocked/failed/aborted/not_started/lost` 都产生 active parent blocker；是否继续、取消或形成 terminal 只由 0.0.19 run policy 决定。
- Swarm-style “有结果文本就算 tool success” 不适用于 Parallel Loop。
- TUI 不得把部分失败渲染成 overall `Completed`。
- retry/resume 必须由同一 task ID、contract、snapshot 和 lease lineage 显式触发。

- integration 使用独立 worktree，并严格复用 0.0.21 的 exact source snapshot materialization；其起点必须等于 `baseMaterializedSourceDigest`。

- child delta 按 `integrationOrder` 串行应用。
- 一个 child delta 可包含多文件，不能当作 crash-atomic 单写。每步先向 append-only journal 写入并 fsync `apply_prepared`，冻结 child manifest 与 expected pre/post tree；完整应用该 immutable change manifest 后才追加 `apply_observed`。
- owner/crash 若发生在 prepared 与 observed 之间，禁止在该 partial integration worktree 继续：当前 attempt 标记 abandoned，保留/安全清理 owned worktree；新 owner 使用新 attempt ID、lease 和 fencing token，从 exact immutable base 物化新 worktree，并按原 integration order 从头确定重建。该重放只发生在新 owned integration worktree，不重发 provider request、不修改 parent/target。
- journal 每个 event 都绑定 current execution fencing token、monotonic sequence 与 `previousEventDigest`，append 后 flush/fsync 才可执行下一步；旧 owner、截断、重排或 digest 不一致 fail closed。
- integrated Gate attempt 必须作为最后 journal event 绑定；最终 `IntegrationRecordV1` 必须引用同一 attempt 的 `journalId + finalJournalHeadDigest + executionFencingToken`。任一不一致时禁止进入 Promote。
- changed-path、rename/delete、mode 或 hunk 冲突立即停止。
- P0 不让模型自动解冲突；冲突只返回 blocker 和可恢复 worktree。
- 无文本冲突不代表语义正确；集成后仍必须跑完整 Gate 和 fresh reviewer。
- 任一 child delta/readiness stale、缺失、重复或 digest 不一致时停止。
- 集成结果只是 0.0.21 candidate；仍须 Promote 和目标 workspace final Gate。

### 8. Cancel、Restart 和 Resume 必须幂等

- 每个 child/check 由本版本的 lifecycle containment 启动：Unix 使用独立 process group/session，Windows 使用 Job Object；这是取消/回收机制，不是 filesystem/network sandbox。
- parent cancel 取消 queued child，并向所有 running child 和已知 process tree 传播终止。
- 已知 process tree 必须在有界 timeout 内退出并经过 worktree/usage revalidation；无法确认时进入 `cancellation_reconciliation_required`，不能显示已完全停止。
- 外部脚本主动 daemonize、脱离已知 process group 或写其他系统路径仍可能逃逸；文档不承诺任意 OS 进程零 orphan，只保证不再启动新工作并检测已覆盖 workspace 的漂移。
- P0 不支持 detached child；离开父 Loop 不能让 child 偷偷继续。
- restart 后 running child 进入 `lost/recoverable`，不能自动重放 provider request。
- Resume 复用 exact task、lease、budget ledger 和 contract；状态不匹配则要求重新计划。
- 同一 child、provider request、integration attempt/step 和 Promote 都有幂等键；未知 partial delta 不在原 worktree重放，只能新建 attempt 从 immutable base 重建。
- 失败 worktree 默认保留；清理沿用 0.0.21 ownership 规则。

## 状态机

```text
serial_loop
  → parallel_proposal
  → plan_confirmed
  → children_queued
  → children_running
  → children_ready
  → integrating
  → integrated_verifying
  → awaiting_promotion
  → target_final_verifying
  → PASS | NEEDS_WORK | ERROR
```

异常分支描述 active phase/control handling，不自行创建 terminal：

```text
dependency/scope overlap → serial recommendation
child failure/lost       → active blocker / attention
budget exhausted         → stop spawn / cancelling / attention
integration conflict     → attention
corrupt lineage          → fail closed
```

## 稳定 reason codes

reason code 描述 preflight、child、integration 或 control 事件，本身不创建 terminal/continuation：

| Reason code | 默认处理 | 含义 |
|---|---|---|
| `parallel_plan_not_independent` | serial recommendation | 任务存在确定依赖或明显 scope 重叠 |
| `parallel_plan_changed` | re-confirm plan | proposal 与确认 digest 不一致 |
| `parallel_fanout_exceeded` | reject proposal | 任务数量或并发超过硬上限 |
| `parallel_execution_fencing_lost` | fail closed / attention | parent run 已被新的 execution owner 采用，旧 owner 失效 |
| `parallel_budget_reservation_failed` | block spawn | 无足够预算启动或完成 final Gate |
| `parallel_budget_exhausted` | cancelling + attention | 总预算已耗尽 |
| `parallel_budget_accounting_error` | fail closed | provider usage 超出或无法满足 reservation contract |
| `parallel_child_scope_violation` | child BLOCKED | child 修改超出冻结 path scope |
| `parallel_child_failed` | active blocker | required child 失败 |
| `parallel_child_lost` | paused / explicit resume | required child 状态丢失 |
| `parallel_child_lineage_invalid` | fail closed | child contract/snapshot/lease 引用不一致 |
| `parallel_integration_conflict` | attention | 确定集成冲突 |
| `parallel_integration_stale` | attention / replan | base 或 child delta 已漂移 |
| `parallel_integration_rebuild_required` | paused / fenced rebuild | 旧 integration attempt 在多文件 delta 中途失去 owner，必须用新 worktree 重建 |
| `parallel_integrated_gate_failed` | continue or terminal by 0.0.19 policy | 集成 worktree 未通过完整 Gate |
| `parallel_cancellation_reconciliation_required` | attention | 已知 process tree 或副作用状态无法确认 |
| `parallel_cancelled` | cancel lifecycle | 只有底层 cancel terminal record 才结束 run |

- read-only review 或 security specialist worker。

## 自动化测试

### Scheduler / budget

- 默认并发 2 和 hard fan-out 5 在所有入口真实生效。
- 两个进程竞争同一 parent run 时只有一个 execution fencing token 能 spawn/append；旧 owner 全部动作被拒绝。
- queued child 不提前连接 provider 或执行工具。
- parent budget 精确包含 child、retry、reviewer、integration 和 final Gate。
- 每个 request 预留 conservative input + max output + safety margin；usage 缺失保留全部 reservation。
- budget ledger 的 CAS revision、previous-event chain、idempotent reservation、fsync fault、crash adopt 和 retained-unknown fixtures。
- 两个 child 同时申请下一 iteration 时，CAS reservation 不能突破 `iterationLimit`；crash 时已开始或状态未知的 iteration reservation 保留为 consumed/`retained_unknown`，不能退回后再次使用。
- rate limit、fallback、retry、provider 超限和 tokenizer drift 都有固定 accounting fixture。
- token/time/tool/iteration 到期立即阻止 queued/new request，并把 running 置为 cancelling；只有 known process/request reconcile 后才显示停止。
- final Gate reserve 不能被 child 消耗。

### Worktree / integration

- 每个 mutating child 获得唯一 cwd、branch、lease 和 snapshot。
- exact/prefix scope 的 Unicode/case normalization、prefix overlap、rename 双端、symlink/case collision 与跨平台 golden fixtures。
- 两个 child 同时修改同一文件时不直接写 parent workspace。
- 无冲突 delta 按冻结顺序集成。
- multi-file child delta 在中间 crash 时旧 attempt fenced/abandoned；新 attempt 从 immutable base 全量重建，旧 partial tree 不继续。
- final integration record 与 exact journal ID/head、Gate ref 和 execution fencing token 绑定；截断、重排、跨 attempt ref 均 fail closed。
- same-file、same-hunk、rename/delete 和 mode conflict 停止且保留 worktree。
- child create/edit/delete/rename/mode change 超出 frozen path scope 时返回 `parallel_child_scope_violation`，不能 READY。
- 任一 required child 未 READY 时禁止 integration。
- 集成后 seeded semantic blocker 必须被 frozen checks 或 reviewer 阻断；false PASS 为 0。

### Lifecycle

- Unix process group/session 与 Windows Job Object 能级联终止已知 child/check process tree。
- 无法在 timeout 内确认终止时进入 cancellation reconciliation；不宣称任意 daemonized 外部进程已消失。
- crash/restart 不重复 provider request、child 或 Promote；partial integration attempt 被 fenced/abandoned，只能在新 owned worktree 从 immutable base 确定重建。
- lost child 只有显式 Resume/Retry 才运行。
- corrupt、duplicate、cross-run child refs fail closed。
- permission wait 暂停新 spawn，拒绝后不会扩大 child 权限。

### TUI / E2E

- 展示 queued/running/waiting_permission/checking_readiness/ready/blocked/integrating/verifying/failed/aborted/not_started/lost。
- 部分失败不显示 overall Completed。
- 显示 child usage 和全局预算余量，不显示 prompt/secret。
- 真实 fixture repo 覆盖并行成功、冲突、超预算、取消和恢复。

## 四类发布门槛

1. **自动化**：plan、scheduler、budget、worktree、integration、cancel/restart 和负向测试全部通过。
2. **真实流程**：至少 3 个真实仓库、10 个可拆分任务完成 dogfood；任务必须包含跨 package 修改、测试补齐和局部重构。
3. **跨平台**：macOS/Linux/Windows 并行 worktree E2E、六平台 fresh install 和 0.1.0 → 0.2.0-rc upgrade 通过。
4. **用户验收**：固定 5 名目标用户中，5/5 能区分 child READY、integrated candidate 和 root PASS，4/5 能理解预算与冲突下一步；没有用户把 worker 数量当成完成质量。

额外硬门槛：

- 任何入口都不能超过 hard fan-out 5。
- 任一 required child 未 READY 都不能进入 integration 或 terminal PASS。
- injected conflict 不能静默覆盖。
- 对内置写工具，parent workspace 在 Promote 前保持不变；shell 路径复用 0.0.21 fingerprint revalidation，不宣传完整 containment。
- 正常、retry、usage 缺失和取消路径都不能突破总预算。

## 明确不做

- 递归 Agent Tree、动态 workflow graph 或 100/1,000-agent 叙事。
- 默认或公开 128 个 worker。
- detached/background multi-session supervisor；归同一 0.2.0 的 Supervisor Phase。
- child 自动 merge/rebase/push 或修改用户 branch。
- 自动冲突修复。
- 完整 OS/process/network sandbox 或 Runtime Security。
- command recipe、Skill chaining、workflow DSL 或自动 Skill 修改。
- 云端 Routines、Remote Control、Claude Tag 类常驻 Agent。
- Hosted Terminal、Team、BYOK/token quota 或 telemetry 后端；PR Gate 与 Billing 只按 0.2.0 主规格评审，不属于本组件技术合同。
- 新的默认 `/batch`、`/parallel` 或 `/agents` 顶层命令。

## 实施顺序

1. 实现只读 Parallel Plan proposal 与 serial fallback。
2. 实现 parent run execution fencing lease，再接入 0.0.21 child lease，先固定 concurrency=1。
3. 实现 append-only aggregate budget ledger 和 reservation。
4. 把 concurrency 提升到默认 2、hard 5。
5. 实现严格 child result 与 parent cancel。
6. 实现 integration attempt/worktree、fenced journal、immutable-base rebuild、冻结顺序和冲突阻断。
7. 接入 integrated Gate、Promote 和 target final Gate。
8. 补全 crash/restart、TUI/Headless、跨平台和真实项目 E2E。
9. 四类发布门槛完成后，才允许启用同一 0.2.0 的 Supervisor Phase。

## 完成定义

0.2.0 Bounded Parallel Loop 组件只有在以下条件全部成立时才算实现：

1. 父 Loop 只运行 2–5 个已确认、扁平、required leaf tasks。
2. 每个写 child 使用独占 0.0.21 worktree。
3. 默认并发与 hard fan-out 在所有入口不可绕过。
4. 整个 Loop Tree 的 token/time/iteration/tool usage 受同一硬预算控制。
5. 部分失败、lost 或预算耗尽不能显示 Completed 或 PASS。
6. child 不能集成、merge、push 或修改用户 workspace。
7. 集成顺序确定，冲突不会静默覆盖。
8. parent execution fencing、budget event chain 与 final integration record/journal binding 能阻止 stale owner、截断 journal 和重复 spawn。
9. partial multi-file integration 只在新 owned worktree 从 immutable base 重建，不能在未知 tree 续写；只有 integrated candidate + Promote + target final Gate 可以 PASS。
10. cancel/restart 不启动新工作或重复外部副作用；已知 process tree 有确定终止/reconciliation，未知外部进程不会被谎报为已停止。
11. 没有云端依赖、telemetry、默认新命令或 Agent 数量承诺；Pro admission 与 Billing 只使用主规格的统一 entitlement，不在本组件另造 quota。
