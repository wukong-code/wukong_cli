# 0.0.18 Loop-First Simplification

> Internal engineering record — kept in Chinese. English product docs: the user guide and release notes.

> 状态：已于 2026-07-22 发布。
> 目标版本：0.0.18。
> 产品边界：继续 Free、local-first，本地 Loop 不受账号或月度 quota 限制；同时保留 BYOK provider，并完成 Wukong 网站确认登录与可为空的模型目录基础。0.0.18 不提供 Wukong 托管模型或推理，不引入支付、Hosted Terminal、云同步或 Web/D1 telemetry 指标后端。

## 为什么需要 0.0.18

0.0.17 已经修复了误导命令、未知 slash 进入模型、远程 Loop quota 和 reviewer 失控等可靠性问题，但产品入口仍然过多：

- TUI registry 仍有 40 多个内置 slash command，普通用户难以判断哪些是主流程、内部检查或通用工具。
- `/goal` 与 `/loop` 暴露两套相近的自主执行入口；Loop 内部虽然复用 Goal engine，用户却仍会看到 `/goal resume` 等内部语义。
- `/verify`、`/scan`、`/proof` 已隐藏，但 `/judge`、`/guard`、`/review` 等 Loop 内层能力仍与主命令并列。
- `/auto`、`/yolo` 与 `/permission` 重复；`/login` 是需要保留的正式能力，但 0.0.17 Web 发布时删除了 CLI 仍依赖的 `/api/v1/models`，导致网站确认成功后模型目录刷新返回 HTTP 404。
- Cross-Agent Resume 只覆盖 Codex、Claude Code 和 Cursor，尚未覆盖本机已经存在明确会话存储的 Kimi Code 与 Grok。
- `/feedback` 当前依赖 `managed:wukong` 登录，还可以上传 session、日志和代码库 ZIP；Web 却没有接收 API，并且附件行为与“不会上传源码或本地 evidence”的隐私边界冲突。
- CLI、Web 和公开仓库仍有少量发布后文档把 0.0.17 写成“下一个版本”，版本真相源需要再次收口。

0.0.18 不增加新的 Agent 引擎。它只做一件事：**让 Resume 负责接续任务，让 Loop 负责自主交付，让其他能力退回 Loop 内部或高级工具层。**

## 版本目标

1. 用户只需理解 `Resume → Loop → Gate`，普通 help、补全、welcome 和错误提示使用同一套主流程。
2. `/loop` 成为默认命令面唯一突出的多轮自主交付入口；Goal 和其他现有命令实现继续保留并可直接调用，只是不再与 Loop 并列展示。
3. `/resume` 增加 Kimi Code 与 Grok，只读导入本地上下文后重新检查当前 workspace，再进入 Wukong 或创建可编辑 Loop。
4. `/feedback` 改为无需登录、用户主动确认的纯文本反馈；Web 提供最小接收 API，绝不自动附加源码、prompt、日志或本地 evidence。
5. 完成 Wukong 账号链路：CLI 发起 device login、用户在网站确认、CLI 获取和刷新 token、读取允许为空的 model catalog，并支持 logout；当前没有 Wukong 模型，不伪造 placeholder，也不在 0.0.18 实现托管推理。
6. 用命令契约、跨 Agent fixture、隐私负向测试和真实发布 smoke 锁住新的精简边界。

## 命令信息架构

### 默认可见：核心入口

默认 `/help` 和 slash autocomplete 只突出以下入口：

| 命令 | 作用 | 0.0.18 决策 |
|---|---|---|
| `/loop <goal>` | 持续写、检查、审查和修复，直到 Gate 终态 | 默认命令面唯一突出的自主交付入口 |
| `/loop status\|pause\|resume\|stop` | 管理当前 Loop | 取代用户可见的 Goal lifecycle |
| `/resume [source]` | 恢复 Wukong 或外部 Agent 的本地任务 | 增加 `kimi`、`grok` |
| `/new` | 在当前 workspace 开始新会话 | 保留 |
| `/provider` | 配置 BYOK provider 和 API Key | BYOK 模型配置入口 |
| `/model` | 在已配置模型间切换 | 保留快捷入口 |
| `/login` | 发起 device flow，并在 Wukong 网站确认账号连接 | 正式保留并可发现；模型列表允许为空 |
| `/logout` | 断开 Wukong 账号并清理 token | 与 login 成对保留，不影响 BYOK provider |
| `/permission` | 选择 Manual / Auto / YOLO | TUI permission 唯一入口 |
| `/settings` | 打开设置 | 保留 |
| `/transform` | 切换实验性 Role Profile | 按既有产品决定保留并可发现 |
| `/feedback` | 主动提交文本反馈 | 接入新的 Web API |
| `/help` | 显示核心或高级命令 | 增加分层帮助 |
| `/exit` | 退出 | 保留 |

`/transform` 在未启用 `experimental.role_profiles` 时仍显示明确的 `/experiments` 指引，不进入模型。

### 高级可见：Loop 内层与工具

以下能力保留实现，但不与核心入口竞争。它们只出现在 `/help advanced`，不出现在默认 welcome 或首屏 autocomplete：

- Loop 内部诊断：`/verify`、`/scan`、`/proof`、`/judge`、`/guard`。
- 本地 reviewer 配置：`/review`。其中 `review feedback` 是 finding 的本地分类，不是向 Wukong Web 提交产品反馈。
- 工作区与运行工具：`/plan`、`/tasks`、`/mcp`、`/plugins`、`/add-dir`、`/experiments`、`/reload`、`/reload-tui`。
- 会话工具：`/compact`、`/init`、`/fork`、`/title`、`/usage`、`/status`、`/undo`。
- 本地 UI 与导出：`/editor`、`/theme`、`/export-md`、`/export`、`/web`。
- 并行能力：`/swarm`、`/btw`。它们不作为产品主叙事；是否保留公开实验入口由自动化和真实用户路径决定。

`/web` 只代表本机 daemon 和本地 Web UI，不得重新描述成 Hosted Terminal。若 0.0.18 发布前无法通过真实 Loop/session parity E2E，则从默认和 advanced help 一并隐藏，但不以此恢复任何托管终端。

### 从默认命令面隐藏的入口

本版本对命令采用 **hide, do not delete**：保留 handler、CLI/TUI dispatch、配置、持久化兼容和直接调用能力，只从 welcome、默认 `/help` 和首屏 autocomplete 隐藏。`/help advanced` 可以继续发现这些能力。除 feedback 附件上传这一明确隐私冲突外，不因为命令面精简删除底层实现。

| 旧入口 | 0.0.18 行为 | 替代 |
|---|---|---|
| `/goal ...` | 默认隐藏，继续可直接调用和作为 Loop 内核 | 普通用户优先使用 `/loop ...`、`/loop status\|pause\|resume\|stop` |
| `/auto`、`/yolo` | 默认隐藏，继续可直接调用 | 普通用户优先使用 `/permission` |
| `/sessions` | 0.0.18 仅保留不可见兼容 alias | `/resume` |
| `/resume-codex` 等隐藏命令 | 继续保留隐藏兼容入口；不再为每个来源扩张默认 registry | `/resume codex|claude|cursor|kimi|grok` |
| `/export-debug-zip` | 实现保留，内部名称默认隐藏 | `/export` |

全局 CLI 的 `--auto`、`--yolo` 继续作为明确的 headless permission flags；本节只收口 TUI 中重复的 slash 入口。

## P0：Loop 成为唯一自主交付入口

- Goal engine、queue、verification gate 和持久化继续作为 Loop 内部机制，不重写执行核。
- 默认 UI 删除 `/goal resume`、`goal active` 和“Goal 与 Loop 二选一”文案；`/goal` 实现、直接调用和旧记录兼容继续保留。
- paused、active、blocked、terminal 的下一步只指向 `/loop status|pause|resume|stop`。
- 普通自然语言仍是单轮对话，不根据文本猜测是否自动启动 Loop；需要持续改代码时由用户显式运行 `/loop`。
- Cross-Agent handoff 中 `Start /loop` 为主选项，但目标必须可编辑，用户确认前不得执行。
- CLI/TUI 的正式语法只宣传：

  ```text
  /loop [--max-iterations N] [--every 5m] [--review-model alias] <goal>
  wukong loop "<goal>" [--max-iterations N] [--every 5m] [--review-model alias]
  ```

- Loop 固定使用统一 proof gate；`--until` 不再进入 help。旧值和旧持久化 record 只做读取兼容，不能继续形成四套公开停止条件。
- writer、checks、fresh reviewer、anti-ratchet、stall strategist、取消、超时、max-iterations 和 PASS / NEEDS_WORK / ERROR 契约继续作为不可回退的发布基线。
- Loop 失败只显示稳定 Reason + Next；内部 verify/scan/reviewer 细节留在 transcript 和高级诊断。

## P0：Cross-Agent Resume 增加 Kimi Code 与 Grok

### 统一入口

```text
/resume
/resume codex
/resume claude
/resume cursor
/resume kimi
/resume grok
```

- 裸 `/resume` 仍先显示 Wukong 本地会话。
- 来源补全、session picker、来源标签、welcome suggestion、handoff 和只读 import skill 同步支持 `kimi`、`grok`。
- 不新增 `/resume-kimi`、`/resume-grok` 公开命令；来源只通过 `/resume <source>` 扩展。

### Kimi Code

当前本机格式已经确认：

- 索引：`~/.kimi-code/session_index.jsonl`，包含 `sessionId`、`sessionDir`、`workDir`。
- 元数据：`~/.kimi-code/sessions/<workspace>/<session>/state.json`，包含 title 和更新时间。
- 用户输入：`~/.kimi-code/user-history/<sessionId>.jsonl`。

实现要求：

- 优先读取 `.kimi-code` 新格式；只有新目录不存在时才考虑 `.kimi` legacy fallback，避免迁移后的重复 session。
- 若本地格式只提供用户历史而没有完整 assistant transcript，UI 必须明确显示“恢复最后请求”，不能虚构已导入完整对话。
- 从 last user request 生成可编辑 Loop draft；进入 Loop 后重新读取 workspace、Git 和项目检查。
- 解析损坏行时隔离单条/单 session，不能让整个 picker 失败。

### Grok

当前本机格式已经确认：

- 搜索索引：`~/.grok/sessions/session_search.sqlite`，包含 session id、cwd、title、updated time。
- session 元数据：`~/.grok/sessions/<encoded-workdir>/<session-id>/summary.json`。
- 对话：同一目录的 `chat_history.jsonl`；其他文件包括 events、terminal logs、system prompt 和运行状态。

实现要求：

- 用只读 SQLite 连接或有界目录扫描发现 session；数据库锁定、缺失或损坏时安全回退，不修改 Grok 数据库。
- 只读取 title、cwd、更新时间以及 user/assistant conversation；禁止读取或导入 `auth.json`、`system_prompt.txt`、terminal logs、memtrace、hidden reasoning、approvals 和工具原始输出。
- 正确解码 workspace 目录，并在 realpath 后校验仍位于 `~/.grok/sessions/` 内。
- `chat_format_version` 不支持时跳过该 session 并给出本地说明，不猜测字段。

### 所有来源共同安全边界

- 只读导入，不重放旧 tool call、permission、测试结论或外部 Agent 的系统指令。
- source path 必须经过 realpath、root containment 和 symlink escape 校验。
- discovery 默认有文件数、单行大小、head/tail 读取和最近时间窗口上限。
- picker 只显示最小摘要；source path、完整 prompt 和 transcript 不上传、不写 telemetry。
- 进入 Wukong 后重新核对当前 workspace、Git 状态和检查结果。
- fixture 必须脱敏，不能把开发者真实 `~/.kimi-code` 或 `~/.grok` 会话提交进仓库。

## P0：网站确认 Login 与模型目录基础

### 已确认的 0.0.17 故障

- CLI OAuth host 是 `https://wukong.today`，device authorization、网站确认页和 token endpoint 当前存在。
- 正式登录交互应由 CLI 申请 device code、打开或提示 `wukong.today` 确认地址，用户在网站用 Google/GitHub 账号批准；CLI 只轮询 token，不在终端收集账号密码。
- CLI API base URL 是 `https://wukong.today/api/v1`；登录取得 token 后调用 `GET /api/v1/models` 获取当前模型目录，目录允许为空。
- 0.0.17 Web 发布提交删除了 `/api/v1/models`，所以有效 token 也会得到 404。
- 当前 `/api/v1/usages` 能接受同一 token，证明故障不在账号 token 验证。
- 当前 Wukong 尚未提供模型，因此没有 `POST /api/v1/chat/completions` 是本阶段的产品边界，不是 0.0.18 的缺陷。CLI 不得把空目录包装成可选择的 `managed:wukong` 模型。
- 将 `Failed to list Wukong models (HTTP 404)` 归类为“expected skip”只能消除提示，不能修复连接，因此不得作为最终方案。

### 服务端 contract

- `POST /api/oauth/device_authorization`：创建短期 device code。
- `/auth/device`：用户在 Wukong 网站完成 Google/GitHub 账号确认并批准或拒绝；严格校验 device code、过期时间和站内 callback，拒绝外站回跳。
- `POST /api/oauth/token`：device-code exchange 与 refresh-token rotation。
- `GET /api/v1/models`：验证 CLI access token。当前固定返回 `200 {"data":[]}`；缺失、无效或过期 token 返回稳定 `401`，不能返回 404，不能返回 placeholder。
- `GET /api/v1/usages`：返回真实 provider usage；当前没有配额时返回 `usage: null, limits: []`，不能虚构 Guest/Free allowance。
- 0.0.18 不新增或宣传 `POST /api/v1/chat/completions`、Messages API 或其他托管推理 endpoint。

未来接入最新模型时，只有 catalog、真实推理、流式 tool call、错误路径、成本归属和隐私声明全部就绪，模型才可以出现在生产目录。目录 schema 保持向前兼容，使 CLI 无需为每次增加模型重新发版；在那之前生产目录必须诚实为空。

### CLI 行为

- `/login`、`wukong login` 保持可发现：显示网站确认 URL 与 user code，尽力打开默认浏览器，在用户完成网站确认后轮询 token；取消、拒绝、过期和网络失败必须说明具体阶段。
- 网站确认和 token 保存成功即代表登录成功，不能因为 `data: []` 抛出 “No models available” 或回滚 token。
- 空目录时不得创建模型 alias、不得把 `managed:wukong` 设为默认模型、不得覆盖用户现有 BYOK provider/default；UI 显示“Wukong 账号已连接，当前还没有可用的 Wukong 模型，请继续通过 `/provider` 使用 BYOK 模型”。
- `/logout` 清理 Wukong token、账号状态和已存在的 managed provider/default alias，但不得删除其他 BYOK providers。
- 启动和 `/model` 可以刷新已登录的 catalog；`200 data: []` 是正常空状态，404/5xx 是 contract/service failure，必须有界提示且不删除未来可能存在的 last-known-good catalog。
- token 缺失才安静跳过可选 refresh；有效 token + endpoint 404 是服务端 contract regression。
- `/usage`、`/status` 展示账号连接状态与真实 managed usage；`null`/空 limits 表示当前无托管用量或配额，不伪装成免费额度。
- `/feedback` 与账号、当前 model/provider 继续解耦，未登录用户也可以主动提交反馈。

### 隐私边界

- BYOK provider：模型请求直接发送给用户配置的第三方 provider。
- 0.0.18 只有网站账号确认、token、空模型目录和 usage/status；不存在 Wukong 托管推理，因此不会通过 `managed:wukong` 向 Wukong 发送 prompt、response、tool arguments 或源码。
- 未来开放托管模型前，必须先更新 Privacy、首次选择提示、日志保留和上游数据政策，并完成独立验收；不能用本规划预先获得授权。

## P1：Web Feedback API

### API contract

新增：

```http
POST /api/v1/feedback
Content-Type: application/json
Idempotency-Key: <submission-uuid>
```

请求只允许以下字段：

```json
{
  "message": "Loop 在验证阶段重复执行",
  "category": "bug",
  "version": "0.0.18",
  "platform": "darwin",
  "arch": "arm64",
  "loop_outcome": "NEEDS_WORK",
  "reason_code": "verification_repeated",
  "contact": "optional@example.com"
}
```

字段规则：

- `message` 必填，trim 后 1–4096 字符。
- `category` 只允许 `bug|onboarding|loop_result|feature_request|other`。
- `version`、`platform`、`arch` 使用受控格式；不发送完整 OS release 或机器信息。
- `loop_outcome` 只允许 `PASS|NEEDS_WORK|ERROR|null`。
- `reason_code` 只能是稳定低基数 code，不能放错误堆栈、命令或路径。
- `contact` 可选，最多 320 字符；不要求账号。
- `Idempotency-Key` 是每次显式提交新生成的 UUID，只用于避免网络重试产生重复反馈，不得复用为 install/device 标识。
- 拒绝未知字段、multipart、压缩包和超过 8 KiB 的请求体。

成功响应：

```json
{
  "feedback_id": "fb_xxx",
  "status": "received"
}
```

稳定错误：`400` 校验失败、`413` 过大、`429` 限流、`503` 存储不可用。

### D1 与运营边界

- 新增独立 `feedback` 表：`id`、唯一 `idempotency_key`、`category`、`message`、`version`、`platform`、`arch`、`loop_outcome`、`reason_code`、可选 `contact`、`status`、`created_at`、`retention_until`。
- `status` 只允许 `new|triaged|closed`；0.0.18 不建设公开反馈 Dashboard。
- 默认保留 90 天；发布前必须提供可验证的 purge job 或受控运维清理命令，不能只写 `retention_until` 而从不删除。
- Cloudflare edge 做请求频率限制；D1 不保存原始 IP、设备指纹或匿名 install id。
- handler、日志和错误上报不得记录 `message`、`contact` 或完整请求体。
- feedback 是用户主动提交的数据，不是 telemetry，不写 product-metrics 表，也不触发额外 `feedback_submitted` 事件。

### CLI UX 与隐私

- `/feedback` 在任何 BYOK provider 下都可使用，不要求 `managed:wukong` 或 Wukong 登录。
- 先收集 category 和文本，再显示将发送的精确字段，最后要求 Submit / Cancel。
- 确认区必须明确：`No files, logs, source code, prompts, or local evidence are attached automatically.`
- 删除 `logs`、`logs+codebase`、session archive、presigned upload 和 upload-complete 全部路径。
- 不发送 session id、model alias、provider、完整 OS version、任意 `info` map、objective、prompt、transcript、diff、路径或 API Key。
- 用户手动输入的文本可能包含其主动选择分享的代码片段；UI 应提醒不要粘贴 secret，但不能声称服务端从不接收用户主动输入的代码。
- `WUKONG_TELEMETRY=0` 不阻止用户主动 `/feedback`；提交仍必须每次显式确认和可取消。
- API 失败时显示本地错误，并提供 GitHub Issue URL；不能因为 fallback 自动打开浏览器后又提交一次。

## P1：Web 与 legacy API 收口

- `/api/v1/loops/start`、`/complete`、`/usages` 已不再被 0.0.17+ CLI 使用。0.0.18 保留其旧客户端兼容实现，但从当前文档和新客户端路径隐藏，明确标为 legacy，且不得限制当前 Loop。
- Web 首页、下载、Dashboard、Privacy、Terms、Status、Guide 和 Changelog 应准确区分 BYOK 与可选 Wukong 账号；账号不能限制本地 BYOK Loop，当前模型目录为空，不能暗示已经提供 `managed:wukong` 模型或推理。
- Privacy 改为“Wukong 不会自动上传源码或本地 evidence；只有用户明确确认的 feedback 文本会发送到 Wukong Web”。
- 不恢复 Hosted Terminal、Hosted Report、公开 session、云同步或 feedback 附件上传。
- 0.0.18 规划与已实现状态严格分开；未发布前不把 Kimi/Grok Resume 或 Feedback API 写成 live。

|---|---|
| Registry | 核心/advanced/hidden 三层、alias 不重复显示、`/transform` 实验可发现 |
| Resolve | 默认隐藏的 `/goal`、`/auto`、`/yolo` 仍能直接调用；`/login`、`/logout` 可发现且不会因为状态错误进入模型 |
| Dispatch | `/permission` 唯一 TUI permission 入口；Loop lifecycle 不泄露 Goal 文案 |
| CLI | 核心 top-level help 精简；advanced 命令仍可直接运行；legacy flags/records 兼容 |

### Resume

- Kimi Code：index/state/user-history fixture、迁移后 `.kimi` 去重、损坏 JSONL、缺失 assistant transcript、移动 workspace、symlink escape、超大历史和格式变化。
- Grok：SQLite discovery、DB locked/corrupt fallback、encoded workdir、summary/chat version、损坏 JSONL、禁止读取敏感文件、symlink escape 和超大 session。
- 五个外部来源都覆盖 picker → read-only handoff → editable Loop draft → workspace re-check。
- welcome suggestion 仍限制当前 workspace、最近 30 天、每来源最多 50 条，并可关闭。

### Feedback

- Web contract：成功、未知字段、enum、长度、8 KiB body、JSON only、D1 failure、idempotency、rate limit 和 purge。
- CLI：取消、预览、确认、最小 payload、429/503、GitHub fallback，以及任何 provider/未登录状态均可提交。
- 隐私负向断言：不创建 ZIP、不读日志/代码库、不调用 upload endpoints、不发送 session/model/path/prompt，不产生 telemetry event。
- API 与 CLI 使用共享 versioned schema 或 contract fixture，避免字段漂移。

### Managed login/model

- OAuth：device request、网站打开/手动 URL、pending、approve、deny、expire、token exchange、refresh rotation、invalid/revoked token 和 logout；断言 CLI 不接收账号密码。
- Catalog：missing/invalid/expired token、`200 {data: []}`、未来单模型 schema fixture、404/5xx 不静默、last-known-good 不被破坏。
- 空目录客户端：登录仍成功、token 保留、不创建 alias、不改变 BYOK default、启动刷新不报错、`/model` 显示明确空状态。
- 真实 E2E：CLI 发起 login → 网站确认 → token → models 200 空目录 → 账号已连接/BYOK 不变 → usage/status → logout → re-login。
