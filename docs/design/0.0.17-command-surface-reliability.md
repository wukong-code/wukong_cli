# 0.0.17 Command Surface Reliability

> 状态：已于 2026-07-22 正式发布；真实 TUI smoke、全量质量检查、六平台资产、升级/fresh install、三仓发布面与 production Web 验收均通过。
> 产品边界：继续免费、BYOK、local-first；不引入支付、PR 写入或新的托管能力。

## 为什么需要 0.0.17

0.0.16 已经完成 Loop Convergence，但 CLI 与 TUI 的命令面仍存在一组会直接损害信任的问题：

- `--role` 看似是可用的运行参数，却没有可发现的合法值，也与 TUI 的 Role Profile 入口重复。
- TUI 中 `/role`、`/report` 等入口与真实产品能力或当前命令契约不一致。
- `/transform` 是保留的实验入口，但未启用实验时如果完全隐藏，用户无法知道如何开启，也无法发现 `list`、`status`、`off` 和可用 Role。
- 未知或已禁用的 slash command 可能被当作普通 prompt 交给模型，导致模型虚构命令行为。
- 部分命令会静默接受多余参数，或在参数无效时改变 permission/focus 等状态。
- 完全 BYOK 的本地 Loop 仍被 Guest/月度 quota 和远程 start/complete 服务限制，网络故障还会产生与模型额度混淆的警告。
- CLI、TUI、README、官网终端示例和自动化测试之间缺少同一份命令契约。

这些问题不需要新的 Agent 引擎。0.0.17 的目标是把现有功能做成可发现、可预测、可回归的命令面。后续版本范围需要根据真实 Free 用户验证重新决策，当前没有已批准的 0.1.0 商业实验。

## 版本目标

1. 每个公开命令只有一个明确入口、参数语法和运行边界。
2. 已删除、实验性、不可用和未知命令都在本地给出确定结果，不交给模型猜测。
3. 权限、导出、Loop 和 Today 等有副作用的命令严格校验参数，失败时不改变状态。
4. CLI、TUI、自动补全、帮助文档和官网演示使用相同名称与语义。
5. 用自动化测试锁定命令注册、解析、分发和真实 CLI 边界。
6. Fresh reviewer 只依赖实际可用的只读工具，并在固定 step/time 预算内给出结构化结论或明确 ERROR。
7. 本地 BYOK Loop 不依赖登录或 Wukong quota 服务；只有单次运行的本地安全限制可以停止执行。
8. `/login` 只连接可选 Wukong 账号，模型 API Key 和默认模型只由 `/provider` 管理。
9. `/resume` 是会话恢复主命令，`/sessions` 仅保留为兼容别名。

## P0：命令契约收口

### Role 与 Transform

- 删除全局 `wukong --role` 和 `wukong loop --role`。
- 删除 TUI `/role` 别名；Role 管理只使用 `wukong roles list|show|init`。
- 保留 TUI `/transform` 作为当前会话的 Role Profile 切换入口。
- `/transform list` 列出内置与用户/项目自定义 Role；`/transform status` 显示当前状态；`/transform off` 恢复默认角色。
- 即使 `experimental.role_profiles` 未启用，`/transform` 仍出现在帮助和补全中；执行时在本地提示通过 `/experiments` 开启，不启动 shell，也不进入模型。
- `/transform` 的参数补全必须包含内置 Role、自定义 Role、`list`、`status` 和 `off`。

### 删除误导入口

- 删除 TUI `/report`。本地验证结果仍由 Loop/Gate 和高级诊断命令输出，不恢复 Hosted Report 产品面。
- 删除 TUI `/yes` 别名；权限模式只通过 `/permission`、`/auto` 和 `/yolo` 的明确语义控制。
- 已删除命令必须返回本地 unknown-command 结果，并提供最接近的合法建议。

### BYOK Loop 准入

- 删除 Guest trial、Free 每月 10 次、单次服务端 5 轮上限和 quota unavailable 警告。
- CLI/TUI 不调用 `/api/v1/loops/start` 或 `/api/v1/loops/complete`，登录状态不影响 Loop 能否运行。
- 默认单次 10 轮，并尊重用户显式 `--max-iterations`；reviewer 8-step / 2-minute 上限、Core step budget 和 `/loop stop` 继续作为安全边界。
- `~/.wukong/usage/loop-runs` 只保存不含 objective/prompt/transcript/diff 的本地恢复记录，不再作为远程 accounting outbox。
- 既有可选 telemetry 继续遵守 `WUKONG_TELEMETRY=0`，不能决定准入或改变最大轮次；0.0.17 不新增 Web/D1 指标后端。

### 账号、Provider 与恢复命名

- `wukong login` 和 TUI `/login` 只完成 device OAuth 账号连接，不请求 managed model 目录，也不写入模型 provider/default model。
- `/provider` 是所有模型 API Key、catalog 和默认模型配置的唯一 TUI 入口；没有模型时 welcome 和错误信息必须指向 `/provider`。
- `/logout` 只断开 Wukong 账号，不能删除 OpenAI、Anthropic 或其他 BYOK provider。
- `/resume` 是 registry 中的 canonical command；`/sessions` 继续解析到同一 handler，避免旧习惯立即失效。

### 本地 lifecycle v2

- 新记录使用 `{ version: 2, runId, state: active|terminal }`，不包含远程 sync attempts、quota request 或 pending outbox 状态。
- 读取 v1 `{ requestId, pending_terminal|synced, sync }` 时原地迁移为 v2，保留 goal/session/workspace 和 terminal outcome。
- 不为 lifecycle v2 新增 Web/D1 接收、存储或运营指标端点。既有 installer/CLI telemetry 仍受原有 opt-out 和禁止敏感内容边界约束。

### Slash command 安全边界

- 未知 slash command、已禁用的实验命令和当前状态下不可用的命令都不得作为 prompt 发送给模型。
- `/help`、命令补全和 dispatch 共用同一 registry，避免“帮助里有、运行时没有”或反向漂移。
- 内置彩蛋 `/dance` 保持当前行为，不进入模型。
- 只允许命令显式声明的参数；多余或无效参数返回本地 usage error。

### 有副作用命令的严格解析

- `/auto`、`/yolo` 只有合法参数才能切换 permission mode；错误参数不得改变当前模式。
- `/settings` 只在 idle 状态打开，避免运行中的会话状态竞争。
- `wukong loop --max-iterations` 只接受完整的正整数，拒绝部分数字、零、负数、浮点数和混合字符串。
- `wukong loop --dry-run` 同时展示 writer model 与 reviewer model，避免隐藏实际执行配置。
- `/export` 与 CLI `wukong export` 统一导出 ZIP；Markdown 使用显式 `/export-md`。
- `wukong today focus --clear-focus` 在任何写入前拒绝冲突参数。
- `wukong roles` 对未知子命令返回合法子命令列表和明确 usage。

## P0：自动化回归矩阵

0.0.17 必须覆盖以下四层，不能只测试单个 handler：

| 层 | 必须覆盖 |
|---|---|
| Registry | 命令名、别名、参数提示、可见性、实验开关和 idle-only 状态 |
| Resolve | 未知/禁用命令本地拦截、建议、参数拒绝、`/dance` 例外 |
| Dispatch | permission 不误切换、settings busy gate、export 语义、transform list/status/off |
| CLI boundary | `--role` 被拒绝、Loop 数值严格解析、Today 冲突无写入、roles 未知子命令 |
| Agent Core | reviewer 只读工具契约、8-step / 2-minute 硬上限、结构化超限错误与取消传播 |

回归要求：

- 被删除的 `/role`、`/report`、`/yes` 和 `--role` 都有负向测试。
- 未知和禁用 slash command 有“不会调用模型”的断言。
- `/transform list` 同时覆盖内置 Role 与自定义 Role。
- permission mode 的非法参数覆盖“状态不变”。
- 完整 app tests、typecheck 和 lint 通过，不使用 skip 或 mock 掩盖命令边界。

## 发布前人工 smoke

在真实 TUI 中至少完成一次以下路径：

1. 未启用 Role Profiles 时，从帮助发现 `/transform`，执行后得到 `/experiments` 指引。
2. 启用后运行 `/transform list`、切换一个 Role、查看 `status`、再执行 `off`。
3. 输入 `/role list`、`/report` 和随机未知 slash，确认只显示本地错误且没有模型回复。
4. 验证 `/auto`、`/yolo` 非法参数不改变 footer 中的 permission mode。
5. 验证 `/export` 产出 ZIP、`/export-md` 产出 Markdown。
6. 运行一次真实 `/loop`，确认 transcript 保留必要诊断，fresh reviewer 不尝试不可用写入或 shell 工具，且在预算内返回 PASS / NEEDS_WORK / ERROR 并释放 active Loop。

## 兼容性

Wukong Code 仍处于 `0.0.x`，命令面尚未承诺稳定。0.0.17 会主动删除误导入口，而不是继续保留会造成错误预期的 alias：

| 旧入口 | 0.0.17 替代入口 |
|---|---|
| `wukong --role <role>` | TUI `/transform <role>` |
| `wukong loop --role <role>` | 先在 TUI `/transform <role>`，或使用现有 writer/reviewer model 配置 |
| `/role list` | `/transform list` |
| `/role off` | `/transform off` |
| `/report` | `/loop` Gate 结果；高级诊断使用 `/proof` |
| `/yes` | `/permission`、`/auto` 或显式 `/yolo` |
| `/export <id>` Markdown | `/export-md <id>` |

升级说明必须明确列出这些删除和替代入口。

## 明确不进入 0.0.17

- `wukong account`、`wukong pr gate`、Stripe Billing、entitlement 和公开 Checkout。
- GitHub App、Team policy、audit log、managed reviewer 或 managed credits。
- 云端 `/schedule`、`/ship`、Hosted Report、远程 session 或同步闭环。
- 新的 Agent/Persona 市场、默认多 reviewer、`--agent` judge mode 或自动 policy 修改。
- TUI mascot、welcome 动画等与命令可靠性无关的视觉扩张。
- 新增安装或命令提示 telemetry；已有 `WUKONG_TELEMETRY=0` 退出机制保持不变。
