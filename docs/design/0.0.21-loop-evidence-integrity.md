# 0.0.21 Loop Evidence Integrity

> 状态：已于 2026-07-30 发布并完成公开安装、升级与官网验收。
> 目标版本：0.0.21。
> 最后更新：2026-07-30。
> 前置版本：[0.0.20 Reusable Verification Criteria](0.0.20-reusable-verification-skills.md)。
> 产品边界：补丁版本；继续 Free、local-first、BYOK，不新增命令、配置迁移或托管能力。

## 一句话定义

> **当同一种内置风险出现在不同文件、行或证据位置时，Loop reviewer 必须看到每一条不同 occurrence，不能因为它们共享 risk kind 而丢失后续 finding。**

0.0.21 不扩张 Loop 的执行模型。它只修复 0.0.20 brokered reviewer
路径中的 evidence identity 冲突，并保持 macOS、Linux、Windows 使用同一
功能面。

## 为什么需要这个补丁

0.0.20 使用 `risk.id` 作为内置风险证据的 `evidenceId`。当扫描器返回两条
相同 risk kind、但位置或证据不同的 finding 时，broker 会把后续 finding
误判为重复输入。结果是 reviewer 可能只看到第一处风险，无法基于完整风险集
做判断。

0.0.21 把完整 occurrence 纳入 canonical identity：

- risk id；
- severity；
- message；
- file；
- line；
- evidence。

同一份 occurrence 在重试时得到相同 identity；同类但位置或证据不同的
occurrence 得到不同 identity；字段完全相同的重复输入仍可正常去重。

## 功能列表

### P0：完整保留不同的风险 occurrence

1. 内置风险 evidence ID 从单独的 `risk.id` 改为
   `risk.id@canonicalOccurrenceDigest`。
2. 同一种风险出现在不同文件、行或 evidence 时，broker 保留为不同证据。
3. reviewer 接收当前 Gate attempt 的完整、bounded 风险 evidence 集合。
4. deterministic risk failure 的优先级、Gate 判定和 reviewer 权限边界保持
   不变；本补丁不能把失败改成 PASS。

### P1：稳定 identity 与回归覆盖

1. canonical digest 对同一 occurrence 是确定性的，不依赖数组顺序或随机 ID。
2. 回归测试覆盖“相同 risk kind、不同文件和行”的两条 finding。
3. 测试同时断言两条 evidence 都到达 broker，且 identity 互不冲突。

### 发布一致性

1. macOS x64/arm64、Linux x64/arm64、Windows x64/arm64 使用同一功能面。
2. 不提供某些平台有、某些平台没有的降级版本。
3. Release Notes 使用本文件对应的固定公开说明，不从包含历史回撤提交的
   commit log 自动拼接功能。

## 用户可观察结果

例如扫描器同时发现：

```text
src/first.ts:10   diff.placeholder_added
src/second.ts:20  diff.placeholder_added
```

0.0.20 可能只把其中一条交给 reviewer；0.0.21 会保留两条不同 occurrence。
用户不需要使用新命令或修改配置，现有 `/loop`、`wukong loop`、Resume 和
BYOK provider 路径保持不变。

## 明确不包含

0.0.21 不包含：

- exact/dirty source snapshot、依赖 bootstrap 或隔离 Git worktree；
- Candidate Workspace、Candidate Gate 或 candidate delta；
- Safe/transactional Promote、Apply journal、lease、fencing、恢复或回滚；
- Promote 后的 target Final Gate；
- Windows FFI、原生句柄保存或任何平台专用执行实现；
- `/worktree`、`/candidate`、`/promote` 等新命令；
- 并行 Agent、Detach、Supervisor 或 PR Gate；
- Hosted execution、源码/evidence 上传、managed model credits；
- 支付、quota、entitlement 或 telemetry backend。

[已取消的 Isolated Loop Worktrees 文档](0.0.21-isolated-loop-worktrees.md)
只保留为历史研究，不是 0.0.21 或后续版本的实现承诺。

## 发布门槛

发布 0.0.21 前必须完成：

1. repeated-risk regression、相关 typecheck 与 lint 通过；
2. 六平台 native RC 构建、启动与 `--version` smoke 通过；
3. GitHub Release 的六个 ZIP 与六个 SHA 文件完整；
