## 已有事实与本轮目标

2026-11-02 项目负责人确认：**真实用户首次使用已经跑通**。这是已有进展，
不再把“先证明有人能首次跑通”设为下一阶段入口。此确认未附人数、平台、耗时和
案例授权明细；不据此推断全部平台/五来源 Resume 已验收、用户持续复用或已付款。

本地 CLI 已按 MIT 公开，官网及运营后端保持私有。原
[First Success 设计](0.1.2-first-success-and-surface-simplification.md)中尚未实现的功能
仍是待评估的改进，不代表用户尚未跑通，也不整体继承为本版本的必做项。

本轮目标从首次使用转为：**同一用户在下一次交付中，能否复用验收条件，并把结果
和未覆盖项清楚交给另一个人。** 重复使用与交接需求仍待已有用户的反馈确认。

## 范围评审结论

下表是建议，不是批准后的开发清单；没有具体使用阻碍的条目不因优先级自动开工。

| 候选 | 本轮建议 | 理由与最小边界 | 进入实施范围的依据 |
|---|---|---|---|
| 本地交付摘要 | 优先候选 | 复用已有 attempt、Gate 与终态信息，减少交接时手抄；先验证人工摘要，确需自动化时只做本地预览/显式保存 | 用户需要向他人交付结果，现有终端输出或手工整理不足；确认字段与保存方式 |
| 验收条件与检查映射 | 保留，先用现有能力 | 先由用户整理条件并映射到 Goal、Done when、Preflight 和既有检查；不先建 AI Spec 生成器或新任务系统 | 实际出现重复遗漏或重复配置，现有合同表达不足，再评审数据结构与自动化 |
| GitHub PR Gate / 自动写回 | 暂缓 | 引入凭据、fork 输入、exact-commit 绑定、stale 状态和部分写入恢复，成本明显大于贴一段摘要 | 多次真实交付需要在 PR 验收，且手动附摘要不能解决；另批接入设计 |
| 实际仓库接入 | 继续作为使用验证 | 用现有 CLI 整理项目检查、陪跑交付，观察下一次能否复用；不是一个新增 CLI 功能 | 明确仓库、任务与用户授权；客户资料和服务安排留在私有运营仓库 |
| 真实演示与案例 | 整理已有结果 | 复用已跑通记录，获得授权后脱敏；案例公开与首次跑通是两回事 | 展示授权和可复核内容就绪；不强制重做一次首次使用实验 |
| Provider test、下一步提示、Preflight 草稿 | 按实际阻碍选取，非整批前置 | 功能尚未实现，但首次使用已跑通；只有反复认证排错或编辑丢失等具体问题才值得优先做 | 已有用户反馈能指出问题、频率及预期改善 |
| headless run-plan、命令分层与新 check 入口 | 暂不纳入本轮建议范围 | 没有当前重复交付阻碍的证据；更改授权面或命令心智需单独设计 | 有明确自动化/可发现性问题后重新评审，兼容合同保持 |

## 优先候选：本地交付摘要

### 已有能力与新增价值

已有 Goal/Done when/Preflight、冻结合同、项目检查、独立 reviewer、Gate 终态和
本地运行记录。本轮源码核对入口为 `apps/wukong/src/cli/sub/loop.ts`、
`apps/wukong/src/cli/lib/loop-run-store.ts`；`apps/wukong/src/cli/sub/export.ts`
导出的是会话归档 ZIP，不能直接当作可分享的脱敏交付摘要。

先用现有信息人工整理一份结果给接收者；如果现有输出已足够，则不新增摘要功能。
若确认需要自动化，建议只补“读取一次已有运行 → 本地预览 → 用户显式保存”，
不增加执行核、模型调用、网络上传或第二套 Gate 判定。命令名称和格式未定。

建议最小字段：用户确认的目标/条件、workspace revision 与 dirty 状态、run/attempt
身份、实际检查及其结果、reviewer 是否运行与结论、Gate 或停止状态、未覆盖项及
下一步。条件没有对应证据时明确标为未覆盖，不能用模型叙述补成已验证。

具体字段是否可从现有 durable state 完整取得、脱敏规则与存储兼容性，仍需技术设计
核对；本次只读源码不等于已具备摘要功能。交付价值应由接收者能否理解结果验证。

### 必须保留的语义

- 复用原始 attempt 的 Gate；确定性检查通过且 reviewer 未运行不能写成 Gate PASS。
- 缺失、过期、部分执行、失败与取消各自如实展示；停止不能改写成通过。
- 记录结果对应的 commit/工作树状态；dirty 运行不冒称验证了干净 HEAD，后续改动
  不被旧结果覆盖。摘要展示时点的检查不能悄悄触发新一次执行。
- 默认不包含源码、diff、prompt、transcript、密钥、绝对 home 路径或 raw evidence；
  原始会话 export 不是隐私安全的分享替代品。预览后保存仍须用户明确操作。
- 不恢复 Hosted Report、上传入口、自动 PR 评论、自动 merge 或托管 runner。
- 摘要便于交接，不保证无缺陷，也不改变 Free、本地 BYOK、账号可选的核心路径。

## 验证顺序与验收

1. 基于已跑通用户的下一次真实任务，确认当前交接方式与重复卡点，不重建首次使用门槛。
2. 用现有能力和人工条件映射/摘要验证价值；可公开案例须先获授权，不新增自动行为采集。
3. 若确需代码，用户先确认一个最小范围、技术设计、发布级别与兼容策略；暂缓项不随之自动纳入。
4. 摘要若获批，覆盖身份缺失、dirty/后续修改、未运行 reviewer、部分/失败/过期证据、
   取消/停止、脱敏与保存失败；按最终变更执行适用回归和发布验收。

首次使用跑通、复用、交接价值和商业验证分别记录。人数、留存比例、独立自助程度、
服务付款与续费尚不能由本次负责人确认推导；也不作为本技术候选的新增产品门槛。

## 后续独立评审

GitHub 集成需另批目标 PR/commit、权限、fork 执行与凭据隔离、stale 标记、幂等及
部分写入恢复。外部 Issue/PR/代码均是不可信输入，不继承权限或完成声明。

服务报价、合同、收款和客户资料由私有运营仓库管理，不放入公开技术版本的完成
定义。0.2.0 大规模瘦身、共享治理、团队后台、Billing、云端 Agent、SSO/SLA 与
完整任务管理器均不属于本轮建议范围。
