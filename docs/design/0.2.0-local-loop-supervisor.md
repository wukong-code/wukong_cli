# 0.2.0 组件：Local Loop Supervisor

> 状态：0.2.0 候选组件；尚未批准实施。
> 目标版本：0.2.0。
> 最后更新：2026-07-25。
> 前置组件：[0.2.0 Bounded Parallel Loop](0.2.0-bounded-parallel-loop.md)。
> 主规格：[0.2.0 Pro Reliable Autonomy](0.2.0-pro-reliable-autonomy.md)。
> 产品边界：0.1.0 的单前台 Loop 与本机安全边界继续 Free；显式 Detach 与多 Loop exception-first 监督属于候选 Pro Pilot 权益。只管理用户明确启动的本机 Loop，不提供跨设备、云端、Slack、BYOK/token quota 或 telemetry 后端。

## 一句话定义

> **让用户在本机统一查看、显式后台运行、暂停和恢复多个 Loop，并默认只把 approval、问题、冲突、预算和终态等需要人处理的例外提到前面。**

0.0.21 与 0.1.0 解决可信单 Loop，0.2.0 的 Parallel Phase 解决单个父 Loop 内的有界并行，Supervisor Phase 再解决“一个人怎样同时监督多个本地 Loop，而不重新回到逐条盯 Agent 输出”。

本版是本机 Loop supervisor，不是 Hosted Agent、Remote Control、Agent View 克隆或云端 Routine。机器关机时不会执行；supervisor 丢失、用户登出或异常退出时立即失效 execution owner 并停止新工作，受控执行树必须由 owner-death guard 终止或进入 reconciliation。主动脱离受控 process tree 的外部 daemon 仍可能逃逸，不能宣传为绝对零后台进程。

## 研究依据

本设计参考：

- [Steps of AI Adoption Artifact](https://claude.ai/code/artifact/bfdfaef9-bc62-4dfe-ba9e-c58a26c9accf)
- [Claude Code Agent View](https://code.claude.com/docs/en/agent-view)
- [Claude Code Remote Control](https://code.claude.com/docs/en/remote-control)
- [Claude Code Routines](https://code.claude.com/docs/en/routines)
- [Running an AI-native engineering org](https://claude.com/blog/running-an-ai-native-engineering-org)

吸收的原则：

1. 用户应按异常和最终结果监督，而不是持续观察每个 token。
2. 多个 session 必须有统一状态、预算和 attention reason。
3. 后台执行必须显式进入，不能因关闭界面就默认扩大权限。
4. approval、问题、冲突和预算增加必须始终由用户处理。
5. 重启恢复不能重放未确认命令或 provider request。

不照搬的部分：

- 不提供手机、浏览器或跨设备 Remote Control。
- 不建立 Anthropic/Wukong 云端执行环境。
- 不做时间、API、GitHub event 或 Slack 消息触发的 Routines。
- 不做 Claude Tag 类常驻团队 Agent。
- 不允许 supervisor 自主创建无限 Loop 或自动批准。

## 当前实现基线与问题

当前已经具备：

- `/tasks` 查看当前 session 的 background task、部分输出和停止入口；
- background Agent 生命周期与持久化记录；
- `Agent(resume=...)` 和 AgentSwarm `resume_agent_ids` 的手动恢复基础；
- `/loop status|pause|resume|stop` 的当前 Loop 心智；
- Goal terminal、continuation 和本地 session 搜索；
- 本地 server/web mode 基础。

但当前还不是多 Loop supervisor：

1. `/tasks` 只管理当前 session，不是跨 session、跨 repo 的 Loop 视图。
2. running task 在重启后可能变为 `lost`，不会形成统一的 paused/recoverable 操作。
3. 没有 Attach、Peek summary、Retry/Resume 的一致 CAS。
4. background child 和 parent Loop 的 terminal/Gate/budget 没有统一投影。
5. 用户看到的是活动日志和任务数量，不是“现在需要我处理什么”。
6. 多个 Loop 没有本机全局并发与 BYOK safety ceiling。
7. pending approval/question 在退出界面后容易变成不清晰的等待状态。
8. 若直接加入 daemon 或远程页面，容易误导为机器关闭后仍会运行。

## 版本目标

1. 定义统一的 `SupervisorItemV1`，投影 session、Loop、parallel children、Gate、budget 和 attention。
2. 普通入口继续使用 `/loop`，不新增 `/agents`、`/supervisor` 顶层命令。
3. 用户显式 Detach 后，当前 Loop 才能交给本机 supervisor 继续。
4. 退出 TUI、关闭 terminal 或切换 repo 不自动 Detach。
5. supervisor 只在本机 owner 有效时启动新执行；owner 丢失后受控执行树必须停止或进入 reconciliation，机器停止后不运行。
6. 重启后未完成 Loop 只有在 owner-death/process/workspace/usage reconciliation 全部成立时才恢复为 `paused`；未知状态进入 `needs_attention`，不自动重放。
7. 支持 Attach、Peek summary、Pause、Resume、Cancel，全部使用 CAS 和幂等键。
8. 用稳定 attention reasons 汇总 approval、question、conflict、budget、provider 和 terminal。
9. 默认列表按是否需要人工处理排序，不按日志活动量排序。
10. 建立本机全局 active-loop、worker、token/time 和 provider concurrency safety caps。
11. compact UI 不显示源码、prompt、diff、secret、完整路径或 transcript。
12. 所有 supervisor state 留在本机，不上传 Wukong Web/D1。

## 强依赖

本组件实施前必须满足：

1. 同一 0.2.0 的 Parallel Phase 已完成，parent/child/integration lineage、aggregate budget、cancel/restart 和 final Gate 已稳定。
2. 0.0.21 worktree lease 能在进程退出后安全恢复、保留和释放；target promotion lease 能跨 Wukong 进程排他并在 owner 丢失后 reconcile。
3. 0.0.19 terminal/continuation 仍是最终状态真相源。
4. 0.0.20 provider consent 只能在 exact run 内使用，Detach 不能扩大或延长 consent。
5. 当前 session/background/task state 必须先迁移到统一投影，不能再新建一套竞争状态机。
6. 任一状态无法证明时恢复为 `needs_attention`，不能自动继续。

## 核心不变量

### 1. Supervisor 只投影，不改写 Loop 真相

规则：

- Supervisor item 只引用已有 session/run/parallel/Gate records。
- 不允许 supervisor 自己生成 PASS、NEEDS_WORK 或 ERROR。
- terminal 与 continuation 冲突时 fail closed，显示 `state_inconsistent`。
- `supervisorItemId` 对同一 session/goal 稳定；同合同 continuation 只把 `currentRunId` 通过 CAS 指向新 run，旧 run 仍在历史中。
- terminal Goal 可以没有 current run；Revised Loop 使用新 `goalId` 和新 supervisor item。
- 同一个 active/current run 只能有一个 supervisor item。
- 投影可以重建；底层 durable records 不能由 UI cache 替代。

### 2. Detach 必须显式、受限、可撤销

Detach 前显示：

- exact Loop/contract/run；
- workspace 与 worktree；
- permission ceiling；
- exact BYOK provider consent；
- 当前与剩余预算；
- 本机 supervisor 运行边界；
- 退出 TUI 后哪些行为会继续、哪些会暂停等待。

不变量：

- 只有用户显式确认 exact detach digest 后才转交 supervisor。
- Detach 不改变 permission mode、provider、budget、contract 或 Gate。
- pending approval/question 的 Loop 不能通过 Detach 自动回答。
- detached Loop 仍受原 parent/global caps。
- Attach 可以随时取得交互视图；Pause/Cancel 是可追溯请求，只有到达安全 checkpoint 并完成 revalidation 后才算收回执行权。
- 关闭普通 TUI 但没有 Detach 时，当前行为保持现有前台语义。

### 3. 本机 Supervisor 不是云端服务

P0 使用用户级本机 supervisor process：

- 只在用户显式 Detach 时启动或采用；
- 默认不随系统开机启动；
- 只接受当前 OS 用户的本机 IPC；
- IPC 使用 Unix domain socket 或 Windows named pipe；如复用 localhost，必须绑定 loopback、随机 capability token 和 strict origin；
- socket/token 文件使用当前用户私有权限；
- 不开放公网 listener、远程 tunnel 或 Wukong Web control plane；
- 机器关机时不执行；进程退出、用户登出或休眠/唤醒异常时先使 authority/execution fencing tokens 失效、禁止新执行，再走 owner-death containment 和 reconciliation。

所有 detached 执行都必须绑定：

```ts

```

Owner-death 规则：

- 当前 OS 用户只有一个 `SupervisorAuthorityLeaseV1`；authority 与每个 run 的 execution ownership 都存于 user-global registry，acquire/adopt/release 使用 cross-process lock + CAS，并单调提升 fencing token。仅比较 PID 或时间戳不构成 ownership。
- authority 过期/owner lost 后，新实例必须先进入 reconcile，不能直接 adopt active run；每个 provider request、tool/check、child spawn、budget/integration append 和 Promote handoff 都校验 exact authority + execution fencing tokens。
- detached provider/tool/check/child 只能由 guard 启动；不能绕过 guard 直接 background spawn。
- Unix 使用每 run watchdog + heartbeat pipe/EOF + 独立 process group/session。supervisor owner 丢失时 watchdog 停止新 spawn，并在有界 timeout 内依次终止已知 group、升级 kill、记录 reconciliation。
- Windows 使用 Job Object `KILL_ON_JOB_CLOSE` 与 owner/watchdog handle；关闭或失效后仍要校验进程、workspace 和 usage。
- 未知 provider response 的 reservation 保持占用，不能按 0 结算，也不能在 restart 时自动重发。
- 只有已知执行树终止、in-flight side effect journal 可解释、workspace fingerprint 和 usage ledger 均完成 revalidation 后，item 才能进入 `paused`。
- watchdog/Job Object 状态缺失、进程仍存活或副作用无法确认时进入 `needs_attention/owner_death_reconciliation_required`，不能直接显示 paused。
- 外部脚本主动 daemonize、脱离已知 group/job 或写其他系统路径仍可能逃逸；与 0.2.0 Parallel Phase 一致，本机制是 lifecycle containment，不是完整 sandbox。
- sleep/wake 后一律先 invalid owner → pause/reconcile/revalidate；不能因 heartbeat 恢复就自动继续。

本机 IPC capability 使用：

```ts
interface LocalIpcCapabilityV1 {
  readonly tokenId: string;
  readonly issuerAuthorityFencingToken: string;
  readonly audience: 'wukong-local-supervisor';
  readonly bootEpoch: string;
  readonly restartEpoch: string;
  readonly issuedAt: string;
  readonly expiresAt: string;
  readonly allowedActions: readonly ('peek' | 'attach' | 'pause' | 'resume' | 'cancel')[];
  readonly nonceLedgerDigest: string;
  readonly tokenDigest: string;
}

interface LocalIpcActionV1 {
  readonly actionId: string;
  readonly tokenDigest: string;
  readonly nonce: string;
  readonly kind: 'peek' | 'attach' | 'pause' | 'resume' | 'cancel';
  readonly expectedProjectionDigest: string;
  readonly idempotencyKey: string;
  readonly actionDigest: string;
}
```

- raw token 只保存在当前用户私有文件/handle 中，records 只保存 digest。
- authority adoption、supervisor restart、boot/sleep epoch 变化或权限变化时立即 rotate；旧 token 全部失效。
- 每个 mutating action 携带未使用 nonce、expected projection digest 和 exact allowed action；nonce 通过 append-only CAS ledger 一次性消费，重复/replay 返回原结果或 conflict，不再次执行。

下次打开 Wukong 时：

- supervisor 仍存活：重新认证本机 IPC 后只读取当前投影；
- supervisor 已停止：guard 已 settled 且全部 revalidation 通过的项恢复为 `paused`；其余进入 `needs_attention` 并显示 exact reconciliation reason；
- 不自动重放 pending command、tool approval、question、provider request 或 promotion。

### 4. 顶层状态必须少而稳定

用户只看到四个稳定 lifecycle：

```text
running
paused
needs_attention
terminal
```

详细 phase 可以包括：

```text
planning
writing
waiting_permission
waiting_question
verifying
integrating
awaiting_promotion
final_verifying
terminal
lost_recoverable
```

phase 只解释进度，不能替代 Gate outcome。

唯一投影规则：

| 底层事实 | lifecycle | terminalKind | outcome | attention |
|---|---|---|---|---|
| active run 正在执行且无人工 blocker | `running` | `null` | `null` | 无 |
| durable pause 或 supervisor 重启后的安全暂停 | `paused` | `null` | `null` | 可选 resume |
| approval/question/conflict/budget/source stale/lost | `needs_attention` | `null` | `null` | exact reason |
| completed terminal PASS | `terminal` | `completed` | `PASS` | 无 |
| completed terminal NEEDS_WORK | `terminal` | `completed` | `NEEDS_WORK` | `terminal_needs_work` |
| completed terminal ERROR | `terminal` | `completed` | `ERROR` | `terminal_error` |
| cancel/abandon lifecycle terminal | `terminal` | `cancelled/abandoned` | `null` | 无或 review |

同合同 continuation 创建后，同一 item 从 `terminal` 经 CAS 指向新 `currentRunId` 并回到 `running/paused`；不能覆盖旧 terminal record。

### 5. Attention 只表示需要人处理

```ts

```

规则：

- 普通进度、日志追加和 token 流动不创建 attention。
- 同一稳定 blocker 使用幂等 attention ID，不重复刷屏。
- approval、question、budget extension 和 conflict choice 不能自动代答。
- safe summary 不包含 tool arguments、prompt、diff、secret 或完整路径。
- attention 解决后追加 resolution record，不覆盖历史。

### 6. 所有控制动作必须 CAS + 幂等

支持：

- `Attach`：回到该 Loop 的交互上下文；
- `Peek`：查看 bounded safe summary、阶段和 Gate/预算，不加载完整 transcript；
- `Pause`：提交 pause request，立即阻止新 turn/child；当前执行到达安全 checkpoint 并完成 revalidation 后才进入 `paused`；
- `Resume`：从 exact paused state 继续；
- `Cancel`：提交 cancel request，阻止新执行并终止已知 process tree；完成 reconciliation 后才进入现有 terminal/cancel 语义；
- `Retry`：只有底层 continuation/retry policy 允许时才展示。

```ts
interface SupervisorControlTransitionV1 {
  readonly actionId: string;
  readonly kind:
    | 'pause_requested'
    | 'pausing'
    | 'resume_requested'
    | 'resuming'
    | 'cancel_requested'
    | 'cancelling';
  readonly authorityFencingToken: string;
  readonly executionFencingToken: string;
  readonly requestedFromProjectionDigest: string;
  readonly lastSafeCheckpointRef: string | null;
  readonly transitionDigest: string;
}
```

每个动作绑定：

- supervisor item projection digest；
- active run/session identity；
- current authority + execution fencing tokens；
- expected lifecycle/phase；
- caller local capability；
- one-time action nonce 与 idempotency key。

重复点击、两个 TUI 同时操作或 reconnect 不能启动第二个 turn、child、check、provider request 或 Promote。

安全 checkpoint 规则：

- checkpoint 只位于 model request 前后、tool call 前后、child spawn 前后、integration delta 之间和 Promote Apply journal 的 change boundary。
- pause/cancel request 到达后不再启动新的 provider request、tool、child、integration delta 或 Promote。
- 已在 flight 的 provider/tool/process 先请求取消；在得到完成、取消或超时结果前保持 `pausing/cancelling`，不能提前显示 `paused/terminal`。
- 对已开始的 filesystem/Apply 副作用，必须根据 worktree fingerprint、usage reservation 和 Apply journal reconcile；未知状态进入 `needs_attention/state_inconsistent`。
- `SupervisorAuthorityLeaseV1` 与 `ExecutionOwnershipLeaseV1` 的单调 fencing tokens 确保同一 run 只有一个实例推进执行；owner 丢失后必须先 reconcile，再由 CAS adoption 产生新 token。
- Attach 只改变交互观察者，不抢占 execution owner；真正执行权变化仍走 pause/resume CAS。
- Supervisor execution owner 不能替代 target promotion lease；所有 Promote 都必须投影并尊重 0.0.21 的 target-global registry、cross-process lock 与 fencing token，目标繁忙时进入 `needs_attention/promotion_target_busy`。

P0 默认值应保守，并通过 dogfood 决定，文档不提前承诺具体大规模数字。

不变量：

- `CapacityRegistryLeaseV1` 是独立于 supervisor 生命周期的短租约：任何 0.2.0 foreground CLI 或 supervisor 都必须先通过 user-global lock + CAS 获取它，才能修改 capacity ledger；事务完成后立即释放。获取 capacity authority 不会启动、Detach、采用或取得任何 Loop 的执行权。
- foreground reservation 必须绑定 `foregroundProcessIdentityDigest`，detached reservation 必须绑定当前 `executionFencingToken`；两者恰有一个非空。supervisor authority 只控制 detached execution，普通 foreground admission 不依赖 `SupervisorAuthorityLeaseV1`。
- global cap 与每个 0.2.0 Parallel Loop budget 同时生效，取更严格者。
- `activeLoopLimit` 统计所有 cooperating foreground 与 detached run 的 `running/resuming/pausing/cancelling`；queued、paused、needs_attention 和 terminal 不占 active slot。
- `totalWorkerLimit` 统计正在执行的 planner/writer/child/reviewer/bootstrap/check/integration worker；等待 capacity 的任务不占，已 spawn 但尚未 reconcile 的 worker 继续占。
- provider request 必须在一个 admission transaction 中同时预留 user-global provider slot、exact provider-origin/credential slot、保守 token 上限和 bounded work-time slice；任一 reservation 失败都不能连接 provider。
- 每个 Loop 的 wall-clock ceiling 是从 run start 到 deadline 的真实经过时间；aggregate work-time ceiling 是所有 cooperating foreground/detached worker 已结算和仍预留的 active milliseconds 之和，不能把多个并行 worker 的时间只按父 Loop 墙钟计算一次。
- token reservation 使用 conservative input estimate + request max output + safety margin；work-time 在每个 turn/worker slice 开始前按冻结上限预留。只有可验证 actual usage/duration 才能结算并释放未使用部分；usage 缺失、进程丢失或结果不可解析时保留完整 reservation。
- 所有 0.2.0 foreground CLI 与 supervisor 都通过同一 user-global capacity ledger 做 CAS check-and-reserve → append-only event → flush/fsync → start/connect。检测到不兼容旧进程或无法访问统一 registry 时，foreground parallel 与 Detached admission 都 fail closed。
- 同时涉及 global capacity 和 0.2.0 per-Loop budget 时，固定锁顺序为 capacity registry → Loop budget ledger；使用同一 `CapacityAdmissionTransactionV1` 先在两个 ledger 写入并 fsync prepared reservation，再 durable commit，只有 commit 后才能 spawn/connect。prepared reservation 立即计入两个上限，因此 crash 在任意中间点都不会形成可执行但未计费的窗口。
- crash/adopt 后 prepared/active/unknown reservation 进入 `retained_unknown` 或 `reconciliation_required`；只有证明 process/request 从未开始或取得可验证 actual 后才能 settle/release，不能按“进程看不见”直接释放。旧 capacity/execution token 无权追加 ledger event。
- 同一 canonical target workspace 同时最多持有一个 target promotion lease；不同 supervisor item 不能因分属不同 Loop 而绕过。
- cap 满时新 Loop 保持 queued/paused，不偷偷抢占。
- foreground 或 Detached Loop 都不能自行扩大 per-loop 或 aggregate safety ceiling；paused 项可以释放已证明停止的 count slot，但保留自身 budget/usage lineage，未知 token/time reservation 不释放。
- 用户增加预算必须 Attach 或处理明确 attention，并确认新 digest。
- 所有 usage 只保存在本机；不创建 usage telemetry API 或月度 quota。

### 8. Privacy 与本机状态分离

Supervisor index 只保存：

- opaque IDs；
- repo/workspace 的安全显示名；
- lifecycle/phase；
- attention reason；
- budget aggregate；
- terminal kind、Gate outcome/ref；
- timestamps 与 digests。

不保存到 index：

- prompt 或 transcript；
- raw source、patch、diff 或 Gate evidence；
- secret、environment 或 provider key；
- 完整绝对路径；
- reviewer reasoning。

Attach 后读取原 session records，仍受原有本机权限和 provider consent；Supervisor compact list 不复制正文。

```text

```

现有 `/tasks` 保留为高级兼容入口，显示当前 session 的 command/subagent 细节；它不再承担跨 session 产品心智。

启动页只增加一条紧凑摘要：

```text
Active loops 3 · Needs attention 1
```

`/loop status --all`：

```text
Needs attention
  API migration     integration conflict   Review

Running
  CLI tests         verifying              61% budget
  Docs refresh      writing                24% budget

Terminal
  Resume parser     PASS                   18m
```

列表默认按 attention → running → paused → terminal 排序；`terminal` 必须同时显示 outcome，不能用 Completed 暗示成功。

## 稳定 reason codes

Supervisor action/condition 使用独立结果，不写 Loop Gate outcome：

```ts
type SupervisorActionStatus = 'accepted' | 'rejected' | 'conflict' | 'unavailable' | 'pending';
```

| Reason code | Supervisor status | 对 Loop outcome 的影响 |
|---|---|---|
| `supervisor_detach_consent_required` | `rejected` | unchanged；仍是前台 Loop |
| `supervisor_projection_stale` | `conflict` | unchanged；刷新后重试 |
| `supervisor_execution_fencing_lost` | `conflict` | unchanged；旧 authority/run owner 失效，禁止继续执行 |
| `supervisor_state_inconsistent` | `unavailable` | unchanged；投影进入 attention |
| `supervisor_local_auth_failed` | `rejected` | unchanged；不执行控制动作 |
| `supervisor_ipc_replay_rejected` | `rejected/conflict` | unchanged；token/epoch/nonce 已失效或已消费 |
| `supervisor_process_unavailable` | `unavailable` | unchanged；owner 失效并开始 reconciliation，不直接宣称 paused |
| `supervisor_owner_death_reconciliation_required` | `unavailable` | unchanged；已知 process/side effect/usage 状态未确认，进入 attention |
| `supervisor_loop_paused_after_restart` | `accepted` | unchanged；仅 guard settled 且全部 revalidation 通过后 lifecycle=`paused` |
| `supervisor_global_cap_reached` | `rejected` | unchanged；保持 queued/paused |
| `supervisor_capacity_reconciliation_required` | `pending` | unchanged；旧 reservation 状态未确认，不能提前释放 slot |
| `supervisor_action_conflict` | `conflict` | unchanged；只有一个 CAS 胜出 |
| `supervisor_attention_required` | `pending` | unchanged；等待人工处理 |
| `supervisor_pause_pending` | `pending` | unchanged；等待 safe checkpoint |
| `supervisor_cancel_pending` | `pending` | unchanged；等待 cancellation reconciliation |
| `supervisor_cancelled` | `accepted` | 只有底层 cancel terminal record 才令 terminalKind=`cancelled`；Gate outcome 保持 `null` |

Supervisor 不能从这些 reason 推导 PASS/NEEDS_WORK/ERROR、Continue 按钮或 continuation policy。

## 自动化测试

### Projection / state

- session、Loop、parallel、Gate 和 budget records 能稳定投影。
- duplicate/corrupt/cross-run refs 进入 `state_inconsistent`。
- terminal 与 continuation 只使用底层真相，不由 supervisor 猜测。
- terminal item 允许 `currentRunId=null`；同合同 continuation 使用稳定 item identity 指向新 run，Revised Loop 创建新 item。
- lifecycle/outcome 映射表的每个分支都有 golden fixture，`terminal` 永远显示 exact outcome。
- attention ID 去重、resolve 和 restart 后保持稳定。

### Detach / IPC

- 未显式 Detach 时退出 TUI 不继续执行。
- Detach 不扩大 permission、provider consent、budget 或 contract。
- Unix socket/Windows named pipe 权限和本机 capability 验证。
- 非当前用户、跨 origin、stale token 和 replay action 被拒绝。
- capability issuer/audience/expiry、restart/boot/sleep rotation、allowed action 和 nonce one-time CAS fixtures。
- supervisor owner 丢失会使新执行停止；只有 guard/process/workspace/usage 全部 reconcile 后才恢复 paused，否则进入 owner-death attention。
- Unix watchdog pipe/EOF + process group 与 Windows Job Object kill-on-close 均覆盖正常 exit、kill -9/TerminateProcess 和 owner fencing 竞争。

### Control actions

- Attach/Peek/Pause/Resume/Cancel 重复调用幂等。
- 两个 TUI 并发 Resume 只启动一个 turn。
- 两个 supervisor 进程竞争 authority、同 run ownership adoption 和 stale fencing token 时只有一个 CAS owner；旧 owner 的 request/spawn/journal append 全部失败。
- Pause/Cancel 经 requested → in-progress → safe checkpoint → settled 转换，不能提前显示 paused/terminal。
- in-flight provider/tool、integration delta 和 Promote Apply 在 cancel/crash 后根据 usage reservation、fingerprint 和 journal reconcile。
- execution fencing token 丢失或竞争时只有一个 supervisor 可以恢复。
- 两个 detached Loop 或两个独立 Wukong 进程对同一 target Promote 时只有一个取得 target lease；另一个稳定显示 promotion attention。
- pending approval/question 在 restart/reconnect 后仍未回答。
- budget extension、conflict choice 和 Promote 必须人工确认。
- Cancel 对 parent、children 和已知 process tree 发出级联终止；超时或未知副作用进入 attention，不能谎报已停止。

### Global limits / privacy

- global cap 与 per-Loop budget 取更严格者。
- foreground CLI 不启动 supervisor 也能取得短期 capacity authority，并与 detached run 通过同一 ledger 原子计数；capacity authority 不授予 execution ownership。
- foreground + detached active-loop/worker/provider/token/work-time reservation 通过同一 ledger 原子计数；两个进程并发 admission 不能突破 count、token 或 time ceiling。
- 同一 action 同时受 global capacity 与 per-Loop budget 约束时，固定锁顺序和 prepared/committed transaction fixture 保证：只完成一个 ledger、fsync 中断或 commit 前 crash 都不会 spawn/connect，也不会释放未知 reservation。
- provider actual usage 与 worker actual duration 可验证时才结算未使用量；missing usage、kill、owner adoption 和 sleep/wake 的未知 token/time 保留全额。
- cap 满时不建立新 provider connection；crash 未 reconcile 的 reservation 不提前释放。
- compact index、logs、notification 和 stream-json 不含 prompt、diff、secret 或完整路径。
- 本机 usage 不发往 Wukong Web/D1。

### Real E2E

- 同时运行至少 3 个 Loop，覆盖 2 个 repository。
- 关闭并重新打开 TUI 后状态、预算、attention 和 terminal 不丢失。
- kill supervisor、kill child、sleep/wake、provider auth failure、rate-limit exhausted 和 orphan worktree 有确定结果。
- sleep/wake 后先 pause/reconcile/revalidate，绝不自动继续；主动 daemonize 的 escape fixture 必须进入 attention，不能谎报已清理。
- Attach 后能继续当前 contract，不能重复 check/provider request/Promote。

## 四类发布门槛

1. **自动化**：projection、Detach、IPC、CAS、global caps、restart 和隐私负向测试全部通过。
2. **真实流程**：至少同时运行 3 个 Loop、覆盖 2 个真实仓库，完成 running、attention、pause/resume、cancel 和 PASS/NEEDS_WORK。
3. **跨平台**：macOS/Linux/Windows supervisor lifecycle、IPC、sleep/restart 和六平台 fresh install/0.1.0 → 0.2.0-rc upgrade 通过。
4. **用户验收**：固定 5 名新用户中，5/5 能在紧凑列表找到需要处理的 Loop 并正确选择下一步，5/5 理解机器关机后不会继续，4/5 能独立完成 Detach → Attach → Resume。

额外硬门槛：

- pending approval/question 在任何 restart 路径都不能自动放行。
- Attach/Resume 不重复 turn、check、provider request 或 Promote。
- global cap 与 per-Loop budget 同时有效。
- supervisor records、notification 和 Web/D1 请求中源码、prompt、diff、secret 为 0。

## 明确不做

- 云端 `/schedule`、机器关闭后继续执行或 hosted control plane。
- 手机/浏览器 Remote Control、跨设备同步或公开分享。
- Slack/Claude Tag 类常驻 Agent。

- 递归 Agent Tree、动态 workflow graph 或 100/1,000-agent 规模。
- 完整 sandbox、Runtime Security 或 Prismor 集成。
- Hosted Terminal、Team、BYOK/token quota 或 telemetry 后端；PR Gate 与 Billing 只按 0.2.0 主规格评审，不属于本组件技术合同。
- 新的默认 `/agents`、`/supervisor` 或 `/remote` 命令。

## 完成定义

0.2.0 Local Loop Supervisor 组件只有在以下条件全部成立时才算实现：

1. 用户能在本机统一看到多个 Loop 的真实状态。
2. 只有显式 Detach 的 Loop 能在退出 TUI 后继续。
3. 机器关机时不执行；supervisor owner 丢失后不再启动新工作，受控执行树被 guard 终止并 reconcile，无法证明的逃逸/副作用显示 attention 而不是伪报 paused。
4. restart 不自动批准、回答、加预算或重放副作用。
5. attention 列表只包含需要人工处理的例外。
6. Attach/Pause/Resume/Cancel 全部 CAS、幂等且可追溯；Pause/Cancel 只有在 safe checkpoint 和副作用 reconciliation 后才完成。
7. global caps 与每个 Loop budget 同时生效。
8. supervisor authority/execution fencing 与独立 capacity authority/atomic ledger 能阻止两个进程重复 spawn，foreground 不需启动 supervisor，并且 count、token、time reservation 都不能突破上限。
9. compact UI 和 records 不复制源码、prompt、diff、secret 或 transcript。
10. terminal/Gate 仍由底层 Loop records 决定。
11. 没有云端 control plane、telemetry、默认新命令或无人值守承诺；Pro admission 与 Billing 只使用主规格的统一 entitlement，不在本组件另造 quota。
