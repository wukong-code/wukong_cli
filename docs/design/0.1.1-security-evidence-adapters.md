# 0.1.1 Security Evidence Adapters

> 状态：产品与工程候选；尚未批准实施，不是当前功能承诺。
> 目标版本：0.1.1，最早在 0.1.0 stable 与稳定性观察完成后实施。
> 最后更新：2026-07-29。
> 前置版本：[0.1.0 Trusted Local Loop](0.1.0-trusted-local-loop.md)。
> 产品边界：Free、local-first、BYOK；默认关闭，不新增默认顶层命令，不把安全扫描、Loop 或 BYOK token 放入付费墙。
> 上游参考：[`@openai/codex-security@0.1.1`](https://github.com/openai/codex-security/tree/f22d4a36f26d16287bcdfd707b369116e02a08c3)，固定 commit `f22d4a36f26d16287bcdfd707b369116e02a08c3`。

## 一句话定义

> **0.1.1 让 Wukong 的 frozen Gate 可以安全消费外部安全工具的本地 evidence：先验证 producer、target、coverage、schema 和 artifact seal，再把结果映射成 Wukong 自己的稳定 finding 与 Gate blocker；外部扫描器永远不能单独产生 root PASS。**

0.1.1 不把 Wukong 改造成另一套漏洞扫描器。它建立 provider-neutral adapter contract，并以 Codex Security canonical JSON 与 SARIF 作为首批实现，后续 Semgrep、CodeQL、Snyk 或用户自有 scanner 只能通过同一合同接入。

## 1. 为什么独立为 0.1.1

0.1.0 的首要任务是稳定单个 Trusted Local Loop、target Final Gate、completion seal、安装升级与真实用户路径。把外部 scanner、额外进程、成本预算和第三方 artifact 一起塞进 0.1.0 RC，会扩大 false PASS、隐私、取消与恢复的风险面。

因此版本边界是：

1. 0.0.21 先完成 target Final Gate 的 validate-before-terminal completion seal。
2. 0.1.0 冻结 Wukong 自己的 finding/occurrence identity、coverage-aware lifecycle 与 release integrity。
3. 0.1.1 再接入单个、可选、受控的外部 evidence producer。
4. 0.2.0 才考虑多 producer/多任务的有界编排、Detach/Supervisor 与 evidence-bound PR Gate。

## 2. 用户路径

0.1.1 只增加现有高级检查层的可选能力：

- **Import**：用户显式选择已有的 Codex Security canonical scan directory 或 SARIF 文件；Wukong 只读加载、验证和映射。
- **Execute**：用户在 Preflight 审查 exact producer、executable、target、scope、预算、网络/credential 边界和 policy digest 后，允许 Wukong 调用本机已安装的 producer。
- **Loop integration**：用户可把 producer 选入 frozen Gate Plan；candidate 与 target Final Gate 必须使用计划中冻结的 phase、scope 和 policy。
- **Explicit export**：用户主动导出 Wukong 的本地 JSON/SARIF projection；默认不生成报告、不上传 Wukong Web。

默认 `/loop`、`wukong loop` 和内置 risk scan 不依赖 Codex Security、Python、SQLite、Docker、登录或网络。0.1.1 可以扩展现有 `scan`/Gate 配置，但不新增 `/security`、`/deep-scan` 或其他默认顶层命令。

## 3. Provider-neutral 合同

```ts
interface GateEvidenceProducerV1 {
  readonly schemaVersion: 1;
  readonly producerId: string;
  readonly producerVersion: string;
  readonly adapterId: string;
  readonly adapterVersion: string;
  readonly mode: 'import' | 'execute';
  readonly supportedFormats: readonly ('canonical-json' | 'sarif')[];
  readonly producerDigest: string;
}

interface ExternalEvidenceArtifactRefV1 {
  readonly logicalName: string;
  readonly format: 'canonical-json' | 'sarif' | 'adapter-metadata';
  readonly privateRef: string;
  readonly byteLength: number;
  readonly contentDigest: string;
  readonly schemaVersion: string | null;
  readonly artifactDigest: string;
}

interface ExternalGateEvidenceBundleV1 {
  readonly schemaVersion: 1;
  readonly evidenceAttemptId: string;
  readonly runId: string;
  readonly gateAttemptId: string;
  readonly producer: GateEvidenceProducerV1;
  readonly phase: 'candidate' | 'target_final';
  readonly sourceSnapshotDigest: string;
  readonly targetFingerprintDigest: string;
  readonly scopeDigest: string;
  readonly policyDigest: string;
  readonly budgetDigest: string;
  readonly status: 'complete' | 'inconclusive' | 'cancelled' | 'error';
  readonly coverage: {
    readonly completeness: 'complete' | 'partial' | 'unknown';
    readonly includePaths: readonly string[];
    readonly excludePaths: readonly string[];
    readonly limitations: readonly string[];
    readonly coverageDigest: string;
  };
  readonly findingOccurrenceIds: readonly string[];
  readonly artifacts: readonly ExternalEvidenceArtifactRefV1[];
  readonly redactionPolicyVersion: string;
  readonly startedAt: string;
  readonly completedAt: string;
  readonly sealedAt: string;
  readonly bundleDigest: string;
}
```

合同规则：

- `privateRef` 只能由 Wukong private store 分配，是 opaque ref，不接受模型、producer 或用户提供的任意路径。
- `producerId + producerVersion + adapterVersion + sourceSnapshotDigest + targetFingerprintDigest + scopeDigest + policyDigest` 必须与 frozen Gate Plan 完全一致。
- artifact 先经过 bounded read、schema validation、safe-path、file identity、size 和 content digest 校验，再生成 seal。
- upstream artifact 保持 immutable；Wukong 的人工 disposition、注释和 lifecycle projection 单独保存，不能改写原 observation。
- 外部 producer 的 finding 映射到 0.1.0 的稳定 `findingId`；每次导入/执行产生独立 `occurrenceId`。
- 只有 `status=complete` 且 `coverage.completeness=complete` 的 evidence 才能证明某个 required scope 已扫描。partial、unknown、cancelled、error、schema drift 或 seal mismatch 一律是 `inconclusive`/`ERROR`，不能把缺失 finding 推导为 resolved。
- 外部 evidence 可以增加 blocker 或满足 frozen required producer，但不能绕过 deterministic checks、fresh reviewer、Promote 或 target Final Gate，也不能单独产生 root PASS。

## 4. Codex Security 首个 adapter

### 4.1 Canonical JSON import

Codex Security adapter 直接使用其 package root 公开导出的 SDK 和类型：

- `CodexSecurity`、`loadContract` 与公开 model types 只存在于可选 adapter package，不进入 Wukong core 默认依赖。
- adapter 精确锁定 `@openai/codex-security@0.1.1`；在上游 `<1.0` 期间不使用 caret/range 自动升级。
- `loadContract` 必须验证 `scan-manifest.json`、`findings.json`、`coverage.json`、scan ID、target/scope expectation、schema、artifact hash/seal、symlink/TOCTOU 与 producer version。
- Wukong 不重写或放宽上游 schema；先验证 upstream truth，再映射为 `ExternalGateEvidenceBundleV1`。
- Codex Security 的 `findingId`/`occurrenceId` 保留为 provider-native IDs，同时生成 Wukong provider-neutral identity；两个 namespace 不互相冒充。

### 4.2 SARIF import

SARIF 是兼容投影，不是 canonical truth：

- 保留 tool/rule identity、primary fingerprint、所有 relevant locations、severity/confidence 和原始 result index。
- location path 必须是安全的 repository-relative POSIX path；绝对路径、`..`、反斜杠、device/ADS 和 path collision fail closed。
- SARIF 缺少 target snapshot、coverage 或 producer seal 时，必须由用户提供并确认独立 expectation；否则只能作为 advisory evidence，不能满足 required Gate producer。
- 多个 result 指向同一 root control 时可共享 finding identity，但不得因标题相似自动合并独立漏洞实例。

### 4.3 Local execution

执行本机 Codex Security 时：

- 首选在独立可选 adapter package 中调用精确锁版的 `CodexSecurity` public SDK；只有 SDK 无法覆盖的兼容路径才调用本机 CLI，不能 deep import 上游 private module。
- Preflight 冻结 adapter/package version、resolved Codex/CLI executable realpath、file identity/version、argv、target、scope、output root、budget 与有效环境 digest。
- 任一 child executable 都必须位于 source/candidate/Git common-dir/generated writable scopes 之外；拒绝 repository-controlled shim、symlink/junction、非 regular file 和 resolve/spawn identity drift。
- subprocess 使用 exact executable + argv 直接启动，不经过 login shell；PATH 只保留已验证的绝对目录，并清除未授权 credential、proxy、provider 和 secret 环境。
- output/state 位于 Wukong private root，必须在 source、candidate 和 Git common-dir 之外；POSIX 目录/文件使用 `0700/0600`，Windows 使用当前用户独占 ACL；拒绝 symlink、hardlink、root replacement 和非空复用目录。
- 运行 Codex Security 可能需要 Python `>=3.10` 与 Codex credentials；这些只在用户确认的 run-scoped adapter 内使用，不能变成 Wukong core 或默认 Loop 的安装前置。
- process/worktree/output hardening 不等于完整 filesystem/network/process sandbox；无强制隔离时 UI 必须展示剩余风险。

## 5. 预算、取消与恢复

```text
prepared
  → running
  → validating
  → sealed
  → joined
```

附加终态是 `inconclusive | cancelled | error`，不能从这些状态恢复为同一 attempt 的 `complete`。

- Preflight 必须证明预算足够完成最小有效扫描；无法估算时明确显示 unknown，不允许 setup 用尽全部预算后产出“成功的空结果”。
- time、token/cost、process output、artifact bytes 和 optional network 都使用 hard budget；预算耗尽产生 partial/inconclusive evidence。
- SIGINT/SIGTERM 先 fence late write、停止 producer、等待有界 child join，再持久化 cancelled terminal；迟到 callback 不能覆盖取消状态。
- crash/restart 不能因目录或文件存在就 resume。必须重读并验证 producer/version、schema、target/snapshot、scope、coverage、artifact identity/hash 和 seal。
- 无 owner 的 `running` attempt 必须进入 explicit reconciliation；合法 sealed attempt 可幂等 join，损坏/不完整 attempt 保留现场并显式 rerun。
- error、stderr、URL userinfo/query、Authorization、API key 和环境值在写 event、receipt、JSON/SQLite、日志或 stream-json **之前**使用同一 redactor 去密；raw diagnostic 只在有界、私有、短生命周期 ref 中存在。

## 6. Finding lifecycle

0.1.1 复用 0.1.0 的 provider-neutral lifecycle：

- `new`：当前完整 coverage 中首次出现。
- `persisting`：稳定 identity 在当前完整 coverage 中再次出现。
- `reopened`：历史已关闭 identity 在当前完整 coverage 中再次出现。
- `resolved`：历史 identity 所属 scope 在当前 producer/version 下完整覆盖，且当前 observation 缺失。
- `unknown`：当前 coverage partial/unknown、attempt cancelled/error、schema/seal invalid，或 scope/producer 不可比较。

人工 feedback 使用 `accepted | false_positive | fixed | unclear` 的 mutable projection。它可以影响后续 reviewer context 和显示，但不能删除 observation、伪造 coverage 或把 required blocker 改成 PASS。

## 8. 许可与升级纪律

Codex Security 使用 Apache-2.0；Wukong 当前是 proprietary/UNLICENSED。首次复制或修改 upstream 源码前必须：

1. 新增 `THIRD_PARTY_NOTICES.md`，记录 upstream repo、package version、完整 commit、Copyright 2025 OpenAI、Apache-2.0 和 copied file list。
2. 在分发物中保留 Apache-2.0 license 副本；修改过的 vendor 文件显著注明来源与 Wukong 修改。
3. 保留适用的 copyright、patent、trademark 和 attribution notice；Apache-2.0 不自动授予 OpenAI/Codex 商标使用权。
4. 每次升级重新检查 public exports、schema、LICENSE/NOTICE、known issues、生成物与负向测试；不能只更新 semver range。
5. 产品称为 “Codex Security adapter/integration”，不能把 Wukong 自有扫描冒充为 Codex Security。

这是工程合规门槛，不替代正式法律审核。

## 10. P0 实施顺序

1. 冻结 `GateEvidenceProducerV1`、`ExternalGateEvidenceBundleV1`、stable reason codes 和 Gate mapping。
2. 实现 private artifact store、schema/hash/seal validator、pre-persist redaction 与 crash/cancel lifecycle。
3. 建立独立可选 adapter package，精确锁定 Codex Security `0.1.1`，先完成 canonical JSON import。
4. 实现 generic SARIF import；无完整 target/coverage expectation 时只产生 advisory evidence。
5. 实现 trusted local execution、budget、signal handling 与 resume reconciliation。
6. 接入 candidate/target Final Gate 的 frozen producer plan，不改变 root PASS 决策权。
7. 完成跨平台、真实仓库、许可/attribution 和 public truth 验收。

## 11. 明确不做

- 不在 0.1.1 内实现多 repo bulk scan、deep multi-agent scan、Detach 或 Supervisor。
- 不自动安装 Git hook、自动 patch/fix、自动提交、push、PR comment 或 status。
- 不把 Python/SQLite Workbench、Codex Skills/MCP 或 Codex auth 变成 Wukong core。
- 不把 Codex Security 设为默认/required scanner，不因未安装而阻止普通 Free Loop。
- 不将 SARIF、模型匹配或人工 false-positive 反馈当作 deterministic PASS。
- 不新增云端 runner、Hosted Report、源码/evidence 上传、Team policy、Billing 或 telemetry 后端。
- 不宣传 external process、worktree、private output 或 Docker profile 是完整 sandbox。

## 12. 完成定义

0.1.1 只有在以下条件全部成立时才算实现：

1. Codex Security canonical JSON 与 generic SARIF 都先验证 target/scope/schema/coverage/artifact/seal，再进入 Wukong Gate。
2. stable finding/occurrence identity、immutable observation 与 mutable feedback 在跨 worktree/restart 中不漂移。
3. required producer 的 partial/unknown/cancel/error/corrupt evidence 不能产生 resolved 或 root PASS。
4. import、execute、cancel、crash/resume、budget exhaustion、late write 和 Windows path fault matrix 通过。
5. output/state 私有、repo 外、no-follow；所有 durable diagnostic 在持久化前去密。
6. Codex Security 未安装、adapter 关闭或服务不可用时，普通 Free/BYOK Loop 仍完整可用。
7. upstream pin、public API、许可证、attribution、copied-file provenance 与分发物完成审计。
8. 没有新增默认顶层命令、云端依赖、付费限制或 false security/sandbox 宣传。
