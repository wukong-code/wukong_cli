# 0.0.14 Cross-Agent Resume 与 Loop UX 收尾

> 状态：开发中
> 目标版本：`0.0.14`
> 最后更新：2026-07-18
> 定位：`0.1.0` 支付与 GitHub PR 工作流之前的免费体验版本

## 1. 版本结论

`0.0.14` 不增加新的商业系统，也不扩张成另一套 coding agent。它解决两个直接影响日常使用的问题：

1. 用户如何把 Codex、Claude Code 或 Cursor 中未完成的任务带进 Wukong。
2. 用户如何在 TUI 中快速看懂当前 Loop 是否通过、为什么没有通过、下一步做什么。

一句话定位：

> **Bring the task in. Let Wukong Loop finish it.**

本版本继续免费、BYOK。支付、GitHub PR 集成和 Team 能力仍归 `0.1.0`。

## 2. 用户主路径

```text
Codex / Claude Code / Cursor 中未完成的任务
                    ↓
       /resume codex|claude|cursor
                    ↓
             选择外部 session
                    ↓
        Continue 或 Start /loop 草稿
                    ↓
      重新读取 workspace 与 Git 状态
                    ↓
       Write → Check → Review → Fix
                    ↓
          PASS / NEEDS_WORK / ERROR
```

裸 `/resume` 保持原有含义，只恢复 Wukong session，不要求用户理解“Wukong 来源筛选”。

## 3. 功能范围

### 3.1 Cross-Agent Resume v1

命令面：

```text
/resume          # Wukong session
/resume codex    # Codex local session
/resume claude   # Claude Code local session
/resume cursor   # Cursor local session
```

兼容入口保留但不进入主帮助和自动补全：

```text
/resume-codex
/resume-claude
/resume-cursor
```

功能要求：

- `/resume` 只加载 Wukong session。
- 只有显式指定外部来源时，才扫描对应工具的本地 session。
- picker 显示来源、标题、原生 session ID、工作目录和更新时间。
- 默认只看当前工作目录；继续复用 `Ctrl+A` 切换全部工作目录。
- 搜索匹配来源、标题和原生 session ID。
- 损坏、未知或无法读取的单个 transcript 只跳过自身，不阻塞 picker。
- 扫描只访问已知本地目录，不发送网络请求。
- 外部文件路径必须经过 realpath 与根目录边界检查，拒绝 symlink 越界。

已知本地来源：

| 来源 | 本地数据 | v1 行为 |
|---|---|---|
| Wukong | `~/.wukong/sessions/` | 原生 replay |
| Codex | `~/.codex/sessions/**/rollout-*.jsonl` | 只读上下文导入 |
| Claude Code | `~/.claude/projects/*/*.jsonl` | 只读上下文导入 |
| Cursor | `~/.cursor/projects/*/agent-transcripts/*/*.jsonl` | 只读上下文导入 |

### 3.2 外部会话安全导入

选择外部 session 并选择 `Continue in Wukong` 后，通过内置 `resume-codex`、`resume-claude` 或 `resume-cursor` Skill 处理。

允许提取：

- 用户目标和最后请求；
- assistant 已完成工作的简要结论；
- 未完成事项和已知 blocker；
- 来源中存在的工作目录、branch、session ID 和时间；
- 对继续任务有必要的少量对话上下文。

禁止继承或重放：

- system/developer instructions 和隐藏 reasoning；
- API key、OAuth token、环境变量和 MCP credential；
- 旧权限批准、sandbox 状态和工具 allowlist；
- 原工具的旧 tool call、terminal、后台任务和子 agent；
- “测试已通过”“文件已修改”等未经当前 workspace 复验的历史结论。

外部 resume 的 UI 必须明确这是“导入并在 Wukong 中继续”，不是重启原 Codex、Claude Code 或 Cursor 进程。

### 3.3 Resume → Loop 衔接

选中外部 session 后先提供两个清晰动作，不立即启动模型或写入 workspace：

```text
Continue in Wukong
Start /loop
```

`Continue in Wukong` 会安全导入必要上下文并普通继续；`Start /loop` 只把 session 的最后用户请求预填成可编辑的 Loop 目标，用户按 Enter 后才启动。进入 Loop 前必须：

1. 重新读取当前工作目录和 Git branch。
2. 检查当前 diff、未跟踪文件和冲突状态。
3. 重新发现项目检查命令。
4. 把旧 transcript 中的完成声明只视为背景，不作为 evidence。
5. 使用当前 Wukong permission、model、role 和 review policy，不继承外部配置。

v1 不自动启动 `/loop`，避免用户选中 session 后立即发生写操作。

### 3.4 TUI Gate 与 Footer 简化

TUI 不再把不同语义压缩成容易误解的：

```text
Verify ✗ · Proof BLOCKED · High-risk changes detected
```

统一显示一个 Gate 结论和必要原因：

| 实际状态 | TUI 文案 |
|---|---|
| 尚未运行检查 | `Gate not checked` |
| 检查命令失败 | `Gate NEEDS WORK · Checks failed` |
| 没有可运行检查 | `Gate NEEDS WORK · No project checks found` |
| 发现需要人工确认的高风险变更 | `Gate REVIEW · Risky changes need review` |
| deterministic gate 通过 | `Gate PASS` |
| reviewer 返回 blocking finding | `Gate NEEDS WORK · <主要 blocker>` |
| runtime/config 错误 | `Gate ERROR · <可操作原因>` |

要求：

- 不用 `Verify ✗` 表示“未发现测试”或“还没运行”。
- `Proof BLOCKED` 不再作为普通用户常驻概念；普通用户只理解 Gate。
- 高风险规则命中必须说明风险类型，不能直接暗示代码一定错误。
- Footer 只保留一个主要结论；详细 verify/scan/proof 信息进入 transcript 或高级命令。
- 文案在窄终端中稳定截断并保持列对齐。

### 3.5 检查发现与真实项目兼容

0.0.14 补充 Loop 在非 Node 项目中的基础检查发现，目标不是建立全语言 CI 系统。

计划覆盖：

| 项目类型 | 基础候选检查 |
|---|---|
| Node / monorepo | 现有 npm/pnpm/yarn/bun scripts 与嵌套 package discovery |
| Python | 已配置的 pytest、ruff、mypy 或项目声明命令 |
| Rust | `cargo test`、项目已有 lint/check 配置 |
| Go | `go test ./...`、项目已有 lint 配置 |

规则：

- 优先执行项目显式配置，不凭语言类型盲目运行所有工具。
- 工具未安装属于可解释的 `ERROR` 或 unavailable，不是假测试失败。
- 无测试项目继续沿用安全边界：源码改动不能仅凭 reviewer 自评为 PASS；纯文档改动可以进入只读 review。
- 自动发现必须有超时、命令数量上限和真实临时仓库 E2E。

### 3.6 兼容策略

旧停止条件继续接受并归一化到 `proof-pass`：

```text
verify-pass
scan-clean
judge-pass
```

0.0.14 继续输出 deprecated 提示，但不删除旧 wire value、Goal record 或 CLI/TUI 参数兼容。实际删除时间另行决定，不能仅因为兼容矩阵写了“不早于 0.0.14”就在本版本移除。

## 6. 明确不做

`0.0.14` 不做：

- Stripe Checkout、customer portal、付费 entitlement 或真实价格；
- GitHub PR comment/status check；
- Team policy、audit log 和组织权限；
- 云端 `/schedule` 或后台跨机器 Loop；
- 自动修改 active review policy 或 reviewer Skill；
- managed model credits；
- 宣传恢复原 Agent 进程或完整隐藏状态。

## 7. 商业边界

Cross-Agent Resume 是免费迁移和激活入口，不单独收费。它的商业价值是让用户更容易把未完成工作带入 Wukong，并体验 Loop 的收敛与 reviewer 价值。

`0.0.14` 继续使用当前 Guest/Free Loop quota，不新增 resume 次数限制，不对本地 transcript 数量计费。未来收费点仍是更多 Loop、deep reviewer、PR 协作、共享 policy、审计和托管运行。

## 8. 发布门槛

- 裸 `/resume` 只出现 Wukong session，且不扫描外部目录。
- 三个显式来源命令能发现真实本地 session，并正确显示来源和原生 ID。
- 外部 session 选择后不会重放工具、继承权限或上传 transcript。
- symlink 越界、损坏 JSONL、未知事件和超大记录不会导致 TUI 崩溃。
- 导入后对当前 workspace 与 Git 状态重新检查，旧 transcript 不能替代当前 evidence。
- 用户可以明确选择普通继续或确认后进入 `/loop`。
- Footer 对未检查、检查失败、风险复核、review blocker 和 runtime error 使用不同文案。
- Node/Python/Rust/Go 的已支持检查发现有 fixture 和真实临时仓库测试。
- 旧 Goal records 和 legacy stop flags 继续兼容。
- 全量测试、typecheck、lint、native build/smoke 通过。
- 中英文 README、用户指南、设计文档、CHANGELOG、公告和公开 release assets 一致。

## 9. 成功指标

发布后重点观察：

- 外部 session picker 打开次数和成功发现率；
- 外部 session 被选择后继续任务的比例；
- 外部 resume 后启动 Loop 的比例；
- Loop 首轮进入 `NEEDS_WORK` 后最终收敛到 `PASS` 的比例；
- session discovery 失败率和平均耗时；
- 用户是否仍询问 `Verify ✗`、`Proof BLOCKED` 的含义。

默认不上传 transcript、源码、diff 或自由文本。若统计实现需要服务端事件，只允许记录来源类型、成功/失败分类、耗时区间和匿名版本信息。
